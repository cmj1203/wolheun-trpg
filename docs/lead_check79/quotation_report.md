# 인용 화법 교정 77~79

## 원인과 수정

실제 QA76에서 생성한 `길을 잃었다라.`를 모델 교열이 그대로 승인했다. 교열 지시 보강은 이 표현을 고치지 못했고, 생성 지시 보강도 같은 장면의 세 응답 중 하나에서 재발했다. 두 지시문 대안은 구현에 넣지 않았다.

`app/src/gm/validate.ts`의 대사 검증에서 정상 인용부호 구간을 제외하고, ㅆ 받침 종결형에 명사 인용 조사가 붙는 구조를 검사한다. 위반은 `format/quotation`으로 반환한다. 기존 재생성 경로가 대사와 주변 서술을 전체 출력으로 다시 만들며, 낱말 치환이나 새 재시도·대체 경로는 추가하지 않았다. 명사 `만다라`, 정상 단편, 부호가 있는 직접 인용은 보존한다.

## 실제 입력과 응답 대조

입력: `길을 잃었어요. 당신들에게 해를 끼치려는 게 아니에요. 칼을 내려 주세요.`

| 검수 지점 | 관측 |
|---|---|
| QA76의 실제 원시 응답 | 남자: `길을 잃었다라.` |
| 수정 전 구조 검사 | 문제 형태 5건이 검사를 빠져나가 시험 실패, 정상 대조 9건 통과 |
| 수정 후 첫 시도 | QA76 응답을 검증 경계에 재생해 `format/quotation`으로 거절 |
| 둘째 시도 | 실제 모델 생성과 교열 2호출, 위반 없음, 대체 대사 미사용 |

둘째 시도의 전체 출력:

1. 나레이션: 목을 짓누르던 서늘한 감각이 아주 조금 물러났다. 칼끝이 피부에서 한 마디 정도 멀어지며 숨을 쉴 틈이 생겼다.
2. 남자: 길을 잃었다고?
3. 나레이션: 남자의 눈이 가늘어지며 나를 꿰뚫을 듯이 살폈다.

이 검수는 저장 스냅샷과 원래 판정·대가를 읽는 격리 경계 검수다. 첫 응답은 새 모델 생성이 아니라 QA76 캡처 재생이며, 이를 실제 새 게임 완주로 세지 않는다. 스냅샷은 호출 전후 동일했다. 기본 재시도 수와 15초 예산을 유지했다. 이번 경계 호출은 12,287ms였고 과거 첫 생성 시간을 포함하는 지연 수치는 아니다.

## 확인한 범위

- 신규 구조 시험 16건을 포함해 관련 세 파일의 시험 310건 통과, 실패 0건.
- 설치된 `tsc --noEmit` 통과. `bun check --no-script`는 해당 명령 미지원으로 실행되지 않아 별도 로그에 보존했다.
- 최초 경계 검수 준비는 기본 옵션을 누락해 모델 호출 없이 끝났다. 실패 원장을 보존하고 기본 옵션을 적용한 두 번째 실행으로 확인했다.
- 77 진단의 정규화된 변화값은 실제 앱의 원문 비교와 달랐다. 원시 응답을 덮어쓰지 않았고 `quote77-integrity.md`에 한계를 기록했다. 이 진단을 독립 품질 평가로 확대하지 않는다.
- 새 전체 통합 QA와 사용자 서버 재시작은 하지 않았다. QA76의 완주 증거는 수정 전 실행으로 남는다.
- 기존 CodeRabbit 등록은 1,393개 변경 파일이 상한 150개를 넘어 거절된 상태다. 이번 수정을 검토 완료로 세지 않는다.
