# 첫 실제 모델 진행 검수

2026-11-09. 원시 기록: `work/continuation/qa/real-1794202058383/`.
리드가 summary와 canonical_first.jsonl의 입력·상태·실제 생성 15문장·대가 기록을 읽었다.

실제 newGame `b00_open`, seed 913에서 행동 7회 뒤 `b08_gaze`에 머물렀다.
종료는 `CampaignQaError: 미준비 실제 입력: b08_gaze[3]`이며 ending은 null이다.
완주나 독립 결말 도달이 아니다. 모델 trace 11건은 요청·시도 기록 수다.
화면·그림·전체 경로 검수 완료로 세지 않는다.

## 정지 원인

| 입력 | 실제 해석·상태 |
|---|---|
| 눈을 마주하며 길을 잃었다고 말함 | person, talks 1, rolls 0 |
| 무슨 잘못인지 말해 달라고 요구 | person, talks 2, rolls 0 |
| 눈을 피하지 않고 숨을 고름 | idle, threat/nudged, rolls 0 |

계획 입력 세 개가 소진됐다. 이것만으로 게임의 무한 반복을 입증하지 않는다.
다만 대본의 stare_back 목표와 실제 예시 `(똑바로 눈을 마주 본다)`는 첫 입력과 겹친다.
모델은 새로운 성취를 노린 시도가 아니라는 이유로 이 입력을 대화로 처리했다.
장면이 요구하는 사회적 의도와 분류 계약의 충돌을 검토해야 한다.
단순 호흡·가만히 있기를 강제 판정하거나 눈 관련 낱말로 접근법을 강제하지 않는다.

## 실제 비용과 문장 연속성

앞선 b05 호소와 b06 칼날 회피는 모두 miss다.
각각 guard_grip(팔 붙들기), guard_hold(뒤에서 팔 꺾어 잡기)가 실제 대가로 기록됐다.
따라서 호위를 근거 없이 생성했거나 회피 성공을 취소했다고 판정하지 않는다.

생성 문장은 이미 팔을 붙든 호위를 다음 판정에서 “뒤에서 나타난 호위”로 새로 등장시킨다.
현재 구속 상태에서 몸을 날리는 연결도 설명하지 않는다.
다른 ID의 대가라도 이미 일어난 행동을 이어 받는 서술이 필요하다.
입력 수만 늘려 같은 새 등장과 재구속을 반복하지 않도록 담당에게 원시 근거를 전달했다.

실제 획득 저장과 선행 로그는 보존한다. 다음 실험은 원인 검토 뒤 배정하며,
임의 상태 주입이나 정사 강제 합류로 이 실행을 완주로 바꾸지 않는다.

## 실제 앱과 시험 설정 차이

담당이 행운 확인 설정 누락을 추가 보고했고 리드도 두 호출부를 확인했다.
서버는 `new Engine(..., Date.now, true)`지만 이 실행의 도구는 기본 생성자를 사용했다.
따라서 useLuck=true 계획이 있어도 실제 앱처럼 행운 확인을 받을 수 없었다.
첫 실행과 획득 저장 8개는 행운 확인이 없는 엔진 변형의 증거로만 보존한다.
이를 정상 앱 진행·정상 앱 저장·화면 완주로 세지 않는다.
도구 설정을 실제 앱과 맞춘 뒤 새 newGame에서 다시 시작해야 한다.
위 b08 분류·고정 예시의 충돌과 연속성 관측은 해당 실행의 원시 결과로 그대로 남긴다.
