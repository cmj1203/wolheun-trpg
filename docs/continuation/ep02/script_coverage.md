## 계승과 입력

시트의 초기 능력·수치는 단독 파싱용 정의다. 부모 연결 모듈은 기존 실행 상태를 그대로 유지하며 새 게임을 만들지 않는다. 소지품은 기존 `magic_bag`, `earring`, `map`, `pin` 네 종류뿐이다. 가방·핀 추가 지급, 압수 가방 복구, 부상 삭제, 시간·귀찌 소급 복구는 없다. 천·꼬치는 플래그이며 물건 목록을 늘리지 않는다. 정사 입장은 부모가 `e_survivor`와 `e_curious`만 연결한다. `e_spy`, 사막 도주·계약·인질·작은 끝을 여기로 강제 접속하지 않는다.

- `ep02_unlock`: 익숙한 기술로 자물쇠를 열면서 소음을 줄이는 것이 판정 대상이다. 성공·혼합·실패 모두 기술 자체는 익숙하며 소음·여유가 달라진다. 실제 행동 결과만 `ep02_confidence`로 이어진다. 무행동은 손을 멈추고 숨을 고르는 서술만 내고 같은 입력 자리에 남는다. 강제 기본 접근 판정은 `stall_idle: true`로 막는다.
- `ep02_question`: 먼저 원작 질문과 더듬는 응답을 읽은 뒤 답변·행동을 받는다. 평범한 대답·질문·침묵은 무판정이다. 의도적인 기만·쓸모 협상·실제 도주만 해당 접근으로 판정한다. 감정·세계 밖 말에 원치 않는 설득이나 도주를 대신 수행하지 않는다.
- 괄호 해석은 기존 입력 처리 계약을 사용하며 새 파서를 만들지 않았다. 다른 장면의 독백·이동·감탄·궁정 대화에는 자유 입력이 없다.

궁정 `ep02_palace`, `ep02_proposal`, `ep02_suspicion`, `ep02_court_boundary`에는 아시나 입식·응답·새 지식 플래그·수첩 항목이 없다. 다만 공유 엔진 `say()`는 모든 대사를 `state.recent`에 쌓고 GM 문맥이 이를 읽으므로, 비공개 대화가 아시나의 기억처럼 쓰이지 않게 부모의 문맥 분리 검증이 필요하다.

자물쇠의 무행동은 동일 비트로 라우팅해 원문을 다시 재생하지 않는다. 기존 `leaveOutcome()`가 비판정 idle에도 진행 횟수를 늘려 잔여 판정을 0으로 표시하는 문제는 공유 담당에게 전달했다. 선택권과 비판정 잔여 횟수 보존은 실제 엔진 회귀로 확인해야 한다. `stage.who`·`identity.with`·`danger.with`도 신규 `ep02_남자`와 기존 남자가 같은 인물임을 인식해야 한다.

## 지도

실제 31비트는 모두 14개 지도 노드에 한 번씩 포함된다. 내부 연결 13개이며 본선은 `ep02_prison`부터 `ep02_court`까지, 질문에서 `ep02_escape`로 성공 분기가 갈라진다. 사막 두 결말과 첫 감옥 노드 사이의 외부 선은 부모가 병합한다.

`atlas.chapters`의 1화 `ep01`은 `ep02_prison`, `ep02_window`, `ep02_pin`; 2화 `ep02`는 `ep02_lock` 이후 모든 노드다. `ep02_escape`만 지도 `ending: true`다. `ep02_court`는 본선의 회차 경계이므로 `ending: false`이며, 후속 화가 연결될 자리에 최종 결말 표시를 붙이지 않는다. 엔진의 회차 경계 결과 화면과 지도에서의 이야기 최종 종료 표시는 별개다.
