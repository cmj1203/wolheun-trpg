# 1화 감옥 후반~2화 연결 계약

`app/src/engine/continuation.ts`가 독립 검증한 기존 사막 대본과 후속 대본을 합친다. 시나리오 식별자 `ep01_desert`, 시작 비트, 초기 시트와 난수 상태는 유지한다.

- `e_survivor`와 `e_curious`만 최종 결과 대신 다음 장의 `계속` 선택지를 갖는다.
- `e_spy`는 가방 압수 결말을 유지한다. 2화 c011의 가방에서 천을 찾는 원문을 이유로 압수를 취소하지 않는다.
- `e_road`, `e_deal`, `e_value`와 작은 끝은 기존 결말을 유지한다.
- 사막 운명과 징조는 `!flag:후속_시작`일 때만 적용한다. 체력 쓰러짐의 별도 지름길 두 곳도 같은 조건으로 제한해야 한다.
- 붙잡힘 장 경계에서 `후속_시작`을 세운다. 기존 종료 저장은 `resumeCampaign`으로 열어 이전 대사를 반복하지 않고 기존 `choose`를 한 번 실행한다.
- 저장된 부상·수치·소지품·공개 정보·기억·지도·난수 상태를 초기화하지 않는다. 후속 장면에서 새로 일어나는 효과만 기존 엔진이 적용한다.
- 소지품 카탈로그는 시작 지급 목록을 겸하므로 후속 물건을 시트에 추가하지 않는다. 원래 갖고 있던 핀·가방·지도·귀찌를 유지한다.
- 감옥 후반과 2화 비트 식별자는 모두 `ep02_` 접두어를 유지한다. 시작은 `ep02_prison_wake`다. 지도에서는 `ep02_prison_*`를 1화, `ep02_lock_view` 이후를 2화 그룹으로 구분한다. 미래 재회 예고, 회차 크레딧 입력 단계, 도시 대사 중복 재생을 넣지 않는다.
- 지도는 같은 시나리오 식별자와 기존 기록을 유지한다. 후속 노드·선은 선언형 데이터로 추가하며 `atlas.ts`는 이 레인에서 수정하지 않는다.

## 2화에서 3화

실제 존재하는 `app/content/ep03_palace.yaml`만 명시적으로 합친다. 3화 시작은 `ep03_c001`이며 `ep02_court_boundary` 한 곳의 종료 표식만 `continue_ep03` 선택지로 바꾼다. 도시 도주와 사막의 독립 결말은 그대로다.

사막 운명 제한은 처음 2화를 합칠 때 한 번만 적용한다. 3화를 더할 때는 이미 제한한 운명·초기 시트·시작·식별자를 유지한다. 궁정 종료 저장도 `resumeCampaign`이 이미 읽은 궁정 대사와 효과를 재생하지 않고 경계 선택을 한 번 실행한다.

지도는 `ep02_court`를 중간 노드로 바꾸고 `ep03_s01`로 잇는다. 3화의 실제 14개 노드와 장 그룹을 합치며, 아직 등록하지 않은 4~10화를 발견하거나 플레이 가능하다고 표시하지 않는다.

공유 파일은 이 레인에서 수정하지 않는다. `shared-integration.patch`를 리드에게 전달하고 적용 결과를 받아 검증한다. 패치는 커밋·푸시·코드레빗 요청이 아니다.
