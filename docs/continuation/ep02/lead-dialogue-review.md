2026-11-09. `work/continuation/ep02/run/real-gm-1794193577130/transcript.jsonl`을 메모리에서 파싱해 GM trace 18건과 실제 action.step.events의 by=gm 대사 22건을 모두 읽었다. 22건에는 고정 입력 안내와 지식 잠금 답변도 포함된다. 새 모델 호출은 하지 않았고 원본 기록을 수정하지 않았다. 최신 입력 분류·지식 수정 전의 기록이며, 수정 후 재검증으로 세지 않는다.

## 판정

전체 내용 PASS가 아니다. 기존 혼합 입력 반려에 더해, 실제 채택된 생성 문장에 중복 표현과 부정확한 신체 묘사가 남아 있다.

| 실제 입력·출력 | 독립 판정 | 필요한 수정 범위 |
|---|---|---|
| 핀 조작 뒤 “이제 문틈 사이로 아주 작은 틈을 만들 수 있었다.” | ‘문틈 사이에 틈’이라는 같은 의미의 중복. 잠금 해제 성공 자체는 보존했다. | 서술 프롬프트와 생성 문장 검수에서 행동의 실제 결과를 한 번만 표현하도록 교정. 이 문자열만 치환하지 않는다. |
| “문이 열려 있어서 걸어 나왔어요.” 뒤 “남자의 눈동자가 비릿하게 휘어졌다.” | 눈동자가 휘어진다는 신체 묘사가 부정확하고 ‘비릿하게’와의 호응도 어색하다. 뒤의 깔아보는 반응은 입력을 무시하지 않는다. | 눈매·입꼬리 등 실제 움직인 부위를 구분하는 자연스러운 문장으로 생성해야 한다. 같은 대사에 수식어만 바꿔 붙이는 처리는 충분하지 않다. |
| 시선과 손목을 보는 동작 + “잡은 손부터 놓아 주세요.” 뒤 “그의 움직임을 읽어낸 남자가 내 손을…” | ‘그’와 ‘남자’의 지시 대상이 충돌하며, 누가 누구의 움직임을 읽었는지 불명확하다. 단순 요구를 판정·의심 상승·이동으로 처리한 의미 오류도 함께 존재한다. | 이미 진행 중인 혼합 입력 의미 분류 수정과 함께, 행동자·대상·반응 주체를 끝까지 일치시켜야 한다. |
| 입맞춤 시도 실패 뒤 손목 저지와 “죽고 싶어 환장했나.” | 실제 실패 결과에 맞는 저지와 강한 인물 반응이 있다. 입력한 큰 행동을 무관한 한 줄로 넘기지 않았다. | 이 기록에서는 성공을 취소한 것으로 판정하지 않는다. 다른 결과의 성공 보존 여부까지 보증하지 않는다. |
| 택시 요청 뒤 “…뭐?” | 현대 개념을 아는 척 설명하지 않고 당혹 반응을 냈다. 문법 반려 사유 없음. | 현재 문장만 PASS. 수치·장면 무변화는 기존 구조 검사 범위다. |

## 버린 후보와 실제 출력 구분

재회 첫 talk trace에는 “그게 네놈의 변명인가?”가 있지만 실제 action 이벤트에는 그 후보가 없고 “그게 탈출한 이유인가?”가 채택됐다. 현재 로어도 ‘네놈’을 금지한다. 따라서 이 기록을 근거로 금지 호칭이 실제 화면에 노출됐다고 보고하지 않는다.

핀 조작의 생성 서술과 뒤의 고정 대본, 입맞춤의 두 narrate 후보도 구분했다. 생성 단계 후보 수를 실제 화면의 대사 수로 취급하지 않았다.

공개 뒤 “그건 아직 몰라.”가 반복된 것은 기존 지식 선택 결함 증거다. 이후 visibleLore 수정과 표시 시점 계약의 실동작이 완성되면 해당 경계만 다시 검증해야 한다. 이 검수는 이미 통과한 나머지 구조 시험의 재실행을 요구하지 않는다.

남은 관문은 수정 후 실제 출력의 문법·주체·행동 결과를 다시 읽는 일과, 화별 자연 진행 기록 전체의 독립 스토리 검수다. 이 문서로 원문 CG 대본 133줄이나 전체 화의 자연 진행 검수까지 완료했다고 주장하지 않는다.
