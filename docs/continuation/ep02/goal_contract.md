# 성공 목표 선언 경계

`FreeSpec.goal`은 기존 자연어 설명이다. 새 `FreeSpec.goals`는 성취 효과·도착지·독립 비용을 가진 선언표다. `ApproachSpec.goal`은 같은 비트의 목표 ID를 참조한다.

`scenario.ts`는 비어 있거나 예약된 `local`·`none` 목표 ID, 미지 접근법 참조, 도착지·조건·비용 참조 오류, hard 비용 연결, 성취 효과의 중복·덮어쓰기를 검사한다. 성공 경로는 목표가 소유하며 `edgesOf`도 목표 경로를 포함한다.

`price: []`는 추첨을 끈다. 혼합 결과에 실제 인라인 비용이 있으면 허용한다. 수치 보너스만으로 비용을 대신할 수 없다. 목표 비용과 인라인 비용을 동시에 적용하는 선언은 거부한다. 이야기 속 독립 비용인지, 자원 바닥에서 실제 차감되는지는 실제 엔진과 스토리 QA로 확인해야 한다.

`work/demo-slice/lane63/improv-parser.patch`를 대조했으며 기존 `scenario.ts`를 그 패치로 덮어쓰지 않았다. 해당 패치의 빈 목표 비용 일괄 거부는 적용하지 않았다.

2026-11-09 검증:

- `bun test ./tests/continuation_goals.test.ts ./tests/continuation.test.ts --timeout 10000`: 36개 통과, 실패 0개, 단언 98개, 113ms.
- 같은 통합 검사 중 `tsc --noEmit`은 공유 수정의 `eval/run_kinds.ts:35`에서 `Interpretation` 새 변형에 `spoken`이 없다는 오류 1개를 냈다. 해당 파일은 이 레인이 수정하지 않았다.
- 실제 GM 서버 18192는 운영 요청으로 종료되었다. 모델 없는 결과를 실제 GM 검증으로 표시하지 않는다.

실행 계약 대조에서 남은 불일치:

- 당시 `engine.ts`의 `planProblem`은 목표의 빈 비용 목록을 인라인 비용과 무관하게 거부했다.
- 당시 `finishResolve`는 즉흥 목표 성공에서 일반 결과의 효과를 비우므로 인라인 비용도 사라질 수 있었다.
- 이는 파서의 허용 범위를 줄여 숨길 문제가 아니다. 기존 엔진 담당에게 알려 빈 목록·인라인 실비용 계약을 실행 경로에서도 맞추도록 요청한다.

후속 YAML의 목표 선언은 이 경계 검사와 엔진 처리를 맞춘 뒤 추가하고, 자물쇠와 도시 도주의 성공·혼합 성공이 다음 대사에서 취소되지 않는지 확인한다.
