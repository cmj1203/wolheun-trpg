## 기존 종료 저장 변환

3→4와 동일하게 각 행의 **beat와 ending ID 쌍**을 경계 레지스트리에 등록한다. `ending` 값만 같다는 이유로 다른 비트의 저장을 변환하지 않는다. 위 계속 선택이 실제 합성 비트에 존재하는지까지 확인한 뒤 다음 순서로 처리한다.

1. 저장 GameState 전체를 복제한다. 기존 판 ID·시나리오 ID·난수·플레이 시간·수치·소지품·플래그·변장·이름·발화·들은 기억·방문·지도 진행을 유지한다.
2. `ending`만 null로 열고 해당 경계의 실제 계속 선택을 한 번 실행한다. 전편 시작이나 이미 읽은 출발 비트를 다시 enter하지 않는다.
3. 출발 비트의 원문·효과는 이미 반영된 저장 상태이므로 다시 적용하지 않는다. 다음 실제 비트의 정상 효과만 실행한다.
4. 4화 거리 저장에는 공통 `continue_ep05` 선택과 `ep05_entry`의 비접촉 분기가 실제 존재해야 한다. 성취 플래그를 지우거나 근접 경로로 대체하면 안 된다.
5. 5화의 인사 여부는 실제 줄의 발화 플래그를 사용한다. 미선택 질문을 새로 발화시키거나 두 장에서 같은 입력을 다시 받지 않는다.
6. 기존 종료 저장은 새 목표와 가격을 새로 판정하지 않는다. 원래 ending 기록을 과거 로그에서 삭제하거나 성공 결과를 local로 축소하지 않는다.

현재 helper의 `BOUNDARIES`와 실제 합성은3→4·4→5 두 종료·5→6·6→7·7→8·8→9·9→10 전체가 등록돼 있다. 부모가 실제 소스의 각 ending/choice 쌍과 `connectChapter` 호출을 읽어 위 표와 대조했다. `resumeCampaign`은 등록되지 않은 경계를 `continued:false`로 돌려준다. 연결과 구조 적재 확인만으로 각 과거 저장의 실제 HTTP 재개까지 통과했다고 보지 않는다.

## 상태와 지도 보존

- 모든 새 합성은 기존 캠페인의 sheet와 플레이 중 GameState를 유지한다. 각 chapter.sheet는 독립 실행용이며 다음 화를 붙인다는 이유로 현재 소지품·수치·이름·변장을 재초기화하지 않는다.
- 7화의 짐 일부 반환은 전량 반환이 아니다. 치부책 반환·석방·출궁 허가를 만들지 않는다. 8화 관객 알현의 게디크/자키야 정보와9화 관객 칼·호칭은 아시나의 들은 기억으로 옮기지 않는다.
- 9화 c001의 복사된 `lose: [magic_bag, map]`은 소유자가 제거했고, 전달받은 실제 inventory 전부 보존 회귀를 추가했다. 7화 c003 마지막 줄은 `ep03_짐_수중없음=false`·`ep07_짐_부분반환=true`만 설정하며 전체 gain은 없다. 4화의 기존 lose는3화 압수에 이어지는 현재 계약으로 유지한다.
- 표의 좌표는 현재 원본 값이다. 화5·6·8·9·10은 독립 지도 좌표로 서로 겹칠 수 있어 UI 소유자가 장별 배치를 통합해야 한다. 비트 ID와 노드/장 소속을 유지하고 연결 edge를 추가한다. 좌표만 맞췄다고 실제 경로가 연결되었다고 보지 않는다.
- 출발 노드는 연결 뒤 ending=false가 되어야 한다. 현재8화 출발 노드는 이미 false이고9화는 ending 필드가 없으므로, 원래 표시값이 아니라 실제 종료 비트 기준으로 경계 처리를 결정한다.
