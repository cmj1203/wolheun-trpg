- 리드가 전달한 사용자 전체 todo는 **10/28 완료**다. 이 레인의 내부 todo를 닫는 것으로 사용자 전체 todo를 바꾸지 않는다.
- 그림은 **계획 위치 / 계획 고유 후보 / 실제 PNG / 도구 차단 / 보류 / 독립 승인 / 실제 설치**를 나눠 보고한다. 원작 입력 PNG·원본 크롭·대조판·거절 입력은 실제 생성 후보 PNG 수에 포함하지 않는다.

## 집계 근거

기존 산출 manifest와 실제 완료 영수증만 사용한다. 파일을 다시 세거나 통과 시험을 반복해 집계하지 않는다. 대장이 초기 계획 스냅샷이면 실제 생산 수의 근거로 쓰지 않는다. 해당 writer가 이미 수집한 성공 영수증·SHA를 다음 정상 기록 시 생산 대장에 반영한다.

CLI 종료0만으로 생성 성공을 세지 않는다. 실제 결과 PNG의 존재·기록된 해시·완료 영수증이 있어야 한다. 독립 승인이 없거나 설치하지 않은4~10화 신규 후보는 **독립 승인0 / 실제 설치0**으로 유지한다. GPT의 원작 비교 기록은 Claude 독립 승인이 아니다.

실제 PNG는 파일 생성 수이며 미술 합격 수가 아니다. 원작 가림 위반으로 보류된 PNG도 이 수에 포함될 수 있으므로 **실제 PNG6개 중 보류1개**처럼 포함 관계를 쓴다. 보류를 실제 PNG에 다시 더해 합산하지 않는다. 알려진 원작 차이는 같은 writer가 정상 실행을 보존하며 교정하고, 새 후보도 독립 검수 전 상태로 남긴다.

## 리드 보고 시점

정상 PNG 증가와 PID 교체는 기존 생산 대장·감시에만 기록한다. 별도 보고는 한 화 생성 묶음 완료, 새 도구 거절·원작 불일치, 실제 실행 중단, 독립 검수 준비처럼 다음 조치가 바뀌는 사건에 한정한다. RPC 응답턴 오류만으로 정상 native runner·감시를 재시작하거나 중복 생성하지 않는다. 기존 writer의 소유권을 유지한다.

## 5화 거절 시점 스냅샷

`ep05/art/generation-final-manifest.json`의 첫 차단 시점은 다음과 같다.

| 분류 | 수 |
|---|---:|
| 전체 매핑 위치 | 74 |
| 계획 고유 후보 | 72 |
| 실제 PNG | 1 |
| 최종 도구 차단 | 1 |
| 미호출 고유 후보 | 70 |
| 그림 승계 위치 | 2 |
| 독립 승인 | 0 |
| 실제 설치 | 0 |

거절1+미호출70을 합친71은 미해결 재고다. **71개 재생성 대기열이 아니다.** 거절된 `ep05_c002_p01`은 최종 도구 차단으로 유지하며 재시도·변형 우회를 하지 않는다. c003~c009 보류는 미호출 재고 안의 하위 상태이므로70에 다시 더하지 않는다.

별개 비성적 아침·궁정·소개·차·일상 장면의 새 결과는 재개 대장에 따로 기록한 뒤 후보 ID 기준으로 합친다. `resume-after-block-result.json`은 첫 아침 궁정 c010_p02의 종료0·출력 존재·SHA를 기록한다. 과거 차단 시점 스냅샷을 현재 생산 수라고 바꾸어 읽지 않는다.

원작 서사를 삭제하거나 차단된 앵커에 임의의 대체 장면을 넣지 않는다. 이 컷의 미해결 상태는 최종 전달 조건에 남으며, 다른 그림 제작 완료로 감추지 않는다.
