## 혼합 비트 분할

새 비트는 `ep10_c034_question`, `ep10_c034_audience`, `ep10_c035_audience`, `ep10_name_audience` 네 개다.

- 기존 c033 → 새 c034_question의 왕 질문 → 새 c034_audience의 독백 2줄 → 기존 c034의 이름 선택. 원래 선택 ID·대사·효과·분기는 기존 c034에 그대로 남는다. 실제 선택 응답은 주인공 시점이다.
- 기존 name_source의 아시나 답변과 진명확인 효과 → 새 name_audience의 왕 독백 → 기존 c035. 진명확인 효과는 원래처럼 아시나 답변 비트 진입에 남겨 시점을 바꾸지 않았다.
- 기존 c035의 가족투표 발화 → 새 c035_audience의 왕 독백 → 기존 c036.
- c037·c071은 원래 왕 독백만 있는 비트라 분할 없이 관객 시점만 선언했다.

왕 질문과 모든 아시나 발화는 미선언 주인공 시점이다. c034의 빈 선택 비트도 주인공 시점으로 돌아온다. 새로운 대사나 CG를 만들지 않았으며 원래 줄 순서·각 줄의 CG를 유지했다.

지도 노드 ID·좌표·간선은 그대로다. `ep10_c034_decision.beats`에는 question·audience·기존 c034 순서, `ep10_name_source_node.beats`에는 기존 name_source·새 name_audience 순서로 넣었다. `ep10_s05.beats`에는 c035 바로 뒤에 새 c035_audience를 넣었다.

c070은 화자 미확정 침묵이며 관객 시점을 선언하지 않았다. 왕의 인접 독백으로 화자를 추정하지 않았다. c049·c053의 앞서 교정한 줄 효과, 라 쿤 호칭 분기, 손목 비판정·거리 확보 분기는 그대로다.

## 이번 단계 확인과 대기

이번 변경 직전 YAML을 메모리에 보관했다. 변경 후 실제 YAML을 `Bun.YAML.parse`로 파싱하고 다음 새 선언 검사만 실행했다.

1. 관객 비트 집합이 위 5개와 정확히 같음.
2. 관객 비트의 모든 줄이 `ep10_왕속마음`이고 총 8줄임.
3. 새 분할을 역으로 합치고 새 관객 속성과 지도 멤버만 제거하면 변경 직전 전체 선언과 `Bun.deepEquals` 결과가 true임.

결과는 모두 통과했다. 전체 선언 역비교에는 발화·CG·순서·효과·선택·이전 플래그 교정·c070·손목·호칭 분기·지도 간선이 포함된다. 구조 비교이지 런타임 검증은 아니다.

작업 시점 `app/src/engine/scenario.ts`에는 `perspective` 파싱이 없었다. 따라서 파서와 루트 런타임 준비 후의 실제 파싱·주인공 recent/spoken 제외·표시 시점 확인·질문 격리는 대기다. 원작 관객 대사는 계속 표시되어야 하며, TYPE_READY만으로 기억 격리를 구현했다고 주장하지 않는다. 이 단계에서 기존 7개 통과 검사나 타입 검사를 반복하지 않았다. 새 테스트 파일은 추가하지 않았고, 파서·런타임 통합 후 새로 필요한 검사는 부모 소유다.
