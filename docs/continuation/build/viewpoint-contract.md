# GM 표시 시점 계약

2026-11-09 리드 설계. 구현 완료 보고가 아니다. 자문 작업은 모델 요청 전에 두 번 거절되어 리드가 실제 코드를 읽고 작성했다.

자문 `st_01a1be39`의 재시도·초기화 대기는 종료한다. 작업 상태는 `error`로 실행 중이 아니며, 대응 todo `GM 시점 계약 자문 재개 (클로드 초기화)`는 이미 완료 상태다. 이 문서가 실패한 자문을 대체했고 공유 엔진 담당이 전체를 읽고 구현 계약으로 수용했다. 추가 자문 호출은 필요 없다. 남은 일은 TYPE_READY 이후 실제 구현·표시 시점 회귀·모델/화면 검증이며, 정상 제작·검수 작업은 유지한다.

## 확인한 문제

| 근거 | 판정 |
|---|---|
| `Engine.askGm`은 화면 scene만 바꾸고 앞서 진행된 state와 stateBeat.free/lastFree를 사용한다 | 코드로 확인 |
| `say`는 관객용 궁정 대사도 recent/spoken에 넣고 prompt가 이를 읽는다 | 코드·후속 실제 경로로 확인 |
| 첫 감옥 화면에서 나라를 묻자 이전 사막 위치를 답하고 CG가 꺼졌다 | 실제 UI에서 확인. 나라 이름 누출은 이 호출에서 없었음 |
| 열린 fesian/jail이 hidden 등급과 원본 interpret 목록 때문에 선택되지 않는다 | 별도 공개 후 결함. 표시 시점 문제와 구분 |
| 현재 화면보다 뒤 공개줄의 flags를 GM이 읽을 수 있다 | 코드상 경계 결함. 공개 전 나라 누출 자체는 아직 UI에서 입증하지 못함 |

현재 `GameEvent.scene`에는 beat·배경·cast가 있고 `line`에는 표시 내용이 있다. 질문 Action에는 scene만 있다. 한 비트 안의 공개 전후를 식별하는 서버 측 줄 커서는 없다. 지도 표시 토큰은 scene 순서를 확인하며 줄의 공개 시점을 증명하지 않는다.

## 결정

권위 GameState는 되감지 않는다. 엔진이 실제 이야기 장면·줄을 만들 때 **그 시점의 읽기 전용 GM 투영본**을 별도로 잡고, 서버가 송신한 순서와 실제 표시 확인을 연결한다. 질문에는 서버가 확인한 마지막 표시 투영본을 사용한다.

클라이언트가 flags, recent, 소지품, 임의 과거 state를 보내 GM 상태로 쓰게 하지 않는다. `action.scene`만 바꾸거나 마지막 free를 재사용하는 방식, 현재 flags에서 아직 안 읽은 키를 추측해 지우는 방식은 채택하지 않는다.

## 엔진 경계

1. `newGame`·`act`·`resume` 및 `resumeCampaign` 내부 act가 같은 비공개 표시 관측 훅을 전달한다. 외부 DTO인 Step/GameEvent에 전체 투영 state를 넣지 않는다. 서버만 훅으로 받은 투영본을 보관한다.
2. 일반 이야기 line은 그 줄의 실제 `sets/effects`와 기억 처리가 반영된 시점에 잡고 미래 줄 효과는 포함하지 않는다. scene과 lead의 진입 경계는 아래 확정 규칙을 따른다.
3. 현재 act의 push 훅은 즉시 스트림으로 보내고, say는 line을 push한 뒤 sets/effects를 적용한다. 따라서 기존 push 옆에서 무조건 state를 복사하면 공개 플래그가 한 줄 늦는다. say에서 줄과 부수 change 이벤트를 로컬로 모아 상태를 확정한 뒤 기존 **line → change** 표시 순서를 보존하여 송신한다. 진입 opening batch도 아래 규칙으로 확정한 뒤 송신한다. 임의 지연·타이머로 순서를 맞추지 않는다.
4. 투영본은 GM이 읽는 그 순간의 상태 필드를 보존한다. flags/recent만 바꾸고 items·tracks·heard·said·spoken·완료 행동은 앞선 값을 그대로 주면 안 된다. 전체 log를 줄마다 복제하지 않고 시점의 log 길이와 나머지 상태를 보관한 뒤 질문 시 해당 로그 prefix를 구성할 수 있다. 배열·객체를 권위 state와 변경 가능하게 공유하지 않는다.

### lead가 있는 진입 경계 확정

실제 enter는 scene → 각 lead의 say → onEnter 효과 → 본문 순서다. 이 권위 실행 순서를 보존한다. 현재 `b07_rule`의 lead는 `!flag:후드_벗음`일 때 후드가 벗겨지는 줄을 내고 onEnter가 그 플래그를 세운다. 효과를 lead 앞으로 옮기면 실제 조건과 CG 대체 선택의 의미가 달라진다.

opening batch를 onEnter 확정까지 로컬에 보관하며 그 전에는 송신·관측 훅 호출·클라이언트 확인을 허용하지 않는다. 상태는 원래 순서로 한 번만 진행하고 되감기나 가상 상태에 효과 재실행을 하지 않는다.

| 실제 출력 | 확정할 관측 시점 |
|---|---|
| 실제로 출력할 lead가 없음 | scene은 onEnter 효과 후, 본문 전. 입력·선택만 있는 무대사 장면도 이 상태를 사용 |
| 실제 lead가 있음 | scene은 첫 lead 전. 아직 읽지 않은 lead의 기억·효과를 포함하지 않음 |
| 마지막 이전 lead | 해당 say의 기억·줄 효과 후. 뒤 lead와 onEnter 효과는 포함하지 않음 |
| 마지막 실제 lead | 해당 say 이후 onEnter 효과까지 확정된 시점, 본문 전 |

실제 lead는 원본 배열 길이가 아니라 기존 if 평가·spoken 중복 제외 뒤 송신되는 line을 뜻한다. 각 줄의 if·CG 대체는 기존 실행 시점에서 고른다. 앞 lead의 투영은 그 순간 복사하고 마지막 관측만 송신 전에 진입 완료 경계로 확정한다. observer가 받은 관측을 나중에 덮어쓰지 않는다.

송신 순서는 기존 scene → lead와 그 줄의 change → 나머지 lead → entry change → 본문을 유지한다. 마지막 lead까지 읽고 질문하면 그 진입의 소지품·후드 변화가 반영되며, 앞 lead에서 질문하면 뒤 lead의 공개 내용은 보이지 않는다.

회귀는 lead 0/1/2개, 첫째와 둘째의 서로 다른 공개 효과, 기존 if·CG 대체 선택, 필터로 모든 lead가 사라지는 경우, 무본문 choice, 실제 b07 후드를 포함한다. 권위 최종 상태·효과 1회·이벤트 순서·앞줄의 미래 정보 차단을 함께 검사한다. 이는 이전의 일괄 “scene은 진입 효과 후” 문구를 이 경계에 맞게 정정한 것이다.
5. GM 오버레이·수정 안내는 세계 사건이 아니다. 새 이야기 표시 시점이나 세계 대화 기억으로 기록하지 않는다. 생성된 NPC/나레이션 이야기 줄은 실제 세계 줄이므로 script/gm 생산자 구분만으로 제외하지 않는다.

투영본 형식은 표시 frame의 scene 식별자, 서버 내부 상태 스냅샷, 해당 log prefix 경계를 가지면 된다. 클라이언트에는 회전 가능한 불투명 frame 식별자만 준다. 새 세계 행동·분기 변경 때 세대를 바꾸고 이전 frame을 다른 세션에서 사용할 수 없게 한다.

## 관객 장면과 기억

현재 필요한 범위는 주인공 중심 GM 대화다. 전 인물용 범용 기억 저장소를 새로 만들지 않는다.

- BeatSpec에 명시적인 관객 시점 표시를 추가한다. 예: `perspective: audience`. 미선언 기존 장면은 주인공 시점을 유지한다.
- 현재의 2화 궁정 제안과 3화 비공개 접견 등은 원문에 따라 명시한다. cast 슬롯에 주인공이 없다는 사실만으로 판단하지 않는다. 화면 밖 주인공 POV·회상도 있기 때문이다.
- 관객 전용 줄은 기존 이벤트·원작 사건·감사 기록에 남긴다. 주인공에게 들린 대화인 것처럼 recent/spoken에 넣거나 이후 주인공 중심 GM 문맥에 섞지 않는다. 해당 기록의 의미는 플레이어 캐릭터의 세계 내 경험과 반복 방지다.
- GM 조작 질문·답변도 인물이 들은 세계 대화가 아니므로 이 기억에 섞지 않는다.
- 관객 장면을 보면서 누른 GM 버튼은 현재 화면에 실제 표시된 말의 뜻을 설명할 수 있다. 이때 서버 확인된 표시 줄을 질문 문맥으로 따로 주며, 이를 아시나의 recent/spoken/획득 지식으로 복사하지 않는다. 현재 beat의 아직 표시하지 않은 전체 lines를 문맥으로 주지 않는다.
- 관객용 상태 플래그를 주인공 지식 공개 조건으로 사용하지 않는다. 같은 장면을 사람이 보았다는 사실과 아시나가 들었다는 사실은 다르다. 현재 데이터의 관객 플래그와 knowledge 조건을 대조한다. 이름 문자열 목록으로 비공개 대사를 지우지 않는다.
- NPC가 가진 원래 신분·성격·가치관과 정당한 사건 이력은 유지한다. 주인공 중심 최근 대화에서 제외한다는 이유로 정사 사건이나 인물 설정 자체를 삭제하지 않는다.

## 표시 확인과 질문

서버의 세션 표시 런타임에 이야기 scene/line의 순서와 비공개 투영본을 보관한다. 기존 AtlasPlayback의 노드 방문 횟수를 줄 횟수로 몰래 바꾸지 않는다. 지도 scene 확인과 GM 줄 확인은 구분하되 같은 실제 송신 순서를 사용한다.

1. 클라이언트는 CG 준비·디코드 및 이름표·대사 표시를 완료한 현재 줄만 확인한다. 타이핑 중 GM 버튼을 누르면 **현재 줄만 끝까지 표시**하고 확인한 뒤 질문을 연다. 다음 대사 큐를 소비하지 않는다. 따라서 문장 첫 글자만 보인 상태에서 그 줄의 나머지 공개 정보를 질문 답변이 먼저 말하지 않는다.
2. 서버는 세션·표시 세대·토큰·다음 확인 순서를 대조한다. 실제 엔진 로그에 존재하거나 이미 송신한 미래 frame이라는 이유만으로 중간 줄을 건너뛰는 확인을 허용하지 않는다.
3. 질문은 마지막 확인된 frame을 지정한다. 서버가 그 frame의 투영본과 scene으로 GM 문맥을 만든다. 원시 client view나 임의 flags를 채택하지 않는다.
4. 현재 scene에 free가 없으면 현재 conversation 또는 현재 장면의 최소 질문 문맥을 사용한다. 이전 장 lastFree의 목표·화자·상황을 가져오지 않는다. 현재 위치는 시작 사막 고정 설명이 아니라 해당 표시 장면과 그 시점에 알려진 지식으로 답한다.
5. visibleLore를 이 동일 투영본으로 한 번 계산하여 system·interpret user·schema·about 선택 검증에 일관되게 쓴다. 조건이 열린 hidden만 아는 항목으로 바꾸며, 영구 hidden은 열지 않는다. 질문이 생성되는 동안 권위 state가 앞서가도 문맥이 바뀌지 않는다.
6. 질문은 기존 표시 frame과 남은 이야기 큐를 유지한다. 메타 질문 때문에 앞선 이야기 frame을 다른 세계 행동 세대로 취급하거나, 답변을 새 이야기 시점으로 만들지 않는다. 답변 닫기 뒤 같은 줄로 돌아온다.

실제 사람의 눈이 글을 읽었음을 증명하는 보안 기능은 아니다. 정상 UI가 실제 표시한 내용과 GM 문맥의 계약이다. 미래 state를 client에 넘겨 신뢰하는 방식은 필요 없다.

## 저장·복원

- 새 저장은 현재 확인된 투영본과 아직 표시하지 않은 서버 송신 frame들의 투영본을 서버 저장 데이터에 함께 보존한다. client가 보낸 frame 상태로 덮지 않는다. 현재 frame 하나만 보존하면 중간 대사 저장 뒤 남은 줄의 시점 정보가 사라진다.
- 복원은 새 세션의 확인 토큰을 발급하여 같은 표시 큐·시점 정보를 사용한다. scene 진입·sets/effects·가격·판정·RNG를 다시 실행하지 않는다.
- 기존 종료 저장에서 다음 화로 열 때는 실제 `resumeCampaign`의 새 진입에 관측 훅을 전달한다. 이미 읽은 종료 효과와 신규 감옥 효과를 혼동하지 않는다.
- 구형 저장에 줄별 시점 증거가 없으면 정확한 과거 투영본을 복원했다고 주장하지 않는다. 현재 scene만 맞추고 앞선 flags를 주는 fallback은 금지한다. 상태 없는 조작 안내는 제공할 수 있지만 동적 지식 답변은 증거가 있는 다음 경계에서 재개한다. 구형 남은 대사 큐를 다 표시해 권위 상태와 표시 시점이 다시 일치하는 경계 또는 새 행동에서 새 증거를 만든다. 그 한계를 문서·실제 시험에서 명시한다.

## 수용 증거

- 같은 beat의 나라 공개 줄 직전·완전 표시 직후 같은 질문: 전에는 이름/본문/선택 ID가 닫히고 후에는 열린다.
- 감옥 첫 scene에서 엔진이 2화 자물쇠까지 처리했어도 질문은 현재 감옥·현재 소지품·현재 지식만 사용한다.
- 관객 궁정 대화를 본 뒤 시녀 대화: private 문장이 recent/spoken/프롬프트에 없고 정사 이벤트 기록에는 남는다.
