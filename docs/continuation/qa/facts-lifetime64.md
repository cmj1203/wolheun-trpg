# 캠페인 사실의 성립 근거와 수명

## 원인과 수정 경계

`connectChapter`는 후속 facts를 출처·진입 조건 없이 합쳤고 `activeFacts`는 전달된 state의 조건만 평가했다. 따라서8화 항진식과 아직 없는 플래그의 부정 조건이2화에서도 참이었다. 질문의 confirmed/private 분리 자체가 id14 누출의 원인은 아니다.

이 작업은 `continuation.ts`와 새 집중 회귀·fixture·문서만 쓴다. gm/prompt/engine/types/YAML, 서비스와 UI29/18251은 바꾸지 않는다. 추론·예열·서버 재기동은 없다.

## 최소 계약

1. 사실의 원래 OR/AND 조건을 보존한다. 각 OR 분기에 성립 근거가 있는지 따로 본다.
2. 이전 화 또는 소유 화에서 실제로 만들어지는 양성 사건 플래그가 있는 분기는 원래 조건의 수명을 유지한다. 이미 발생한4화 거리 유지가5화 사실로 선언됐어도5화 진입까지 숨기지 않는다.
3. 근거 없는 부정·수치·상수 분기는 그 사실 소유 화의 진입 증거를 AND한다. `gate && A || B`로 누출을 남기지 않고 각 OR 절에 배분한다.
4. 새 엔진은 캠페인 조립이 시작 효과에 넣은 전용 진입 표식을 실제 관측에서 받는다. 기존 실제 저장의 해당 화 고유 사건·실발화 표식도 진입 근거로 쓸 수 있다. 기존 state에 과거 표식을 임의로 주입하지 않는다.
5. 독립 검증 전용 사실은 캠페인 공개 근거가 아니다. 원본8화 facts[0]의 역할을 조립의 출처 메타데이터로 분리한다. FactSpec에 id/scope가 없어 원본 chapter id와 순번을 쓰며, 본문·숨긴 이름 문자열로 필터하지 않는다. 원본 standalone 정의는 그대로 남긴다.
6. 공개 근거는 전달받은 confirmed/private state로만 평가한다. 앞서간 권위 state에서 진입·발화를 가져오지 않는다.

출처 역할 메타데이터는 현재 authoring 구조의 한계다. 원본 facts의 순서를 바꿀 때 이 역할도 함께 검토해야 한다. 정식 YAML id/scope를 추가하는 변경은 이번 허용 범위에 포함하지 않았다.

## 실제 획득 자료와 회귀

`fixtures/continuation-facts-earned64.json`은 실제 정상 판 `real-1794206518713`에서7개 관측과4개 획득 저장을 보존하고, 실제 question-relation64의 HTTP 확정 프레임을 함께 담는다. 원본 파일·row·SHA·origin을 기록했다. 관측 log는 같은 action의 실제 저장 log를 관측 logLength까지만 복원했고 flags/items/RNG/beat는 바꾸지 않았다.

- 실제2화 confirmed 질문의 공개 evidence와 분류 system에서 미래 사실을 배제하고 이미 벗은 후드 사실은 남긴다.
- 실제 earned_33에서 모델 없이 계속 선택해 새 조립의8화 첫 scene을 관측한다. r01 이전에도 현재 대기 사실이 성립하고 독립 검증 메모는 없어야 한다.
- 기존8화 첫 실제 대사 프레임도 원시 플래그를 주입하지 않고 읽는다.
- 실제 earned_34에서 나온 c034 scene/line을 ViewpointPlayback으로 순서대로 confirm한다. 권위 state는 이미 r10=true지만 앞선 확정 scene 질문에는 대기 사실, 공개 line 뒤에는 획득 사실만 있어야 한다.
- 실제9/10화 프레임에서도 r10 획득 사실은 남고 독립 검증 메모는 없어야 한다.
- 다른 새 부정·OR 조건, 앞 화 조건 계승, 원본 입력 불변은 별도의 조건 단위 회귀다. 가상 조건 상태를 정상 판·전체 스토리 증거로 세지 않는다.

기존 원시 요청과 소비 경계의 별도 조사 정본은 `facts-lifetime-frame-evidence.md`다. 이번 새 회귀는 원래 모델 실행이나 전체 게임 품질 승인이 아니라 실제 획득 자료에서의 오프라인 근거·시점 회귀다.

## 검증 기록

제품 수정 전 새 집중 회귀는3 pass / 6 fail이었다. 실제2화 공개 근거·분류 system,8화 첫 진입과 기존 실제 프레임,9/10화 standalone 배제, 다른 새 OR 조건에서 실패했다.

수정 뒤 **같은9개 회귀가9 pass / 0 fail, 40 expect**로 통과했다. 전체 시간은 기록상202ms다. `tsc --noEmit`은 진단 없이 exit0이다. 다른 과거 통과 묶음·전체 테스트·모델 실행을 더하지 않았다.

독립 검증용 원본 역할은 standalone8화 로드에 남고 캠페인에만 제외된다. 배운 ep08_r10 사실은9/10화에서도 남는다. 양성 사건 조건·종료 조건을 새로 추정하거나 전 화 facts를 통째로 버리지 않았다.

새 합성 진입 표식이 없는 구형8화 첫 scene만 있고 그 화의 실제 사건·발화 표식도 전혀 없으면 그 state만으로 진입을 복원하지 않는다. 해당 구형 첫 scene의 대기 사실 양성을 이 검사로 주장하지 않는다. 새 조립의 첫 scene은 실제 획득7화 저장에서 엔진을 진행해 검증했고, 기존 첫 실제 대사 프레임은 발화 표식으로 확인했다. 권위 상태에서 정보를 가져와 메우지 않는다.

모델 질문 의미·원시 응답 품질은 이번에 새로 측정하지 않았다. 이미 실행 중인 UI29/18251에 새 조립이 반영됐다고 주장하지 않으며 재기동하지 않았다. gm/prompt/engine/types/YAML도 변경하지 않았다.
