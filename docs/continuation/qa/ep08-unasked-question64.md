# 8화 미선택 질문 출력 수리

## 리드 실제 화면 인수

기존 실제 획득 지도 n113/c21을 UI에서 재시작하고 home과 ask를 각각 한 번 선택했다. 격리 서버 18255, NO_LLM, 1440×1000이며 상태·대사·판정을 주입하지 않았다.

- home: `여기에는 어떤 사람들이 살아?` 한 줄 뒤 누르의 `보통 하렘은 집의 안주인들이 사는 곳입니다.`가 실제로 표시됐다. c025의 크기 질문은 원문 응답과 화면 관찰 모두에 없었다.
- ask: 원래 크기 질문 두 줄 뒤 같은 누르 답변이 표시됐다.
- 두 선택 요청은 각각 HTTP 200 한 번이다. 실제 첫 답변까지의 분기 계약과 UI 본문·이름·빈 화면 검사는 독립 검수 PASS다. 그 뒤 미래 응답이 네트워크 전문에 들어 있다는 이유로 화면 완주로 세지 않는다. 장 경계·발화 플래그·공개 시점은 아래 엔진 시험의 범위다.

`work/continuation/qa/ep08-unasked-question64/`의 `home-ui.json`, `ask-ui.json`, `home-ui.png`, `ask-ui.png`, `ui-review.md`가 근거다. 두 사진은 같은 누르 첫 답변을 찍었으며 서로 다른 질문을 증명하는 사진으로 쓰지 않는다. 질문 차이는 실제 화면 관찰과 NDJSON line 이벤트로 확인했다.

별도 시각 항목은 미해결이다. 원작 세로 CG c026이 약 130px 폭으로 표시되며 그림 속 말풍선 글자는 작고 아래가 대사창에 가린다. 화면 아래의 게임 대사는 정상적으로 읽힌다. 질문 연결 한 줄 수정과 분리해 기존 8화 그림 제작·검수 담당에게 원작 기반 확장·말풍선 제거 잔여로 전달했다. 전체 UI·미술 승인 PASS가 아니다.

Ego 공간 39는 종료 후 목록에서 없어진 것을 확인했다. 검사 서버 종료 도구는 모니터 상태 파일 삭제 오류를 반환했으나, 서버 HTTP 연결이 끊긴 것으로 실제 종료를 확인했다. 사용자 18080/18081은 변경하지 않았다.

## 원인과 원작 대조

`ep08_c024_ask`와 `ep08_c024_home`이 모두 `ep08_c025`로 연결됐다. home을 고르면 선택문인 “여기에는 어떤 사람들이 살아?” 뒤에 선택하지 않은 크기 질문 두 줄까지 아시나가 발화했다.

원작 근거는 `docs/continuation/ep08/script.md:237–273`과 `work/ep08/merged/ep08_006.png`다. 원본 이미지의 c025 질문과 c026·c027 설명을 직접 보았다.

- c025는 “하렘은 왜 이렇게 큰 걸까?”와 “누르는 그 이유를 알아?”다.
- c026은 안주인, 쿤의 여인들, 연고 없는 어린 소녀라는 거주자를 설명한다. 사람을 묻는 home 질문에도 직접 답한다.
- c027은 그 소녀들이 자란 뒤의 혼인 역할을 묻고 답한다. c026에서 소녀를 소개하므로 양쪽 선택에서 자연스럽게 이어진다.

따라서 home의 `next`만 c025에서 c026으로 바꿨다. ask의 원작 질문, 누르 답변, 다음 질문, 이후 사건은 그대로다. 새 대사나 문장 재작성은 없다.

## 실제 엔진 출력 비교

기존 `app/tests/ep08_harem.test.ts`의 두 경로 행을 확장했다. 이 시험은 실제 로더와 Engine을 쓰고, 선택으로 출력된 line의 화자·본문·CG를 비교한다. FakeGm 호출은 양쪽 모두 0이다. 기존 시험의 전체 방문 순서만으로는 잘못 추가된 질문을 구별하지 못했으므로 그 경계에 검증을 더했다. 새 제품 함수나 시험 전용 공개 인터페이스는 없다.

| 선택 | 수정 전 질문 출력 | 수정 후 질문 출력 |
|---|---|---|
| ask | 크기 질문 두 줄 · c025 CG | 동일한 두 줄 · c025 CG |
| home | 사람 질문 한 줄 · c024 CG → 선택하지 않은 크기 질문 두 줄 · c025 CG | 사람 질문 한 줄 · c024 CG |

양쪽에서 다음 실제 출력 다섯 줄도 동일함을 검증했다.

| CG | 화자 | 출력 |
|---|---|---|
| c026 | 누르 | 보통 하렘은 집의 안주인들이 사는 곳입니다. |
| c026 | 누르 | 다만 궁정의 하렘은 쿤의 여인들뿐만 아니라 연고 없는 어린 소녀까지 데려와 키우기도 하기 때문에 훨씬 넓은 거지요. |
| c027 | 아시나 | 설마… 자라면 쿤이 첩 삼는 거야? |
| c027 | 누르 | 그런 경우도 있지만… |
| c027 | 누르 | 보통은 쿤께서 페시안 주요 인사들의 부인으로 보내십니다. |

선택한 플래그만 켜지고, `말함_ep08_c025`와 c025 방문은 ask에만 생긴다. home은 c025를 방문한 것으로 기록하지 않는다. 두 경로 모두 c057의 확인 선택과 원래 마지막 줄을 거쳐 `ep08_boundary`에 도달한다. 수치·난수·소지품 보존과 판정 없음도 기존 검증을 유지했다.

공개 시점은 Engine 관측으로 비교했다. c026의 scene과 첫 줄에는 `ep08_r07`이 없고 두 번째 설명 줄에서만 생긴다. c034의 scene에는 `ep08_r10`이 없고 “대재상… 아닐까요?” 줄에서만 생긴다. 이 순서는 두 선택에서 같다.

## 보존 및 검증

수정 직전 원문과 비교했을 때 YAML 전체의 차이는 `ep08_c024_home.next` 한 줄뿐이다. 다른 담당자가 완료한 atlas 라벨 13개를 포함한 atlas 전체, facts 3개, c034 전체는 동일했다.

JSON 직렬화 SHA-256도 수정 전후 같다.

- atlas: `57115fb3bb7678b6a76158134e0205a30d1240251ce0cd9b4df126c8d86b7c29`
- facts: `fb34af1d2d6cb5b053db5b48526c6cc7833da99e85e1e995941c4675a6f00de4`

| 실행 | 결과 | 근거 |
|---|---|---|
| 제품 수정 전 동일한 집중 시험 | 3 PASS / 1 FAIL, exit 1 | `work/continuation/qa/ep08-unasked-question64/red.log` |
| 연결 한 줄 수정 뒤 동일 시험 | 4 PASS / 0 FAIL, 61 expect, exit 0 | 같은 폴더 `green.log` |
| `tsc --noEmit` | exit 0 | 같은 폴더 `strict.log` |

집중 명령은 app에서 `bun test ./tests/ep08_harem.test.ts --timeout 20000`이다. red의 유일한 실패는 home 출력에 원하지 않은 c025 두 줄이 추가된 차이였다. ask는 수정 전후 통과했다.

YAML 언어 서버가 설치되지 않아 편집기 진단은 사용할 수 없었다. 실제 로더의 `checkScenario`와 strict 검사는 통과했다.

기존 facts 9개 회귀, 전체 시험, 모델, UI, 서버는 실행하지 않았다. 이 결과는 독립 8화 실제 엔진 경로의 검증이며 전체 캠페인 실주행이나 화면 인수를 뜻하지 않는다. 실제 UI 인수와 이번 요청의 검토 대기열 등록은 root 담당이다. title.ts와 core는 바꾸지 않았다.
