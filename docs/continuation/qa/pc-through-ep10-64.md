# 실제 PC 주행의 10화 도달 근거

2026-11-09. NO_LLM 분리 서버 18251과 에이전트 전용 Ego 공간 29에서 진행했다. 실제 새 게임 seed 2에서 시작했고 상태·수치·판정·응답을 주입하지 않았다. 자유 입력 의미 해석 대신 화면의 명시적 행동·선택·계속·행운 버튼을 사용했다.

## 정식 경로

| 구간 | 증거 | 관찰 |
|---|---|---|
| 1화 시작~2화 경계 | `ep02-first-ui.json` | 새 게임과 행동 8회 모두 HTTP 200, 감옥 기상은 1화로 표시, `continue_ep03` 도달 |
| 3~6화 | `ep03-06-first-ui.json` | 실제 계속·선택으로 `continue_ep07` 도달. 이 파일의 누적 원문에는 1~6화 scene 이벤트 304개가 있음 |
| 6화 정식 저장 | `saves/slot2.json` | `ep06_c065`, ended=false, 실제 획득 상태·화면·남은 큐 저장 |
| 7~10화 | `ep07-10-first-ui.json` | 슬롯2 정식 불러오기 HTTP 200. 복원된 session의 행동 14회 모두 HTTP 200, scene 이벤트 280개, `ep10_boundary`의 결과 화면 도달 |

증거의 공통 폴더는 `work/continuation/campaign-ui64/`다. scene 이벤트 수는 고유 원작 컷·완성 그림·검증한 분기 개수가 아니다. 화면 관찰에는 타자 출력 중간 표본도 있어 문장 개수로 세지 않는다.

중간에 한숨 캡처 보완을 위한 정식 지도 분기를 사용했다. 7~10화 정식 경로를 집계할 때는 슬롯2 불러오기 응답의 새 session으로 요청을 필터해 이 보완용 6화 재방문을 제외했다. 서로 다른 갈래의 결과를 한 경로로 합치지 않았다.

## 이번에 실제로 확인한 수정

- 미인계·미소녀 플래그가 없는 이 경로에서 원작·거리 `ep04_c058` 회상 scene은 전달되지 않았다. `ep04_wet_known`은 유지됐다.
- 6화 네 미확정 화자는 실제 이벤트의 display가 모두 빈 문자열이었다. 화면도 네 장면에서 이름표를 숨겼다.
- 최초 한숨 캡처는 3화의 같은 문구를 먼저 잡은 잘못된 이미지였다. 이를 제외하고 실제 획득 체크포인트 c15로 돌아가 보완했다. 확인 frame이 `ep06_한숨미확정 / ep06_cg_027 / 하아…` 이벤트와 일치함을 `sigh-correct-proof.json`에서 대조했다.
- 6화 계속 버튼과 대사창의 실제 겹침을 발견해 HTML·CSS 배치 원인에서 수정했다. 두 PC 폭과 실제 세 선택지의 독립 검수는 PASS다. 상세·남은 정적 경고는 `docs/continuation/qa/choice-overlap64.md`에 있다.
- 10화 결과의 긴 돌아보기는 스크롤된다. 오른쪽 버튼 묶음으로 스크롤하면 다시 하기·분기 맵·피드백·타이틀로가 모두 보인다. 최초 결과 캡처의 PARTIAL과 보충 캡처 PASS를 구분해 보존했다.

## 남은 계약

이것은 한 버튼 경로의 실제 PC 도달 증거다. 전체 분기, 괄호 자유 입력, 실제 GM 생성 대사, 새 그림의 독립 승인까지 통과한 결과가 아니다. 실제 모델 첫 정상 경로와 대사 감사는 `lead-normal-first-20261109.md`를 따른다.

서버 실행 뒤 소스에서 수정된 입력 충실성·문장 교열·사실 수명 계약을 이 구버전 NO_LLM 실행에 소급해 적용하지 않는다. 사실 수명의 새 소스 집중 회귀는 9/9 통과했지만 새 실제 모델 질문 품질은 별도다. 이미 통과한 정상 경로를 다시 광범위 실행하지 않았다.

10화 결과 본문에는 아직 `결과 · 1화 · 사막 조우`가 남는다. `summary.ts`가 캠페인의 원래 `scenario.episode`를 그대로 쓰는 원인을 확인했고 별도 수정 항목으로 남겼다. 현재 장면의 10화 표시와 결과 메타데이터를 혼동해 완료 처리하지 않는다.

검증 뒤 Ego 공간 29를 닫고 목록에서 제거됐음을 확인했다. 리드의 분리 서버 18251도 종료했다. 사용자 18080/18081은 변경하지 않았다.
