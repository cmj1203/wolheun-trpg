# 첫 실제 판 기록

실행: `bun tests/campaign_qa_main.ts --run --model-window-assigned`.

- 원점: `work/continuation/qa/real-1794202058383/origin.json`.
- 원시 기록: 같은 폴더 `canonical_first.jsonl`, `checkpoint-index.json`, `summary.json`.
- 종료 표식: `work/continuation/ep02/run/campaign-first-actual.log`.
- 실제 `newGame(b00_open, seed=913)`에서 시작했다. 상태·플래그·물건·난수·비트를 주입하지 않았다.
- 7회 행동 뒤 `b08_gaze`에서 입력 계획 3개를 소진했다. `CampaignQaError: 미준비 실제 입력: b08_gaze[3]`, exit 1. 실제 ending은 null이다.
- 모델 추적 11개, 전달된 생성 줄 15개, 실제 입력 경계 저장 8개다. 완주·독립 결말·UI 통과가 아니다.

## driver 설정 차이

첫 실행은 `Engine`의 `luckPrompt=false` 기본값을 사용했다. 사용자 서버는 `server/main.ts`에서 `Date.now, true`를 넘긴다. 경로의 `useLuck=true`와 별개로 첫 실행에는 행운 확인이 없었다. 이 차이는 driver 작성 실수이며 수정 대상이다.

원시 실행 파일과 저장을 수정하지 않는다. 첫 판은 행운 확인이 없는 실제 엔진 실행으로만 보존한다. 사용자 앱의 기본 설정으로 플레이했다고 세지 않는다. 수정 driver는 `Date.now, true`를 넘기고 이후 origin에 설정을 남긴다. 정상 설정의 대표판은 새 newGame에서 시작해야 한다.

## 실제 판정과 대가

| 행동 | 실제 기록 | 생성 서술 대조 |
|---|---|---|
| 3 · b05_why | plead, 매력 2 + 입력 1, 주사위 1·2, 합 6, miss; guard_grip | 칼을 거두지 않고 호위가 팔을 잡는 서술은 실패·대가와 맞는다. 성공 취소 사례가 아니다. |
| 4 · b06_swing | dodge, 근력 0, 주사위 4·2, 합 6, miss; guard_hold | 잘린 머리카락·상처 없음은 원래 dodge.miss.gist/lines에 있다. 호위가 팔을 꺾는 것은 실제 선택된 대가다. |

별도 연속성 결함: 행동3에서 이미 팔을 잡은 호위가 행동4의 생성9줄에서 “뒤에서 나타난 호위”로 새 등장처럼 서술된다. 기존 구속이 더 강해지는 동작과 잡힌 팔을 둔 채 회피하는 연결이 빠져 있다. 이를 회피 성공 취소나 근거 없는 새 호위 생성으로 분류하지 않는다. 누적 상태의 투영과 강화·지속 서술을 공유 담당이 검토한다.

## b08 정체

| 행동 | 실제 입력 | 실제 해석 |
|---|---|---|
| 5 | `(고개를 들고 붉은 눈을 똑바로 마주한다) 길을 잃었을 뿐이에요.` | person, target none. 이유: 단순한 부탁·눈맞춤은 새 성취 시도가 아니라고 판단. |
| 6 | `제가 무슨 잘못을 했는지부터 말해 주세요.` | person, target none. 이유: 질문·항의 발화. |
| 7 | `(눈을 피하지 않고 천천히 숨을 고른다)` | idle, target none. 이유: 현재 태도 유지. |

실제 마지막 저장은 talks=2, rolls=0, turns=0, nudged=true, 머뭇=1, 의심=8이다. 세 번째 입력은 새 판정을 만들지 않았다.

이 기록이 입증하는 중단은 준비 입력 소진이다. 실제 게임의 무한 반복을 입증한 결과는 아니다. 단순 호흡·idle의 무판정은 유지한다.

현재 장면의 `stare_back` 목표는 눈을 끝까지 피하지 않고 마주 보기, `retort`는 항의를 끝까지 전달하기이며 둘 다 성공 next가 b09_verdict다. 생성 응답은 호기심·흥미가 생긴 듯한 반응을 이미 내보냈지만 목표·전이는 반영되지 않았다. 일반적인 말/무시도 분류와 이 장면의 목표 완료 계약을 공유 담당이 대조해야 한다. 준비 문구만 늘려 완주로 덮지 않는다.

## 전달된 생성 줄 검수

행 번호는 원시 기록의 생성 line 순서다. 원문 전체를 읽었으며 고정 원작 줄·실제 판정과 대조했다.

| 줄 | 대조 결과 |
|---|---|
| 1 | 일주일 만에 사람을 만난다는 기간은 b01_sand 고정 줄과 b02 상황에 있다. |
| 2 | 사람 셋은 b02 상황에 명시돼 있다. |
| 3 | 불청객 비유. 새로운 사건·지식 주장 없음. |
| 4 | 말하기 시작하는 접속 서술. 후속 고정 대사와의 최종 편집 검수는 남음. |
| 5~7 | plead miss와 guard_grip 대가에 맞는다. |
| 8~11 | dodge miss의 머리카락·상처 없음 및 guard_hold 대가에 맞지만, 9줄의 호위 재등장 표현과 이미 붙잡힌 팔의 연결은 연속성 반려 사항이다. |
| 12 | 플레이어의 길 잃었다는 말에 대한 반문. |

| 14 | 플레이어의 항의에 대한 오만한 반응. 문법상 비문은 발견하지 못했다. |
| 15 | 항의가 흥미를 자극했다는 서술. 실제 목표 미반영 문제와 함께 반려 대상으로 남긴다. |

원시 모델 추적에는 어미 반복과 100자 초과의 soft 경고가 남아 있다. 이를 지운 통과로 세지 않는다. 모든 원시 해석·생성 후보 검수와 후속 정사 진행, 실제 UI/frame, 그림 승인은 별도 미완료다.

첫 기록의 GmTrace는 입력·원시 응답·검사·시간·모델 정보를 보관하지만 전체 system/user 프롬프트는 보관하지 않았다. 첫 판의 정확한 프롬프트까지 읽었다고 주장하지 않는다. 이후 driver는 실제 chatJson 요청 직전 전체 요청과 prefill system을 별도 기록하고 실행 코드 해시도 origin에 남긴다.
