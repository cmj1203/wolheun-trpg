# 대실패 구현 계약

사용자가 대성공 유지와 1·1 대실패 추가안을 승인했다.
새 판정은 원래 주사위 6·6이면 대성공, 1·1이면 대실패이고 나머지는 기존 합계 판정이다.
보정치가 이 두 특수 결과를 바꾸지 않는다. RNG 소비와 두 주사위는 그대로다.

## 판정과 결과

- `fumble`은 별도 Tier와 표시 이름 `대실패`를 갖는다. 성공 목표 효과·성취 기억·성공 preempt를 적용하지 않는다.
- 기존 데이터에는 miss가 필수다. fumble 결과 선언은 crit처럼 선택 사항이며 기존 대본과 옛 저장을 일괄 재작성하지 않는다.
- 명시 fumble이 없으면 기존 miss의 실패 내용·경로·선택된 비용을 유지하고, 실제 불리한 수치 변화 한 곳을 한 칸 더 나쁘게 한다.
- 기본 강화는 이미 선언된 불리한 변화에서 실제 적용 가능한 한 곳만 고른다. 수치가 바닥·상한이라 변화하지 않는 곳이나 잠긴 수치를 추가 불이익으로 선택하지 않는다. 그런 후보가 없으면 남은 정신력, 그다음 남은 체력에서 한 칸을 지불한다.
- 별도 즉사·강제 포획·정사 합류를 추가하지 않는다. 기존 자원 소진과 정상 실패 분기 규칙은 유지한다. 없는 인물·사건을 만들어 대실패를 꾸미지 않는다.
- 명시 fumble이 있으면 그 결과를 사용하며 기본 추가 한 칸을 중복 적용하지 않는다.
- 비용 표는 한 번만 선택·적용한다. 추가 불이익이 상태·변경 표시·GM 입력에 같은 값으로 전달돼야 한다.
- 기본 miss와 비용 적용 후 모든 후보가 실제로 포화됐고 정신력·체력도 0이면 추가 한 칸은 적용하지 않는다. 이것은 포화 상태의 명시적 예외다. 이미 0인 체력을 다시 깎아 포획 플래그를 새로 세우는 방식으로 추가 불이익을 위조하지 않는다. 기존 종료·전이만 유지하며 해당 포화 상태를 회귀로 입증한다.

## 행운과 저장

현재 실패를 행운으로 7점까지 메우는 선택은 대실패에도 유지한다.
행운 사용을 결정하기 전에는 대실패 효과를 적용하지 않는다.
사용하면 최종 mixed 결과만, 거절하거나 부족하면 fumble 결과만 적용한다.
현재 판정·효과·비용·RNG를 재굴림하거나 두 번 소비하지 않는다.

대실패 구제에 필요한 행운은 `max(1, 7 - 원래 합계)`다.
큰 양의 보정으로 합계가 이미 7 이상이어도 자연 1·1 구제에는 최소 1점을 쓴다.
0점 또는 음수 지불로 구제하거나 행운이 늘어나는 경우는 없다.
구제 후 합계는 `max(7, 원래 합계)`로 기록해 높은 원래 합계를 낮추지 않는다.
최종 결과는 mixed이며, 이때는 자연 대실패를 행운으로 구제한 사실을 기록·표시해
높은 합계의 일반 성공과 구별한다.

과거 check의 miss와 이미 저장된 결과는 새 규칙으로 소급 변경하지 않는다.
새 fumble은 정상 저장·재개·경계 계승·표시 관측에서 손실 없이 보존한다.
기존 4등급 저장은 계속 읽을 수 있어야 한다.

## 소유권과 검증

demo-slice가 types/dice/engine/scenario/save/gm 및 관련 핵심 회귀, ep01 규칙 안내를 소유한다.
리드는 web/introduction과 실제 PC 문구·결과 화면을 맡는다. branch-map의 frame 관련 코드는 건드리지 않는다.
타입이 준비되기 전 UI에서 cast/any로 임시 우회하지 않는다.

핵심 확인:

- 36개 주사위 조합과 큰 양·음 보정에서도 자연 6·6/1·1 특수 결과, 나머지 기존 합계 판정.
- 고정·즉흥 목표의 대실패에서 성공 효과 미적용, 실제 실패 내용과 추가 불이익.
- 명시 fumble과 기본 결과, 실제 수치 변화와 표시·GM 문맥 일치.
- 행운 사용/거절/부족, 저장·불러오기·질문 뒤 효과와 RNG 단일 적용.
- 무행동·호흡·단순 관찰에는 새 주사위를 굴리지 않음.
- 기존 성공·아슬아슬한 성공 경로와 사용자 서버를 보존함.

먼저 새 실패를 재현하고 필요한 범위만 회귀한다. 전체 과거 실패를 기대 완화로 없애지 않는다.
실제 화면과 모델 확인이 남았으면 구현 완료와 전체 QA 완료를 구분한다.

## PC 재현 준비

리드가 실제 캠페인을 로드해 newGame의 첫 입력 상태와 원래 RNG로 시드를 찾았다.
seed 75와 80은 둘 다 b02_people에서 첫 두 주사위가 1·1이다.
첫 run의 근력 보정 전 합계는 2다. 저장을 주입하거나 RNG를 고쳐 만든 상태가 아니다.
두 판으로 행운 거절과 사용을 나눠 주사위 카드·추가 불이익·구제 표시를 확인한다.
아직 준비 계산일 뿐 실제 HTTP/PC 화면 통과 결과는 아니다.

UI는 구제 출처를 원래 주사위 값에서 추측하지 않는다.
새 `RollResult.rescuedFrom === 'fumble'`일 때만 대실패 구제 안내를 표시한다.
그래야 예전 규칙에서 1·1 miss를 행운으로 바꾼 저장을 새 대실패로 오인하지 않는다.
리드의 main.ts 주사위 표시 편집은 끝났고, 이후 복원/큐 경계 수리는 branch-map 단독 소유다.
