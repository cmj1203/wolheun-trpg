**미해결 차이 28건: 확정 15건, 각색 검토 13건.** 같은 원인의 여러 위치는 한 문제로 묶었다. 검토에는 현재 정상 경로에서 나오지 않는 휴면 문구 1건(D04)이 포함된다. 확정은 원작과의 차이를 자료로 확인했다는 뜻이다. 창작 분기 전체를 금지한다는 뜻은 아니다. 새 글 536행에는 게임 규칙·도움말·분기 결과도 포함되므로 536행 전부가 오류는 아니다.

처음 제보된 **“그게…” 화자 오류는 감사 도중 52차 동시 작업에서 해결됐다.** 최종 추출본의 Y:961은 남자 “그게…”, Y:967도 남자 “그게… 마지막으로 남길 말인가?”다. 미해결 28건에는 이 항목을 넣지 않았다. 원작은 ep01_c055의 베히다트 발화다. 나머지 **직접 발화 → 속마음 변경 4건**은 S02–S05에 남아 있다.

귀찌 설명 시점도 바로잡아야 한다. 기존 메모는 글자를 지운 그림을 근거로 10화 c013→c014의 변신을 확인했으며, 더 이른 대사는 미확정이라고 적었다. 이번에는 **3화_008.json의 실제 대사 레이어**에서 본모습 은폐·갈색 머리와 눈으로 바뀌는 기능을 확인했다. **4화_003.json의 콘티**에는 일주일·휴식·망가짐 설명도 있다. 따라서 “원작에서 처음 설명되는 때가 10화”라고 쓰면 틀린다. 확인 가능한 앞선 기능 설명은 3화이고, 10화는 기존 조사에서 확인한 탈착·은발 변신 그림의 근거다.

## 범위와 판정 기준

- Y = `app/content/ep01_desert.yaml`, L = `app/content/lore_wolheun.yaml`, I = `app/web/introduction.ts`. 요청에 포함된 lore의 표시 글은 별도 L 파일에 있어 그 파일도 읽었다.
- 문장 단위가 아니라 **저장 위치별 문자열 1개를 1행**으로 세었다. 같은 말이 여러 판정 결과에 저장돼 있으면 각각 센다. 한 문자열에 말풍선 두 개를 합친 경우는 1행이다. Y:366의 빈 CG 전환 문자열은 발화가 아니어서 제외했다.
- **원작 그대로**: 글자 내용은 같고 공백·문장부호 모양·말풍선 합침만 다른 경우도 포함한다. 화자나 순서가 틀려도 글 자체는 이 분류다. 따라서 이 수치가 정상 대사 수를 뜻하지 않는다. “하.”·“……”처럼 짧은 공통 표현의 일치는 동일한 장면임을 입증하지 않으며, 이것만으로 순서 오류를 판단하지 않았다.
- **원작에서 조금 바뀜**: 확인한 원문을 축약·재배열·바꿔 쓰거나, 원문에 새 설명을 덧붙인 글이다. 정확한 뜻·말투 차이는 문제 표에서 따로 판정했다.
- **원작에 없는 새 글**: 1화 전사와 아래 후속 화 조사 자료에서 해당 글의 원문을 확인하지 못한 새 발화·서술·규칙 문구다. 원작 전체 10화의 모든 말풍선에 없다는 전면적인 부재 증명은 아니다. 그림을 새 문장으로 서술한 경우도 대사 전사에는 없는 새 글로 센다.
- 대상: 고정 발화 430행, prices.text 47행, game_help 답 18행, 운명·거절·정체·위험 징조(고정 발화에 포함), 소지품 설명 7행, 그만두기 확인 1행, 입력 안내·목표 16행, 갈림길 힌트 30행, 결말 제목·요약·다음 장면 안내 33행, lore 표시 글·대체 반응·GM 짧은 말 39행, 도입 안내 6행.
- prices는 엔진이 나레이션으로 내보내므로 그렇게 적었다. say/intro는 GM, text는 수첩, prompt/aim은 화면 안내로 표시했다. 이들은 YAML에 직접 화자 키가 있는 발화와 구분해 경로를 함께 남겼다.
- 사실·gist·situation·goal·must_not·검색어·인물 voice/samples 등 **모델 내부 지시**, 수치·효과·리소스 경로·장면 메타데이터·일반 버튼 라벨은 발화 전수 집계에 포함하지 않았다. 동적으로 생성되는 LLM 대사와 엔진 코드 안의 다른 고정 문구도 이 파일 범위의 감사 밖이다. 입력 예시는 엔진이 첫 예시를 힌트로 쓸 수 있지만 원작 인물의 고정 발화가 아니므로 대사 집계에서 제외했다.

## 잘못 세지 않은 항목과 확인 한계

1. **“그게…”의 다른 사용**: Y:619의 “하, 하하… 그게…”는 새 도주 실패 분기의 아시나 말이다. c055를 인용한 동일 장면이 아니므로 같은 단어가 있다는 이유만으로 남자에게 넘기면 안 된다. ep02_c037에도 실제로 아시나의 “그게…”가 있다. 글자 검색만으로 화자를 결정할 수 없다.
2. **이름·왕·페시안의 직접 노출**: Y의 대상 표시글에서 “베히다트”, “페시안”, “국왕/폐하/왕이다” 직접 노출은 0행이다. L:93의 페시안, L:99의 베히다트·왕은 hidden 지식이고 각각 flag:페시안_앎, flag:남자_정체_앎 조건이 있다. 현재 시나리오에는 그 플래그를 켜는 설정이 없다. 이를 즉시 보이는 스포일러로 집계하지 않았다. 다만 Y의 “적국”과 첩자 동기 공개는 별도 문제(M01–M02)다. 동적 LLM 응답 전체의 비밀 유지까지 실행 검증한 것은 아니다.
3. **후드 전환**: 미인계 접근법에는 before.flags.후드_벗음=true가 이미 있다(Y:726). 따라서 미인계에서도 반드시 b07까지 후드를 쓰고 있다고 단정하면 안 된다. 이후 우발적 후드 벗김에는 조건이 있다. 반대로 b07이 해당 플래그를 세운 뒤 b08에 도달하므로, !flag:후드_벗음을 요구하는 은발 대가 Y:1185는 정상 경로에서 선택되지 않는다(D04). 그림의 실제 표시 시점은 이번 텍스트 감사에서 화면 재생으로 검증하지 않았다.
4. **원작 화자와 표시 이름**: 게임의 속마음은 display가 아시나여도 style이 thought다(Y:45–47). UI가 같은 아시나 이름을 보여 주는 것과 원작의 소리 내는 발화를 보존하는 것은 다르다. 엔진의 lineEvent는 line.speaker를 cast에서 조회해 style을 그대로 전달하고, web/main.ts의 shownText는 thought에 괄호를 붙인다. 따라서 S02–S05는 표시 이름 문제가 아니라 고정 글의 화자 키 문제다. 읽은 근거: app/src/engine/engine.ts의 lineEvent, app/web/main.ts:231. 각 줄의 원작 cut/kind를 함께 보존하지 않으면 문자열 자체가 같은 이 오류들을 놓치기 쉽다. 이것은 현재 데이터 구조에서 확인한 재발 경로이며 과거 작성자의 의도까지 추정한 결론은 아니다.
5. **말투**: 새 베히다트 줄 전부를 말투 오류로 처리하지 않았다. 예를 들어 “지루하군.”, “다리는 평민이군.”, “겁은 없군. 머리는 없고.”는 원작 원문은 아니지만 짧은 반말·냉소라는 형식에는 맞는다. 원문 근거 없이 말투 위반이라고 확정하지 않았다. 호의로 확정하는 서술(T03), 장황한 훈계(T04), 거래·선행을 추가한 동기(B03–B04)는 별도로 구분했다.
6. **원본 조사 범위**: assets/ep01/cuts.json의 cuts[].dialogue를 컷 배열·order 순서로 읽었다. 139항목 중 본문 내레이션·대사·속마음은 134개, 타이틀·크레딧은 5개다. assets/ep01/ep01_script.md의 말풍선 전사와 컷 설명을 대조했으며, 거기 적힌 “TRPG 전환 제안”은 원작 대사로 쓰지 않았다. docs/ep02/ep02_script.md도 확인했다.
7. **후속 화**: work/ep_survey의 2–5화 JSON 56개에서 콘티 경로 레이어 621개를 찾았다. 3화는 콘티가 아니라 대사 경로에 실제 type 레이어가 있어서 대사 경로까지 넓혔고, 두 경로의 조사 후보는 1,047개였다(그래픽·그룹 이름도 포함하므로 대사 개수는 아니다). 관련 원문 근거 18개를 부록 C에 남겼다. PSD 레이어 이름에는 연출 메모도 섞이므로 말풍선·속마음의 구분을 확인할 수 없는 후속 화는 “문맥”이라고 표시했다. 6–9화 전체 대사 전사와 10화 그림은 이번 감사에서 새로 판독하지 않았다. 10화 근거는 docs/lead_check40/earring_first_mention.md의 기존 기록이며, 그 기록이 말한 최초 그림 근거와 최초 대사 설명을 구분했다.
8. **동시 수정·검증**: 추출 중 52차의 스크립트 조건·화자 수정이 들어와 최종 추출본으로 모든 위치와 집계를 다시 연결했다. 그 과정에서 이미 해결된 S01을 분리했다. 앱·assets 수정, 커밋, 서버 접속·재시작, 18080/18081 사용, 앱 테스트 실행은 하지 않았다. 이 산출물의 검증은 정적 추출의 누락·줄 위치·문제 참조·집계 일치 확인이다.
