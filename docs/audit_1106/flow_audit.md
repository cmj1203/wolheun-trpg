## 실행과 검증 범위

- 지정한 YAML·엔진·비트 형식·분기 문서를 읽고, 입력 해석과 fallback을 위해 gm.ts, rules.ts, text.ts, scenario.ts, lore 및 불러오기 호출부를 추가 대조했다.
- app/src·app/content·컷 JSON을 `/tmp/flow_audit/`로 복사하고 복사본만 실행했다. 서버·모델·네트워크와 금지 포트를 쓰지 않았다.
- YAML 스냅샷 SHA-256: `e54325dea05a4414f150d36f285fc4c6ee49780594dbd7badd33d13e511ded4e`.
- 30개 비트, 자유 입력 지점 8개, 접근법 27개. 명시적인 choices는 0개여서 접근법 단추를 선택 입력으로 검증했다.
- checkScenario 결과 오류 0개. 정식 next 경로 8개 전부 열거·관찰. 정적 유효성 검사는 위 의미 모순을 잡지 못한다.
- 시작 시드는 `seedFrom("audit-0")`부터 `seedFrom("audit-191")`까지 192개. 각 시드에서 접근법 조합을 모두 분기했다. 총 56,800회 act 처리, 버튼 접근법 hit/mixed/miss/crit 108칸의 누락은 0이다.
- 별도 probe 168개: 직접 접근 108, 즉흥 32, 종료 확인/종료 16, 소지품 경계 2, 지도 기회 5, 결말 resume 4, attack 해석 1.
- 직접 접근·즉흥 등급 probe는 실제 도달 상태를 복제한 뒤 다음 RNG만 바꾼 독립 검증이다. 재개 probe도 실제 결말 상태의 조건을 재구성한 API 검증이다. 이를 b00부터의 시작 시드 재현과 구분했다.
- 추가 직접 입력 5사례: 신분+소지품 복합, 신분 부정, 미모 발화 거부, 지도 대신 핀, 물 기회 수락. 핀 사례 자체는 별도 결함으로 세지 않았다.
- 대화·혼잣말·세계 밖 행동 반복은 최대 8회, idle은 최대 2회 관찰했다. 질문으로 자원 변화 없이 머무는 것은 의도된 대기이며 next의 무한 루프가 아니다.
- 행운 질문은 비활성화했다. 온라인 LLM 의미 분류·행운 창·실제 UI 클릭·소리·그림은 검증하지 않았다. 새 문제의 온라인 LLM 재현 여부가 필요한 곳은 fallback/경계 검증이라고 표시했다.
- 저장소에는 이 감사 폴더의 문서만 추가했다. 앱 수정·에셋 수정·커밋은 하지 않았다.

현재 임시 폴더가 유지되는 동안의 재현 명령:

```sh
cd /tmp/flow_audit
WOLHEUN_NO_LLM=1 bun audit.mjs
WOLHEUN_NO_LLM=1 bun probes.mjs
```

임시 파일이 없어져도 `evidence.md`에 시작 시드·앞선 입력·자원 전후·실제 대사가 남고, `input_matrix.md`에 입력별 다음 줄이 남는다. 이 문서는 결함 보고서이며 앱 수정 완료 보고가 아니다.
