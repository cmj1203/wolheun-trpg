# 인물 말투·설정 감사: ep01 사막 (2026-11-05)

대상: `app/content/ep01_desert.yaml`(대본, 줄 앞 `ep`)과 `app/content/lore_wolheun.yaml`(인물 설정, 줄 앞 `lore`). 브랜치 `cloud/snapshot-1105` 기준.
**이 문서는 글을 하나도 고치지 않는다.** 모든 줄은 안이고, 화면·게임에 나오는 글이라 사용자 승인 뒤에 고친다.

## 어떻게 봤나

- 대본에서 화자별로 줄을 모두 뽑았다: 나레이션 186, 남자 95, 속마음 71, 아시나 66, GM 1(cast 정의뿐). 호위는 cast 가 없어 `호위|복면|검은 머리|세 사람|셋 중|일행` 이 나오는 57줄을 따로 뽑았다.
- 1차 감사: 하위 에이전트 넷이 나눠 봤다. ① 베히다트(남자) ② 호위 ③ 아시나 겉말·속마음 ④ 나레이션·아는 정보.
- 2차 반증: 다른 하위 에이전트 둘이 1차 후보를 하나씩 뒤집어 보려 했다. 줄 번호와 인용을 다시 대조하고, 엔진 코드를 읽고, LLM 없이(`LocalGm(null)`) 엔진을 돌려 재현했다.
- 3차 직접 검토: 금지 어미·금지어 기계 검사, 핵심 재현 다시 돌리기, 대본 전체 직접 읽기를 했다. 여기서 새 문제 1건(B-04 641)을 찾았고, 2차 판정 1건(e_spy "묶어라")을 기각으로 뒤집었다.
- 원작 웹툰 줄(`lore` samples·basis, `docs/cg_lines.md` 의 c0xx)과 이미 승인된 변경(`docs/script_changes.md`)은 기준으로 삼고, 문제로 올리지 않았다.

화면에 나오는 칸과 아닌 칸(엔진 코드에서 확인):
- 화면에 나오는 칸: `lines`, `prices[].text`, `offer.lines`, `nudge`, `press`, `talk_fallback`, `deflect`, `improv.lines`, `fates.warn`, `refuse`, `identity.omen`, `callbacks`.
  - `prices[].text` 는 `sayPrice`(engine.ts 1039)가 화자 `나레이션` 줄로 내보낸다. 그래서 나레이션 규칙을 그대로 적용했다.
- 화면에 나오지 않는 칸: `gist`·`situation`·`goal`·`must_not`·`facts` 는 GM 지시문이다. `free.prompt` 는 입력칸 안내(UI)이고, 엔딩 `summary`·`next_hook` 은 결과 카드(UI)다. 이 칸들은 3인칭이어도 위반이 아니다.

심각도:
- **높음**: 설정을 정면으로 어기거나, 흔한 경로에서 앞뒤가 깨진다.
- **중간**: 설정과 어긋나지만 경로가 좁거나, GM 이 따라 쓸 본보기가 된다.
- **낮음**: 다듬기.

판정:
- **확인**: 재현했거나, 코드·조건으로 반드시 나온다.
- **그럴 법함**: 읽기에 따라 다르다.

    - 속마음에 존대 어미가 쓰인 곳(1826)
    - 속마음이 방금 한 말과 어긋나는 곳(849, 641)
