# 플레이어 입력 분류 평가 — 규칙 경로(--no-llm)

2026-11-05 · 브랜치 기준 `cloud/snapshot-1105` · src 는 고치지 않았다.

## 무엇을 쟀나

- **자료**: `docs/research/input_corpus.jsonl` 222줄. 한 줄이 입력 하나이고 `kind`(종류), `scene`(장면), `expect`(받아들일 처리), `note` 를 단다.
- **경로**: `--no-llm` 으로 띄웠을 때와 같은 `LocalGm(null, lore)` 를 실제 `Engine` 에 물려, 이야기 입력칸에 글을 넣는 `act({type:'free'})` 를 그대로 부른다. 엔진 앞단(그만두기 확인, 질문+행동 나누기, 되돌림 검사, `addressed`, 위험 관문)까지 다 지난 뒤 화면에 무엇이 나왔는지로 처리를 가른다.
- **장면 둘**: 갈래 3(seed 1) 입력으로 닿는 두 자유 입력 자리.
  - `alone` = `b02_people`(곁에 아무도 없고 멀리 세 사람이 보인다. `addressed: run`)
  - `facing` = `b05_why`(칼 든 남자 앞)
- **스크립트**: `app/scripts/input_eval.ts`
  ```sh
  cd app
  bun scripts/input_eval.ts          # 요약 + 틀린 입력 표
  bun scripts/input_eval.ts --all    # 모든 입력 표
  ```
  같은 자료로 두 번 돌려 출력이 글자까지 같음을 확인했다(판정 주사위가 갈려도 처리 이름은 같다).
- **문서에 없는 표현인지**: 스크립트가 `docs/`, `app/`, `app_next/` 의 md·txt·yaml·ts·json·jsonl 을 한글·숫자만 남겨 이어 붙이고, 입력 전체가 그 안에 들어 있는지 본다. 처음 210개 중 6개가 걸려(예: "저장은 어떻게 해?", "왜 하필 나야") 다른 말로 바꿨고, 지금은 0개다. 입력 전체가 그대로 들어 있는지만 보므로 비슷한 말까지 막지는 못한다.
- **재지 않은 것**: LLM 경로(모델이 저장소에 없다). 이 표는 모델이 없거나 실패했을 때 쓰이는 규칙 해석만 보여 준다. 질문 모드(GM 단추, `act({type:'ask'})`)도 재지 않았다.

### 종류와 기대 처리

| 종류 | 뜻 | 기대 처리 |
|---|---|---|
| 행동 | 아시나가 몸으로 하는 일 | 판정(굴리기 전 의도 확인 카드도 같은 길로 본다) |
| 건넨말 | 등장인물에게 소리 내어 한 말 | facing: 대꾸 또는 말 판정 / alone: 판정(`engine.ts` `addressed()` 주석 "사람이 멀리 있는 장면에서 그 사람에게 건넨 말은 다가가 말을 거는 판정이다") |
| 혼잣말 | 아무에게도 건네지 않고 답도 바라지 않는 말 | 혼잣말(`talk` `to: 'self'`. 화면은 "말은 사막 바람에 흩어졌다." 쪽) |
| 게임질문 | 규칙·화면·진행을 묻는 말 | 질문안내(이야기에 넣지 않고 GM 단추로 안내. `engine.ts` "이야기 입력칸에 적은 질문은 여우가 받지 않는다") |
| 세계밖 | ① 플레이어의 현실·게임 바깥 잡담 ② 이 세계에 없는 물건·힘을 쓰려는 입력 | ① 질문안내(`prompt.ts` "이야기 속 세계의 것도 아닌 말(현실의 일, 게임 바깥 잡담)도 game 으로 둔다") ② 세계밖(`improv` `absurd`) |

## 원인 후보

줄 번호는 `cloud/snapshot-1105` 기준이다.

### 1. 규칙 해석의 출력에 혼잣말·게임 질문·세계 밖 잡담이 없다 (대꾸로 간 틀림 99건)

`src/gm/rules.ts` 의 `RuleReading` 은 `approach | talk | ask(why) | deflect | improv` 다섯뿐이고, `talk` 에는 누구에게 한 말인지(`to`)가 없다. `gm.ts` `byRule` 은 이를 `{ kind: 'talk' }` 로 넘기고, 엔진은 `self = read.to === 'self'`(`engine.ts` `freeInputText`)로 보므로 `to` 가 없으면 앞사람에게 한 말로 받는다. 그래서 혼잣말 42건 중 37건, 게임질문 45건 중 44건, 잡담 20건 중 15건이 '대꾸'다. 규칙이 "모르겠다"를 낼 자리가 없어 모르는 입력이 모두 건넨 말이 된다. `risk` 도 규칙 경로에서는 귀찌·정체 낱말로만 붙고 `attack` 은 나오지 않는다.

### 2. 게임 질문이 질문으로 잡히는 길이 수첩 낱말에 묶여 있다 (게임질문 45건 전부)

규칙의 `ask` 는 `isLoreQuestion` 이 참일 때만 나온다(`ASK_WORDS` 의 "뭐야/누구야/알려 줘…" 와 수첩 항목 낱말이나 "여기·저 남자"가 함께 있어야 함). 게임 항목 이름(`gameHelp`)은 `askByRule` 안에서만 보므로, `ask` 가 먼저 나오지 않으면 거기 닿지 못한다. 물음표로 끝나는 문장은 `QUESTION` 정규식에 걸려 `talk` 가 된다. "집착 수치가 뭐야?"처럼 `ASK_WORDS` 에 맞아도 수첩 낱말이 없으면 질문이 아니다. 엔진도 이야기 입력칸에서는 `isQuestionText` 로 질문을 다시 보지 않는다(끼어들기 경로 `engine.ts` 947줄에만 있다).

### 3. 혼자 있는 장면의 건넨 말이 `addressed` 에 닿지 못한다 (건넨말 alone 10건 전부)

`addressed()` 는 `read.to !== 'person'` 이면 그대로 돌려준다. 규칙의 `talk` 는 `to` 가 없으니 `run` 접근(다가가 말 걸기 판정)으로 바뀌지 않고, 대꾸 대체 줄 "대답은 돌아오지 않았다."가 나온다. 같은 엔진 안에서 `to` 가 없는 말을 talk 처리는 '사람에게 한 말'로, `addressed` 는 '모르는 말'로 다르게 읽는다.

### 4. "~다"로 끝나면 행동으로 본다 (틀림 8건)

`rules.ts` 의 `ACTION_ENDING = /[가-힣]+다[.!…~]*$/` 는 형용사·서술격 끝("싫다", "좋다", "미쳤다", "최악이다", "익겠다", "본 거다")도 행동으로 보아 즉흥 판정을 굴린다: `self-a10`, `self-a16`, `self-a18`, `self-f15`, `out-a02`, `out-a09`, `out-f01`, `out-f10`. 같은 저장소의 `text.ts` `isActionText`(현재형 "-ㄴ다/-는다"와 "-할게")로 이 자료를 재 보면 행동 50/50을 그대로 잡고 위 8건과 `per-f20` "당신 얼굴 무섭게 생겼다"(지금도 대꾸로 맞았지만 ACTION_ENDING 에는 걸린다)를 모두 뺀다. 규칙 해석과 엔진이 행동을 가르는 기준이 둘이다.

### 5. 낱말 맞춤이 띄어쓰기를 지우고 낱말 속까지 맞춘다 (틀림 4건, 맞음 속 접근 오류 2건)

`validate.ts` `mentions` 는 원문 포함 또는 공백을 지운 포함으로 본다. 그래서

- `per-f13` "뒤에 계신 분들은…" → 공백을 지우면 "계**신분**들" → `noble`
- `game-a20` "**불러**오기 하면…" → `run`
- `out-f07` "시청자들이 **인사**하래" → `noble`
- `per-f29`, `mod-f01` "…**보여**요?", "노트북을… **보여** 준다" → `bag`
- `self-f11` "신이시여, 한 번만 **살려** 주세요" → `plead`(신에게 한 말이 남자 앞 애원 판정이 된다)

점수 1(낱말 하나)만으로 접근법이 정해지고, 물음 꼴이거나 대상이 다른 문장이어도 그 점수를 그대로 쓴다. 소지품 접근만 `ITEM_RULE_MIN_SCORE = 2` 로 문턱이 있다.

### 6. 세계 밖 물건은 목록에 있는 것만 알아본다 (세계밖 물건 15건 중 10건 틀림)

`lore.forbidden.modern` 에 있는 휴대폰·택시·편의점·총·카메라는 `improv absurd` 로 맞게 갔다. 목록에 없는 드론·선글라스·GPS·오토바이·노트북·라이터·이어폰은 평범한 즉흥 판정으로, 112·와이파이·비트코인을 꺼낸 말은 대꾸로 갔다. 목록 방식으로는 끝이 없다(이 문서는 목록을 늘리는 안을 내지 않는다).

## 고칠 방향(단어 목록을 늘리지 않는 것만)

src 는 고치지 않았다. 아래는 다음 차수에서 고를 후보다.

1. **규칙이 '모름'을 낼 수 있게 한다.** 행동 꼴도 접근 낱말도 아니면 `talk` 대신 '모름'을 내고, 엔진은 모름을 대꾸로 넣지 말고 이미 있는 의도 확인 카드로 "남자에게 하는 말 / 혼잣말 / 여우에게 묻기"를 고르게 한다(원인 1·2·3을 같이 덮는다). 카드가 나오는 횟수가 늘어나는 비용은 이 자료로 셀 수 있다(지금 기준 대꾸 145건 중 행동·접근이 아닌 것 전부).
2. **`to` 가 없는 `talk` 의 뜻을 엔진 한 곳에서 정한다.** 지금은 talk 처리와 `addressed` 가 서로 다르게 읽는다(원인 3).
3. **행동 판단을 `text.ts` `isActionText` 하나로 맞춘다.** 이 자료에서는 행동을 잃지 않고 틀림 8건이 빠진다(원인 4). 다만 세계밖 물건 행동 12건도 행동으로 남으니 원인 6은 그대로다.
4. **낱말 하나만 맞은 접근법은 문장 꼴로 한 번 더 거른다.** 공백 지운 맞춤은 공백 없이 쓴 입력을 위한 것이니 어절 경계를 넘는 맞춤(원인 5의 "계신 분")만 막고, 점수 1 + 물음 꼴이면 접근법 대신 1번의 확인으로 보낸다. `ITEM_RULE_MIN_SCORE` 처럼 문턱을 두는 방식이다.
5. **세계 밖 물건·잡담은 규칙 경로에서 맞히려 하지 않는다.** LLM 경로의 `absurd`·`game other` 에 맡기고, 규칙 경로는 1번의 확인 카드로 받는다. LLM 경로를 이 자료로 재는 것이 다음 일이다(아래).

## 이 자료의 한계

- 기대 처리는 이 저장소의 주석·프롬프트에 적힌 설계를 따라 내가 붙였다. 특히 '세계밖 잡담 → 질문안내'와 'alone 건넨 말 → 판정'은 설계 문장을 근거로 했지만 사용자 확인을 받지 않았다.
- 한 사람이 쓴 문장이라 말투가 쏠린다. 처음엔 게임 질문이 모두 반말+물음표, 남자에게 한 물음이 거의 존댓말이어서, 반말 물음 5개(`per-fq`)·존댓말 게임 질문 5개(`game-q`)·물음 꼴 혼잣말 2개를 더했다. 그래도 "물음표+반말 = 게임 질문" 같은 구분은 이 자료에서 실제보다 좋아 보일 수 있다(지금 반말 물음 중 게임질문 39, 건넨말 5, 혼잣말 2).
- 장면은 두 곳(b02, b05)뿐이다. 소지품·수첩이 열린 정도, 장면 플래그가 달라지는 뒤 장면은 재지 않았다.
- LLM 경로는 재지 않았다. 스크립트의 `evaluate()` 는 `LocalGm` 을 감싸므로 `LocalGm(new LlmClient(...), lore)` 로 바꾸면 같은 자료로 잴 수 있다(모델이 있는 맥에서).
