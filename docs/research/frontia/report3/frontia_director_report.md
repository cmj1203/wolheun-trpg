# 프론티아 상세 분석 — 디렉터

조사 기준: 2026-11-10  
대상: 자사 웹툰 IP로 인터랙티브 스토리를 제작하려는 기획자·디렉터·제작사  
관점: 제작 도구, 이야기 제어, 제작비와 운영, 권리, 수익화, 월흔 적용  
문서 상태: 제작 화면·공식 가이드·약관 관찰과 분석. 실제 작품 발행·수익 정산을 수행한 결과는 아니다.

## 1. 결론

**프론티아는 캐릭터 대화에 그림을 붙이는 도구보다, 고정 연출과 AI 자유 진행을 결합하는 스토리 제작·배포 플랫폼에 가깝다.** 디렉터는 원작의 중요한 장면을 직접 연출하고, 그 사이에서 플레이어와 AI가 대화·행동을 만든다. 다음 장면으로 넘어가는 조건, 상태값, 캐릭터 이미지와 미디어를 같은 편집기에서 다룬다. [D1][D2]

**월흔의 레퍼런스로는 적합하지만, 정식 원작 IP를 바로 공개하는 것은 권하지 않는다.** 제작 방식은 배울 점이 많다. 그러나 공개 콘텐츠의 번역·각색·재라이선스 권한, 다른 회원의 서비스 내 2차 창작 허락, AI 원가 차감 뒤 정산이라는 조건은 원작 사업자가 별도로 판단해야 한다. “저작권이 우리에게 남는다”는 설명만으로 충분하지 않다. [T1][T2]

권고 순서는 다음과 같다.

1. 현재 확보한 도구·가이드·플레이 관찰을 월흔의 설계 검토에 사용한다.
2. 플랫폼 도입 시험이 필요하면 권리 관계가 단순한 별도 소재로 비공개 검증한다.
3. 원작 공개 전 회사의 계약·권리 담당자가 라이선스, 해외 배포, 철회 범위와 비용 내역을 확인한다.
4. 이야기 품질뿐 아니라 완주율·재방문·사용자 지출·운영 대응을 확인한 뒤 사업성을 판단한다.

이 순서는 본 리포트의 판단이다. 현재 계정에 새 작품을 공개하거나 시험을 추가로 실행하라는 지시는 아니다.

## 2. 무엇을 만드는 서비스인가

| 구분 | 확인한 구조 | 디렉터에게 의미 |
|---|---|---|
| 에피소드 | 세계관·캐릭터·프롤로그·미디어·이벤트를 묶은 플레이 작품 | 배포 단위는 대화용 캐릭터 한 명이 아니라 하나의 이야기다. |
| 드라마 | 프레임을 한 장씩 넘기는 연출 | 배경·입식·대사를 함께 조절하는 비주얼 노벨식 표현과 맞는다. |
| 노벨 | 스크롤하며 읽는 표현 | 긴 서술과 배경 포함 이미지를 활용하기 쉽다. |
| 소울 | 에피소드 캐릭터와 구분되는 1:1 채팅용 등록 | 에피소드 진행과 관계형 캐릭터 채팅을 별도 제품면으로 다룬다. |
| 스튜디오 | 에피소드·소울·참고·가이드 | 제작, 예제 학습, 운영을 한곳에 둔다. |
| 수익창출 | 별도 자격 신청·승인 절차 | 작품 발행 가능 여부와 정산 자격은 다르다. |

조사자는 PC 웹에 로그인해 스튜디오 편집 화면을 열고, 공식 가이드와 공개 작품·디렉터 프로필을 읽었다. 앱 내부 제작·정산 대시보드는 확인하지 않았다. [D1]

### 사업·경쟁 관점

운영사는 딥그로브다. 투자사 카카오벤처스의 2026년 7월 1일 발표는 본엔젤스와의 15억 원 시드 투자를 확인해 준다. 같은 자료는 인터랙티브 AI 스토리 게임과 제작 엔진을 함께 강조한다. 투자 유치와 서비스의 이익·현금흐름·장기 존속은 별개의 사실이다. 이용자 수·매출·디렉터 수익 분포를 검증할 운영 데이터는 확보하지 못했다. [B1]

캐릭터 채팅 서비스와 비교할 때 프론티아의 차이는 **그림의 존재 자체보다, 고정 장면·미디어·이벤트 트리거·상태값을 제작 도구로 묶고 작품 단위로 배포한다는 구성**에 있다. 제타·크랙·베이비챗·로판AI 등 개별 서비스의 최신 제작·정산 정책을 동일 조건으로 실험하지는 않았다. 경쟁사마다 다른 가입자 수·재화·정산 비율을 한 표에 놓고 우열을 계산하지 않았다. 외부 노트의 경쟁사 조사는 추가 탐색용이며 도입 판단의 확정 근거로 쓰지 않는다.

### 기본 편집 흐름

`에피소드 종류 선택 → 초안 자동 생성 → 세계관·캐릭터·미디어 → 프롤로그 → AI·연출·발행 설정 → 선택적 고급 설계 → 발행`

편집기는 자동 저장한다. 새 제작 화면 진입이 단순 미리보기가 아니라 계정에 초안을 만드는 동작이었다. 조사 중 생긴 비공개 초안 1개는 삭제하지 않았다. [D1]

발행의 필수 요소는 세계관·프롤로그·기본 정보다. 이벤트나 많은 캐릭터 없이 시작할 수 있다. 반대로 완성도 높은 분기를 갖추려면 디렉터가 별도로 구조를 설계해야 한다. **쉽게 발행할 수 있다는 것과 게임이 충분히 설계됐다는 것은 별개다.** [D2]

## 3. 이야기 제어 구조

### 3.1 고정 장면과 자유 진행을 나눈다

공식 가이드가 설명하는 반복 구조는 다음과 같다. [D2]

```text
디렉터가 작성한 현재 이벤트의 연출 씬
                 ↓
AI 자유 진행 — 진행 가이드가 방향을 제한
                 ↓
다음 이벤트의 트리거 충족
                 ↓
다음 이벤트의 고정 연출 씬
```

| 층 | 담당 | 적합한 내용 |
|---|---|---|
| 연출 씬 | 디렉터가 작성한 장면 | 원작의 첫 만남, 중요한 대사, 정체 공개, 컷신, 결말 |
| 진행 가이드 | 자유 진행의 방향 | 지금 인물이 원하는 것, 이 장면에서 가능한 행동, 숨겨야 할 정보 |
| 트리거 | 다음 사건으로 넘어갈 조건 | 관찰 가능한 행동·장소·시간·상태 변화 |
| 이벤트 프롬프트 | 해당 이벤트의 세계관 프롬프트 대체 | 장면에 맞는 집중 규칙. 기존 세계관에 단순 추가되는 설정으로 착각하면 안 된다. |

이 방식의 장점은 원작의 뼈대와 플레이어 자유 행동을 분리한다는 점이다. 약점은 **트리거의 자연어 해석이 장면 진행의 정확성에 영향을 준다**는 점이다. 가이드는 AI가 대화에서 관찰할 수 있게 조건을 쓰라고 안내한다. 임의의 코드 조건식이나 엄격한 상태 머신을 제공한다고 확인한 것은 아니다. [D3]

월흔에서는 “플레이어가 충분히 친해지면”보다 “플레이어가 부탁을 수락했고 목적지에 도착한 뒤”처럼 판별 가능한 조건이 낫다. 다만 원작상 반드시 보존해야 하는 분기 조건까지 모델의 자연어 판단에 전적으로 맡기는 것은 별도 문제다.

### 3.2 선택지는 행동의 전부가 아니다

직접 작성하는 선택지는 최대 3개다. 공식 가이드는 이를 제안으로 다루며, 자유 입력과 알아서 진행을 함께 제공한다. 고정 연출의 선택지를 비우면 AI가 그 자리를 자동으로 채워 주는 것으로 가정해서는 안 된다. [D1]

이 구조에서 좋은 선택지는 허용 행동을 모두 나열하는 메뉴보다 현재 상황을 이해시키는 예시다. 플레이어가 예시 밖의 행동을 했을 때 인물·세계·상태가 반응해야 자유 입력의 가치가 생긴다.

### 3.3 상태값·키워드북은 서로 다른 장치다

| 장치 | 확인한 역할·제약 | 오해하면 안 되는 점 |
|---|---|---|
| 주인공 상태 | 최대 5개. 시간은 기본 내장. 숫자·문자·시간 등 | UI가 있다는 것만으로 계산과 값 보존이 항상 정확하다고 단정할 수 없다. |
| 캐릭터 상태 | 최대 3개. 관계 등 추적 | 표면적 호감도 변화가 실제 장면 반응·분기에 연결되는지 시험해야 한다. |
| 상태 출력 규칙 | 항목당 최대 300자, 시작값 최대 30자 | AI가 읽고 갱신하는 규칙이다. 단순 데이터베이스 필드와 다르다. |
| 표시 제어 | 플레이어에게 보이기·숨기기, 상단 고정 | 내부 추적 여부와 화면 공개 여부를 나눌 수 있다. |
| 키워드북 | 20항목, 활성화 단어 항목당 5개, 동시에 최대 3항목 | 플레이 중 새 사건을 자동 기록하는 기억장치가 아니라 작성해 둔 설정을 공급한다. |
| 키워드 우선순위 | 목록 상단 우선 | 너무 흔한 단어를 쓰면 필요한 설정보다 다른 항목이 들어갈 수 있다. |
| 대화 기억·요약 | 내부 구현 미확인 | 별도 편집 메뉴를 못 찾았다고 기억 기능이 없다는 뜻은 아니다. |

근거: 편집 화면, 공식 상태값·키워드북 가이드. [D4][D5]

**권고:** 월흔은 원작 설정, 현재 상태, 이번 플레이에서 실제 일어난 사건을 별도로 관리해야 한다. 키워드로 설정을 꺼내는 것만으로 “누가 누구의 볼을 꼬집었고 누가 봤는가”를 대체할 수 없다.

### 3.4 주사위는 규칙책 자체가 아니다

주사위 범위는 설정할 수 있지만, 값이 나왔다는 것만으로 판정이 끝나지 않는다. 세계관이나 진행 가이드에 자연어 판정 규칙을 함께 적는 방식이다. [D6]

따라서 주사위 UI가 있다는 이유로 CoC 규칙, 성공 단계, 강행, 행운 소비, 무행동 시 미판정까지 구현돼 있다고 보면 안 된다. 월흔은 자기 규칙의 조건과 적용 결과를 별도로 검증해야 한다.

## 4. 제작 항목과 제약

아래는 2026-11-10 편집 화면과 가이드 기준이다. 기능·한도는 이후 바뀔 수 있다. [D1]

| 항목 | 확인한 한도·동작 | 제작 영향 |
|---|---|---|
| 세계관 | 3,000자 | 원작 설정 전체를 넣기보다 공통 규칙과 현재 필요한 정보를 분리해야 한다. |
| 캐릭터 | 에피소드당 최대 100명, 이름 12자, 프로필 전체 합산 3,200자 | 등장인물이 많아질수록 핵심 성격·관계·말투를 압축해야 한다. |
| 캐릭터 이미지 | 감정 20 × 상황 20, 칸당 최대 10장 | 표정·복장·상황별 차분을 구조적으로 관리할 수 있다. 등록 가능량이 실제 필요한 제작량은 아니다. |
| 이미지 변환 | 업로드 시 WebP·2048px 변환 안내 | 원본 보존·선화·투명 가장자리 검수가 별도로 필요하다. |
| 배경·상황 에셋 | AI 사용 항목 표시 0/150, 이미지 20MB 이하 | 원작 컷과 장면의 대응을 관리하기 위한 이름 체계가 중요하다. |
| 오디오 | 30MB 이하, 에셋별 BGM·효과음 연결 | 제작 도구와 별개로 음원 이용권이 필요하다. |
| 비디오 | 500MB 이하, 설명 100자 | 오프닝·컷신은 외부 제작 후 올리는 자산이다. |
| 프롤로그 | 1~5개, 연출 씬 최대 4,000자 | 첫 장면의 인물·상황·행동 동기를 고정 연출로 전달할 수 있다. |
| 이벤트 연결 | 다음 이벤트 최대 10개 연결 | 노드 연결 수가 실제 완성한 의미 있는 갈래 수는 아니다. |
| 진행 가이드 | 500자 | 장면의 목적과 경계를 짧고 구체적으로 써야 한다. |
| 이벤트 프롬프트 | 3,000자, 최대 100개 | 공통 규칙의 누락·충돌을 관리해야 한다. |
| 디렉터 주인공 | 최대 5명, 소개·AI 전달 특징 각 200자 | 고정 원작 주인공도 준비할 수 있다. |
| 발행 정보 | 제목 2~20자, 소개 500자, 썸네일 1~10장, 장르 1~3개, 태그 1~10개 | 발견·클릭·기대 형성에 영향을 주는 별도 편집물이다. |
| 공개 범위 | 전체 공개·링크 공개·나만 보기 | 전체 공개만 목록·검색·랭킹 노출의 대상이다. |

가이드의 고정 연출은 한 줄을 한 프레임으로 쓰고, 배경·미디어·캐릭터 이름을 참조하는 문법을 제공한다. 이것은 연출 작성 인터페이스이지 플랫폼의 소스 코드 공개가 아니다.

### AI·미디어 도구

이미지·영상·음악 생성기를 스튜디오 내부에서 직접 실행하는 기능은 조사 범위에서 찾지 못했다. 공식 가이드는 ChatGPT·Suno 같은 외부 도구를 안내한다. 배경 제거는 유료 기능으로 안내됐으나 실제 실행·과금은 시험하지 않았다. “못 찾았다”를 서비스 전체에 영구히 없다는 뜻으로 쓰지는 않는다. [D1]

프롬프트 불러오기는 제목 20자, 프롬프트 최대 7,000자, 선택 프롤로그 4,000자 입력 화면을 확인했다. 초안 변환은 실행하지 않았으므로 변환 품질·비용·분기 자동 구성 능력은 평가하지 않는다.

## 5. 제작과 업데이트 운영

### 상위 디렉터 표본

랭킹·공개 프로필에서 고른 사례이지 무작위 표본이나 성공 공식은 아니다. [D1]

| 디렉터 | 조사 시 작품·팔로워 | 관찰한 운영 방식 | 읽어낼 수 있는 것 |
|---|---|---|---|
| roro | 13작품·2,152팔로워 | 연애 리얼리티 연작, 8인 등장, 대표작 V93 표시, OST 연결·공지 게시 | 캐릭터 관계와 반복 운영을 제품으로 만든 사례다. |
| 매듭달스물사흘 | 22작품·985팔로워 | 학원·무협 등 세계관, 권장 모델·외부 도움말, 텔로스 V8·18인 소개 | 작품 외부의 안내·연속 세계관도 운영 자산이다. |
| 키르히호프 | 1작품·154팔로워 | 심연 V33·30인, 콘테스트 수상 게시, 영상 관련 댓글 | 영상이 진입 관심을 만들 수 있으나 재미·유지는 따로 확인해야 한다. |

거대한 누적 UI 숫자를 독자 수·사용자 수·매출로 바꾸지 않았다. 버전 번호도 수정 횟수의 단서일 뿐, 버전마다 완전히 새로운 이야기가 추가됐다는 증거는 아니다.

### 버전의 비용

재발행하면 버전이 오르고 업데이트 알림을 보낼 수 있다. 진행 중인 플레이는 플레이어가 버전을 업데이트해야 새 버전이 반영되는 구조다. 캐릭터 이름은 첫 발행 뒤 변경할 수 없다는 가이드 제한도 있다. [D1][D2]

따라서 디렉터는 “새 콘텐츠 제작”뿐 아니라 다음 운영 부담을 가진다.

- 인물·에셋 이름의 초기 확정과 참조 일관성.
- 이전 버전의 진행 상태와 새 규칙 사이의 호환성.
- 어떤 문제를 고쳤고 기존 플레이가 어떻게 영향받는지 설명.
- 모델·요금·정책 변경 뒤 같은 작품이 어떻게 달라지는지 확인.

## 6. 수익화: 매출 55%가 아니다

### 자격과 지급을 나눠 읽어야 한다

| 단계 | 확인한 조건·시점 |
|---|---|
| 신청 요건 | 현재 전체 공개 에피소드 3개 이상, 본인 플레이 제외 누적 30,000턴 이상, 팔로워 100명 이상 |
| 승인 | 운영팀 심사. 조건 달성 즉시 자동 정산이 아니다. |
| 정산 대상 | 자격 승인일 이후 발생분. 승인 전·심사 대기 중 수익은 소급되지 않는다. |
| 배분 기준 | `(해당 에피소드 매출 − 제반비용) × 55%` |
| 제반비용 | AI 생성 비용·서버 비용 등. 본 조사에서 단가별 실제 계산 내역은 확인하지 못했다. |
| 적립 산정 | 매월 25일에 전월분을 집계해 정산 재화 산정 |
| 현금 출금 | 최소 100,000정산 재화. 말일까지 신청한 건을 익월 25일 지급 |
| 스타 전환 | 최소 1,000정산 재화, 1:1 무료 스타 전환. 되돌릴 수 없다. |
| 유효기간·세금 | 정산 재화 5년. 비사업자 3.3% 원천징수, 사업자 세금계산서 규정 |
| 비율 변경 | 최소 30일 전 통지, 기존 적립분에는 소급하지 않는 조항 |

근거: 수익 페이지, 공식 파트너 가이드, 수익창출 약관 제2~6조. [D7][T2]

**단순 산식 예시:** 에피소드 매출 100,000원, 차감 비용 60,000원이면 디렉터 적립 기준액은 22,000원이다. 이는 계산 설명용 가정이며 실제 원가·예상 수익·세후 입금액이 아니다.

플레이어가 비싼 모델을 쓰면 매출과 AI 원가가 함께 달라질 수 있다. “한 턴 가격이 높다 → 디렉터 수익률도 높다”는 결론을 내릴 수 없다. 무료·보너스 스타와 소울 채팅이 어떤 정산 항목에 포함되는지도 확인되지 않았다.

### 추가로 확인할 계약 조건

제11조는 참여 중 알게 된 비공개 정보에 대한 기밀유지 의무다. 이 조항만으로 모든 원가가 반드시 비공개라고 단정하지 않았다. 공개 자료에서는 원가 검증에 필요한 상세 산식을 확보하지 못했다.

제12조 제4항은 약관 변경에 동의하지 않아 프로그램에서 탈퇴할 때 기적립 정산 재화 미지급을 규정한다. 정책 위반·자격 박탈의 적립 보류·취소 조건과 함께 계약 담당자가 검토할 항목이다. 조항의 법적 유효성에 대한 판단은 하지 않는다. [T2]

## 8. 공식 디스코드의 제작자 기능

디스코드는 제작 노하우, 에셋, 작품 홍보, 장애 신고, 기능 건의를 분리한 운영 공간이다. 아래 채널 구조는 직접 확인했고, 세부 관찰·읽은 범위는 동봉한 `discord_notes.md`를 기준으로 한다.

| 구역 | 채널 | 디렉터가 얻는 정보 |
|---|---|---|
| Welcome | welcome·rules·start-here | 참여 규칙과 시작 경로 |
| Information | news-한국어·notes-한국어 | 행사·정책·기능 변경·패치 |
| Studio | tips·assets·promote 포럼 | 제작 방법, 재사용 자산, 작품 발표 |
| Support | bug-report·suggestions 포럼 | 장애·기능 부족·운영진 답변 |
| Lounges | 한국어·global 등 | 작품·모델·가격에 대한 이용자 대화 |

내 판단은 **공지 → 가이드 → 운영진 답변 → 일반 사용자 경험** 순으로 근거의 성격을 구분해서 읽어야 한다는 것이다. 건의가 많다는 사실은 기능이 구현됐다는 뜻이 아니고, 운영진의 예고도 출시와 같지 않다. 일부 활성 이용자의 글로 전체 디렉터 만족도를 추정하지 않는다.
