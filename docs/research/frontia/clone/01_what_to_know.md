# 프론티아 모작 — 알아야 할 것 (제품·기술·사업 복제 분석)

작성: 2026-11-11  
목적: 프론티아와 같은 성격의 인터랙티브 AI 스토리 플랫폼을 자사(투니온)에서 새로 만들기 위해 필요한 정보 정리  
근거: 기존 조사 `docs/research/frontia/report3/frontia_director_report.md`, `frontia_player_report.md`, 조사 노트(player/director/discord/external), `source-verification.md`, `frontia_study.md`(11-06 4작품 62턴 플레이). 공식 가이드·약관·화면 관찰 기반이며, 내부 소스·서버·정산 대시보드는 확인하지 않았다.  
용어: 이 문서에서 "확인"은 화면·공식 문서에서 직접 본 것, "추정"은 관찰로부터의 합리적 유추, "미확인"은 근거를 못 잡은 것이다. 모작 설계 시 추정·미확인을 확정 사실로 쓰면 안 된다.

## 0. 한 줄 정의와 복제 난이도

프론티아는 **캐릭터 1:1 챗봇이 아니라, "디렉터가 고정 연출 장면을 짜고 그 사이를 AI 자유 진행으로 메우는" 인터랙티브 스토리를 제작·배포·수익화하는 플랫폼**이다. 복제 대상은 크게 네 덩어리다.

| 덩어리 | 복제 난이도 | 왜 |
|---|---|---|
| 플레이어 앱(뷰어·발견·결제) | 중 | 표준 앱/웹 기능. 비주얼 노벨식 뷰어 + 랭킹/검색 + 스타 과금. |
| 스토리 엔진(고정 연출+AI 자유진행+트리거) | 상 | 프론티아의 핵심 차별점. 자연어 트리거·상태값·기억의 신뢰성이 품질을 가른다. |
| 디렉터 스튜디오(제작 도구) | 상 | 세계관·캐릭터·이미지 20×20·이벤트 그래프·상태값·키워드북 편집기. UI/데이터 모델이 방대. |
| 크리에이터 이코노미(정산 55%·자격·비용차감) | 중상 | 규칙 자체는 단순하나 AI 원가 정산·세무·출금이 운영 부담. |

**핵심 판단:** 뷰어와 과금은 평범하다. 모작의 승부처는 (1) 스토리 엔진의 신뢰성(기억·트리거·세계관 보존)과 (2) 크리에이터를 끌어올 이코노미다. 이 둘이 프론티아의 실제 약점이기도 하다(→ 리포트 2).

## 1. 제품 구조 — 무엇을 만들어야 하는가

| 제품면 | 확인한 역할 | 모작 시 구현 포인트 |
|---|---|---|
| 에피소드 | 세계관+캐릭터+프롤로그+미디어+이벤트를 묶은 플레이 작품. 배포 단위. | 배포 단위는 "캐릭터"가 아니라 "이야기". 데이터 모델의 루트 엔티티. |
| 드라마 | 프레임을 한 장씩 넘기는 비주얼 노벨식 연출 뷰 | 배경+입식+대사 동시 전환 렌더러. |
| 노벨 | 스크롤하며 읽는 뷰 | 같은 데이터, 표현만 다른 뷰어. 분기 엔진은 동일. |
| 소울 | 에피소드와 분리된 1:1 캐릭터 채팅 등록 | 관계형 챗은 별도 제품면. MVP에서 후순위 가능. |
| 스튜디오 | 에피소드·소울·참고(예제)·가이드 | 제작+학습+운영 허브. |
| 수익창출 | 자격 신청·승인·정산 | 발행 가능 여부와 정산 자격은 별개 절차. |

조사자는 PC 웹 스튜디오 편집 화면·공식 가이드·공개 작품/디렉터 프로필을 봤고, 앱 내부 제작·정산 대시보드는 미확인.

### 플레이어 측 화면 흐름(확인)

`홈·검색·태그·랭킹 → 에피소드 상세(기대 형성) → 프롤로그 → 선택/자유입력 → AI 생성 → 장면 전환·이벤트 → 기록·상태·이어하기`

- 홈: 드라마/노벨 입구, 검색·태그, 랭킹·NEW·요즘 인기·장르별, 최근기록·프로필·알림.
- 상세: 인물·세계관·권장 모델·업데이트·미리보기·댓글·디렉터 글.
- 추천 알고리즘 개인화 방식은 미확인.

## 2. 스토리 엔진 — 핵심 복제 대상

공식 가이드가 설명하는 반복 루프(확인):

```text
디렉터가 쓴 현재 이벤트의 고정 연출 씬
        ↓
AI 자유 진행 (진행 가이드가 방향 제한)
        ↓
다음 이벤트 트리거 충족
        ↓
다음 이벤트의 고정 연출 씬
```

| 층 | 담당 | 모작 구현 메모 |
|---|---|---|
| 연출 씬 | 디렉터 작성 고정 장면 | 원작 첫만남·중요대사·정체공개·컷신·결말. 한 줄=한 프레임 문법, 배경/미디어/캐릭터 이름 참조. |
| 진행 가이드 | 자유 진행 방향 제한(500자) | "지금 인물이 원하는 것, 가능한 행동, 숨길 정보". 짧고 구체적인 시스템 프롬프트. |
| 트리거 | 다음 사건 조건 | **자연어로 작성, AI가 대화에서 관찰해 판정**. 코드 조건식·엄격한 상태머신은 확인 안 됨(→ 약점). |
| 이벤트 프롬프트 | 해당 이벤트의 세계관 프롬프트 "대체"(3,000자, 최대 100개) | 세계관에 단순 추가가 아니라 교체. 10-27 공지: 지정 프롬프트는 다음 턴부터 적용. |

- **선택지**: 디렉터가 직접 쓰는 건 최대 3개. 공식은 "제안"으로 다루고 자유 입력 + 알아서 진행을 함께 제공. 선택지를 비우면 AI가 자동으로 채운다고 단정 금지(미확인).
- **주사위**: 범위 설정 가능. 단, 값이 나와도 판정은 세계관/진행 가이드의 자연어 규칙으로 처리. CoC식 규칙 엔진이 내장됐다고 볼 근거 없음.

**모작 설계 함의:** 엔진의 두 축은 (a) 디렉터가 짜는 노드 그래프(이벤트 연결, 최대 10개 다음 노드)와 (b) 노드 안 자유 진행 LLM. 트리거 판정과 상태 갱신을 "자연어 LLM 판정"에만 맡길지, 아니면 판별 가능한 구조화 조건을 병행할지가 모작의 핵심 설계 결정(프론티아는 전자에 가깝고 그게 약점).

### 상태 추적 시스템(확인)

| 장치 | 역할·제약 |
|---|---|
| 주인공 상태 | 최대 5개. 시간 기본 내장. 숫자·문자·시간 타입. |
| 캐릭터 상태 | 최대 3개. 관계 등. |
| 상태 출력 규칙 | 항목당 최대 300자, 시작값 최대 30자. **AI가 읽고 갱신하는 규칙**(단순 DB 필드와 다름). |
| 표시 제어 | 플레이어에 보이기/숨기기, 상단 고정. 내부추적과 화면공개 분리. |
| 키워드북 | 20항목, 활성화 단어 항목당 5개, 동시 최대 3항목. **작성해 둔 설정을 공급**(플레이 중 자동 기록 아님). |
| 키워드 우선순위 | 목록 상단 우선. |
| 대화 기억·요약 | 내부 구현 미확인. |

**모작 함의:** 상태값이 "AI가 자연어로 읽고 갱신"하는 구조라 숫자 보존·계산 정확성이 보장되지 않는다(프론티아의 약점). 모작은 상태값을 결정적(deterministic) 저장소로 두고 LLM에는 읽기/제안만 맡기는 설계가 차별점이 된다.

### 제작 흐름(확인)

`종류 선택 → 초안 자동 생성 → 세계관·캐릭터·미디어 → 프롤로그 → AI·연출·발행 설정 → (선택)고급 설계 → 발행`

- 자동 저장. 제작 화면 진입 자체가 계정에 초안 생성.
- 발행 필수요소: 세계관·프롤로그·기본정보. 이벤트/다수 캐릭터 없이도 발행 가능 → "발행 쉬움 ≠ 게임 설계 충분".
- 캐릭터 이름은 첫 발행 후 변경 불가(가이드 제한).
- 프롬프트 불러오기: 제목 20자 + 프롬프트 최대 7,000자 + 선택 프롤로그 4,000자로 초안 변환(변환 품질·비용 미시험).

## 4. 모델·요금 체계 — 수익 구조의 뼈대

### 모델 가격(공식 일반 안내, 확인)

스타 = 플랫폼 재화. 응답 1회(=AI가 다음 이야기를 한 번 이어 씀)당 소모.

| 모델 표시명 | 스타/응답 1회 |
|---|---:|
| 윙스 | 10 |
| 스파크 | 20 |
| 플레어·글로우·노바·오로라 | 각 60 |
| 세이지·샤이닝 | 각 72 |
| 오라클·스텔라 | 각 160 |

- 품질 순위가 아니라 가격표. 실제 서버 라우팅/버전은 미확인(편집기 표시 모델명만 봄).
- 충전 상품(웹): 5,000·10,000·30,000·50,000·100,000스타 = 같은 숫자의 원화. 즉 **1스타=1원**(웹 표시가). 앱 가격·실제 승인액은 미시험.
- 무료 스타: 오늘의스타·업적·초대·가입선물·리뷰·이벤트. 받은 날부터 30일. 유료 스타와 조건 동일 가정 금지.
- 환불: 웹은 프론티아 문의(미사용 유료스타, 결제 7일 이내), 앱은 Apple/Google.

### 차감 규칙(확인)

대사 입력·선택지·알아서 진행·다시 생성 = 각각 AI 1회 생성 = 과금. 되돌아가 다른 선택 재생성도 과금. 생성 실패 시 미차감 안내(정합성 직접 시험 안 함).

**비용 단위 함정(모작 UX에 중요):** 생성된 1응답이 여러 서술/대사 화면으로 나뉜다. "화면 넘김 ≠ 새 생성". "알아서 진행"은 글을 안 쓸 뿐 새 생성이라 과금. 모작은 이 단위를 플레이어에게 명확히 보여야 요금 불만을 줄인다(→ 프론티아는 이게 불만 요인).

### 부가 과금(확인)

유저 노트 500자 초과 저장 시 **장면마다 20스타 추가**(11-06 디스코드 패치, 웹 선적용). "모델 무료라도 부가비 0 아님".

## 5. 수익화·정산 — 크리에이터 이코노미 설계

### 정산 공식(확인)

`(해당 에피소드 매출 − 제반비용) × 55%` → 디렉터 적립. **"매출의 55%"가 아니라 "순수익의 55%"**.

| 항목 | 조건 |
|---|---|
| 신청 요건 | 전체공개 에피소드 3개+ / 본인 제외 누적 30,000턴+ / 팔로워 100명+ |
| 승인 | 운영팀 심사. 조건 달성 즉시 자동 아님. |
| 정산 대상 | 승인일 이후 발생분만(소급 없음) |
| 제반비용 | AI 생성비·서버비 등. **단가별 실제 계산 내역 미확인**. |
| 집계 | 매월 25일 전월분 집계 |
| 출금 | 최소 100,000 정산재화, 익월 25일 지급 |
| 스타 전환 | 최소 1,000, 1:1 무료 전환, 되돌릴 수 없음 |
| 유효기간·세금 | 정산재화 5년. 비사업자 3.3% 원천징수, 사업자 세금계산서 |
| 비율 변경 | 최소 30일 전 통지, 기적립분 비소급 |

예시(설명용 가정): 매출 100,000 − 비용 60,000 = 40,000 × 55% = 22,000. 실제 원가·세후 입금액 아님.

**모작 함의:** 진입 장벽(3작품/3만턴/100팔로워 + 심사)이 높아 신규 디렉터가 수익까지 도달하기 어렵다(→ 약점/기회). AI 원가 차감이 불투명해 디렉터가 실수령을 예측 못 한다(→ 약점). 모작은 투명 정산·낮은 진입장벽으로 크리에이터를 유인할 수 있다.

## 6. 기술 스택 — 확인/추정 구분

| 영역 | 확인 | 추정 | 미확인 |
|---|---|---|---|
| LLM | 편집기에 10종 모델명 표시, 작품별 기본/권장 모델 선택 | 다중 LLM 벤더 라우팅(이름이 브랜드 가명). 응답당 과금은 토큰 기반 원가에 마진 | 실제 벤더·모델 버전·라우팅·토큰 한도 |
| 이미지 | 업로드 시 WebP·2048px 변환 | CDN + 이미지 파이프라인(리사이즈/포맷). 배경제거 유료 기능 | 내부 이미지 생성툴 유무 |
| 이미지 생성 | 스튜디오 내부 생성기 **못 찾음**. 공식 가이드가 ChatGPT·Suno 등 외부 도구 안내 | 제작은 외부 생성 의존 → 자산 업로드형 | "영구히 없음"은 아님 |
| 상태·기억 | 상태값 UI, 키워드북. 내부 요약/검색 구현 미확인 | 프롬프트에 상태+키워드 주입형. 결정적 상태 저장은 약함 | 대화 기억·요약·RAG 구조 |
| 미디어 | 오디오 30MB/비디오 500MB 업로드 | 외부 제작 자산 업로드형(플랫폼 내 영상/음악 생성 아님) | — |
| 플랫폼 | PC 웹 + iOS/Android 앱, 공식 디스코드 | 웹/앱 공용 백엔드, 웹↔앱 동기화 | 동기화 전체 시나리오 |

**모작 기술 결정 체크리스트:**
1. LLM: 자체 모델? 멀티벤더 라우팅? 응답당 원가·마진 모델 설계.
2. 상태/기억: 결정적 상태 저장 + LLM 제안 갱신 하이브리드로 프론티아 약점 보완.
3. 이미지: 내부 생성기 제공할지(프론티아는 외부 의존 → 차별점). WebP/CDN 파이프라인.
4. 에디터: 이벤트 그래프 + 상태값 + 20×20 이미지 매트릭스 편집기가 가장 무거운 프론트 작업.
5. 과금: 스타형 선불 재화 + 응답당 차감 + 생성 단위 투명 표시.

## 7. 운영사·투자·시장 위치(확인)

- 운영사: 딥그로브. 2026-07-01 카카오벤처스 발표 — 본엔젤스와 15억 원 시드 투자. "인터랙티브 AI 스토리 게임 + 제작 엔진" 강조. (투자 유치 ≠ 이익·현금흐름·존속)
- 이용자 수·매출·디렉터 수익 분포 등 운영 데이터는 미확보.
- 경쟁: 제타·크랙·베이비챗·로판AI 등 캐릭터 챗 서비스. 프론티아 차이는 "그림 존재"가 아니라 "고정연출+미디어+트리거+상태값을 제작도구로 묶어 작품 단위 배포". 경쟁사 최신 정책은 동일 조건 비교 안 함.
- 콘텐츠 편중: 11-10 여성 인기 랭킹 20편 중 19편이 연애/로맨스, 9편 성인표시(여성 필터 표본, 전체 통계 아님).

## 8. 모작 MVP 제안(본 리포트의 판단)

프론티아 전체를 1:1로 복제하기 전, 최소 검증 세트:

1. **뷰어 + 엔진 코어**: 드라마 뷰(배경+입식+대사) + 노드 그래프(고정 연출 → 자유 진행 → 트리거 → 다음 노드).
2. **제작 에디터 축소판**: 세계관·캐릭터(이미지 소수)·프롤로그·이벤트 연결·진행 가이드·트리거. 20×20 이미지 매트릭스와 소울은 후순위.
3. **상태 시스템(차별화)**: 결정적 상태 저장 + LLM 읽기/제안. 프론티아의 "자연어 상태 갱신" 약점을 처음부터 피함.
4. **과금**: 선불 스타형 재화 + 응답당 차감 + 생성단위 명시.
5. **크리에이터 정산(차별화)**: 낮은 진입장벽 + 투명 원가/정산 대시보드.
6. 발견/랭킹/소울/부가과금은 2차.

소울(1:1 챗), 영상 업로드, 배경제거 유료, 멀티마켓 랭킹은 MVP 이후.
