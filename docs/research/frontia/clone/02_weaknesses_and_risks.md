# 프론티아 모작 — 취약점·차별화 기회·리스크

작성: 2026-11-11  
목적: 프론티아를 모작할 때 (1) 더 잘 만들 수 있는 약점, (2) 피해야 할 사업·법적 리스크 정리  
근거: `frontia_director_report.md`, `frontia_player_report.md`, 조사 노트(discord/external/source-verification), 앱스토어 리뷰 재집계(250건), 공식 디스코드 회수분(공지 11·패치 3·포럼 본문 70).  
용어 주의: 여기서 "취약점"은 **제품·사업·UX의 약점과 경쟁 공략점**이다. 보안 침투·시스템 공격을 뜻하지 않으며, 그런 조사는 하지 않았다. 아래 수치는 자발적/부분 표본이라 발생률·전체 여론이 아니다.

## 1. 요약 — 모작이 노릴 7개 공략점

## 2. 스토리 엔진·AI 품질 약점

### 2.1 기억(가장 중요한 약점)

실제 플레이에서 확인한 것: 7~13턴 전 행동을 **질문했을 때** 구체적으로 회상(볼 꼬집기·오리 울음 3번 등). 재접속 3턴에서도 일부 회상.
확인 못 한 것: **질문 단서 없이 자발적으로** 과거를 꺼내는 능력, 장기/재접속에서의 정확한 보존. 재접속 시 화면 속마음·기록에 과거가 이미 노출돼 있어 "숨은 장기기억"만으로 답했다는 증거 아님. 11-10 재접속에서 물건의 목적 누락·행동 순서 오류도 관찰.

구분해야 할 4능력(모작 설계 축): ①연속성 ②질문 회상 ③자발적 활용 ④장기·재접속 보존. 프론티아는 ①②는 보이고 ③④는 미입증.

**모작 기회:** 사건을 결정적 로그(누가/무엇을/언제/목격자)로 저장하고 관련 상황에서 주입하면 ③④를 구조적으로 보강할 수 있다. 프론티아는 "키워드북=설정 공급"이라 플레이 중 사건 자동기록 장치가 아님 → 여기가 빈 자리.

### 2.2 트리거·상태값의 자연어 의존

- 트리거가 자연어로 쓰여 AI가 관찰·판정 → 장면 진행 정확성이 모델 해석에 흔들림. 코드 조건식·엄격한 상태머신 미확인.
- 상태값이 "AI가 읽고 갱신하는 규칙" → 숫자 계산·값 보존 정확성 미보장.
- **모작 기회:** 반드시 보존할 분기·수치는 결정적 로직으로, 그 외 뉘앙스만 LLM에. "UI가 있다 ≠ 정확히 동작".

### 2.3 세계관 밖 입력 실체화

스마트폰·배달앱 입력이 무협/학원/탐사 세계에 실제 기물로 등장하고 신고·소문으로 연결됨. 범용 놀이엔 재미지만 **IP 기반 작품엔 원작 붕괴 위험**.
**모작 기회(특히 자사 웹툰 IP용):** 세계 밖 입력은 인물이 성격대로 받아치되 확정 사실·소지품·수치를 바꾸지 않는 "세계 보존형 자유도". 자유도를 "입력을 무조건 사실화"가 아니라 "세계 지키며 의도·크기에 맞게 반응"으로 정의.

## 3. 요금·과금 약점 (플레이어 이탈 요인)

- **생성 단위 혼동:** 1응답이 여러 화면으로 분할 → "화면 넘김"과 "새 생성"을 플레이어가 헷갈림. "알아서 진행"도 과금. 요금 체감 악화.
- **부가비:** 유저 노트 500자 초과 저장 시 장면당 20스타 추가. "모델 무료"라도 총액 0 아님.
- **무료 행사 의존:** 11-06 62턴 플레이는 무료 스파크 행사 조건. Spark 무료는 11-14까지 특별 이벤트(운영진 답변), 영구 무료 아님. 행사 종료 후 과금 체감이 올라갈 구조.
- **앱스토어 리뷰 재집계(250건, 10-08~11-08):** 5점 217 / 4점 17 / 3점 9 / 2점 3 / 1점 4. 가격 키워드(스타/비싸/가격/과금/현질/충전) 23건 — 단, 긍정 언급 포함이라 "불만 23건"으로 읽으면 안 됨. 3점 이하 16건 중 가격 키워드 5건 → "저평점 대부분 가격 불만"은 이 집계로 미지지. 몰입/자유전개 칭찬 + 무료보상 확대 요구가 함께 나오는 패턴.

**모작 기회:** 생성 단위를 UI로 명확히(이 버튼이 N스타 소모), 부가비 최소화, 무료→유료 전환을 완만히, 번들/구독으로 체감 예측성 제공.

## 4. 수익화·크리에이터 이코노미 약점

- **진입장벽:** 정산 신청 = 전체공개 3작품 + 본인 제외 30,000턴 + 팔로워 100 + 심사. 신규 디렉터가 수익 도달까지 멀다.
- **원가 불투명:** 정산은 (매출−제반비용)×55%인데 AI·서버 원가의 단가별 계산 내역 미공개. 디렉터가 실수령 예측 불가. 기밀유지(제11조)로 원가 상세 비공개 성향.
- **탈퇴 시 미지급:** 약관 변경 비동의 탈퇴 시 기적립 정산재화 미지급 조항(제12조4항). 자격 박탈 시 적립 보류/취소도 계약 검토 대상.
- **구독 부재:** 10-22 멤버십 건의에 운영진 "현재 일회성 구매만" 답. 예측 가능한 월 비용 상품 없음.

**모작 기회:** 낮은 진입장벽, 실시간 원가/정산 대시보드, 명확한 탈퇴/정산 보장, 구독·패스 상품. 크리에이터 유인은 플랫폼 초기 성장의 핵심이고 프론티아가 약한 지점.

## 5. 운영·기술 약점

- **버전 업데이트 부담:** 재발행 시 버전 상승, 진행 중 플레이어는 수동 업데이트 필요. 캐릭터 이름 첫 발행 후 변경 불가 → 초기 확정 실수 복구 어려움.
- **재발행 회귀:** 11-01 패치(미등록 주인공 의상/상황을 AI가 써서 이미지 사라짐)는 기존 공개작 재발행 필요. "패치 = 전작 해결"은 아님. 플랫폼 패치와 작품별 회귀가 분리됨.
- **이미지/화면 버그 이력:** 버그 포럼 18스레드 표본 중 화면·기기·이미지·스크롤 주제 7개(6-26~11-07, 발생률 아님). 이미지 생성이 외부 도구 의존이라 일관성 관리가 디렉터 몫.
- **스튜디오 개편 빈번:** 11-04 미디어/캐릭터 일괄변경·이벤트맵·편집·미리보기 통합 등 개편 → 제작 도구 운영 부담이 실재했다는 방증.

**모작 기회:** 버전 호환성·회귀 테스트 자동화, 이름/참조 리팩터 지원, 내부 이미지 생성·일관성 도구.

## 6. 법적·IP 리스크 (모작 자체의 리스크)

이건 프론티아의 약점이 아니라 **투니온이 모작할 때 스스로 감수·회피할 리스크**다. 법률 의견이 아니며 계약·법무 담당 검토 필요.

### 6.1 모작의 경계 (일반 원칙)

- **아이디어·기능은 저작권 대상이 아니지만, 구체적 표현은 보호된다.** 인터랙티브 스토리 플랫폼이라는 컨셉, 고정연출+자유진행 구조, 스타 과금 같은 기능 아이디어를 구현하는 것은 일반적으로 가능. 그러나 프론티아의 UI 화면·아이콘·문구·가이드 텍스트·약관 문장·코드·캐릭터/작품 등 **구체적 표현을 복사하면 안 된다**.
- 상표(서비스명·로고·"디렉터"같은 고유 브랜드 용어), 데이터베이스권, 부정경쟁방지(형태 모방)도 별개 리스크.
- 프론티아 작품/디렉터의 콘텐츠를 긁어와 자사 학습·전시에 쓰면 저작권·약관 위반 소지. 조사도 읽기만 했고 콘텐츠 수집은 안 함.

### 6.2 자사 웹툰 IP를 올릴 때(프론티아든 자사 플랫폼이든)

프론티아 약관에서 확인된, 원작 사업자가 반드시 검토할 쟁점:
- 회사 이용 허락: 운영·개선·홍보 목적 **비독점·전세계·무상·양도·재라이선스 가능** 이용 허락.
- 공개 콘텐츠 **번역·각색·더빙·포맷변환·제휴마켓 배포** 권한.
- 다른 회원의 서비스 내 2차 창작 허락 포함.
- 탈퇴 후에도 이미 이용 중인 공개 생성물·번역 배포물 예외(즉시 전량 회수 불가 가능성).
- AI 생성물은 유사 결과 가능·독점 저작권 불성립 가능 조항.
- "범용 모델 학습엔 안 씀" ≠ "외부 AI 전송 없음"(품질개선 분석·생성 목적 외부 전송은 별개).

→ 자사 플랫폼을 만들면 이 약관을 **우리가 설계**하므로, 창작자 친화적(권리 보장·명확한 철회·학습 미사용)으로 짜는 것 자체가 차별점이자 리스크 회피.

### 6.3 데이터·AI 원가

- 멀티 LLM 벤더 의존 시 벤더 약관·단가 변동·가용성 리스크. 응답당 원가가 마진을 좌우.
- 성인 콘텐츠·연령 확인·개인정보(실명/결제) 규제 준수 필요. 프론티아도 11-13부터 민감 콘텐츠 표시 기준 운영 예정(조사일 시행 전).

## 7. 시장·경쟁 정보

- 운영사 딥그로브, 카카오벤처스+본엔젤스 15억 시드(2026-07). 투자 ≠ 수익성.
- 경쟁군: 제타·크랙·베이비챗·로판AI 등 캐릭터 챗. 프론티아 차별점은 "작품 단위 배포 + 제작 엔진". 모작은 이 차별점을 복제하되 위 약점(기억·정산·요금투명성)으로 우위 시도 가능.
- 수요 신호: 디스코드 suggestions 25건 중 제작·자산·발행 6 / 요금·모델 5 / 기억·노트 4 / TRPG·이벤트·엔딩 3 (수요 비율 아님, 간격 신호). 기억·요금·구독 요구가 반복 → 모작이 메울 지점과 일치.
- 콘텐츠: 로맨스 편중(여성 필터 표본). 투니온 웹툰 IP가 로맨스 외 장르면 공급 공백을 노릴 수 있음.

## 8. 모작 로드맵 리스크 & 다음 확인 과제

**가장 큰 실행 리스크:**
1. 스토리 엔진 신뢰성(기억·트리거·상태)이 "데모는 되는데 품질이 안 나는" 영역 — 월흔 데모에서 이미 겪는 난제와 동일.
2. 크리에이터 수급(닭-달걀): 작품이 없으면 플레이어가 없고, 플레이어가 없으면 디렉터가 안 옴. 초기 자체 제작 작품(자사 웹툰 IP) 투입이 해법.
3. AI 응답당 원가 > 과금 마진이면 적자. 모델 라우팅·캐싱·요금 설계 핵심.

**모작 착수 전 확인할 것(현 조사 미확인):**
- 실제 LLM 벤더·모델·토큰 한도·라우팅, 응답당 실원가.
- 내부 기억/요약/검색 구조 유무.
- 유료 모델 간 실제 품질 차이, 장기 플레이 기억 보존율.
- 정산 제반비용 단가, 디렉터 실수령 분포.
- 전 작품 엔딩/분기 완성도, 완주율·재방문·지출(사업성 핵심 지표) — 외부에서 관측 불가, 벤치마크 필요.

## 9. 한계

위 모든 수치는 부분·자발적 표본이다(앱리뷰 250건, 디스코드 회수분 공지11·패치3·포럼70, 라운지 각11). 발생률·전체 여론·사업성 결론으로 쓰면 안 된다. 가격·한도·정책은 2026-11-10 시점. 법적 쟁점은 반드시 법무 검토. 이 문서는 모작 의사결정용 분석이지 특정 복제 실행 지시나 프론티아 콘텐츠 복제 권유가 아니다.
