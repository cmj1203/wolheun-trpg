# 월흔 데모의 CoC 7판 전환 계획

작성: 2026-11-06. 상태: 구현 결정 완료, 구현·밸런스 실측 전.

이번 작업의 산출물은 문서와 조사 프레임이다. `app/`, `app_next/`, `assets/`를 수정하거나 서버를 실행하지 않았다. 아래 파일 변경은 후속 구현 레인의 작업 명세다.

## 0. 최종 사용자 결정과 범위

1. 아시나는 **고정된 완성 시트**로 시작한다. 특성치·기능·시작 자원을 굴리지 않는다. 교환, 재배분, 추천값 선택도 없다.
2. 캐릭터 시트는 선바 영상의 구글시트 필드·순서·자동 계산을 배운다. **플레이어가 새 인물을 만드는 주사위 생성은 후속 기능**이며 이번 데모 구현 목록에 넣지 않는다.
3. PC 전용. 1440×900 기준, 1280×720·1920×1080을 검수한다.
4. 1화의 공개 배경은 크롬웰 출신, 부족함 없는 성장 환경, 여행에 대한 열망, 자칭 미소녀다. 웰든·공녀·대공가·본모습·귀찌 마법을 시트·수첩·툴팁·GM 답변에 먼저 공개하지 않는다.
5. 귀찌는 1~2화에서 보통 소지품이다. 3화 독백에서 변장 정보가 수첩에 열리고, 4화 독백에서 **7일·7칸의 수명 트랙**이 나타난다. 1화의 기존 8칸 소모·발열·은발 결말은 제거한다. 영구 삭제와는 다르다.
6. 의심은 숨은 이야기 변수다. 1화 남자는 “첩자”라고 말하지 않는다. 의심 숫자·이름·증감 알림도 공개하지 않는다.
7. `bg3_study.md`를 읽고 적용했다. 기술 태그, 판정 전 목표·성공률, 큰 주사위 화면, 결과 후 자원 사용, 관계 알림의 **전달 순서**를 채택한다. d20·높게 굴리기·영감 재굴림 규칙은 섞지 않는다.

### 1.3 d100 판정

십의 자리 d10(00,10,…90)과 일의 자리 d10(0…9)을 조합한다. `00+0=100`, `00+1=01`, `90+9=99`. 값에 능력 보정치를 더하지 않는다.

판정은 `rawLevel`과 `passed`를 별도로 가진다. rawLevel은 자연 출목의 성취 단계, passed는 이번 난이도를 만족했는지다.

| 자연 결과 | 등급 |
|---|---|
| 01 | 대성공 `critical` |
| 기능/특성 본값 50 미만에서 96–100, 50 이상에서 100 | 대실패 `fumble` |
| 본값의 5분의1 이하 | 극단적 성공 `extreme` |
| 본값의 반 이하 | 어려운 성공 `hard` |
| 본값 이하 | 보통 성공 `regular` |
| 그 외 | 실패 `failure` |

대실패 판정은 성공 단계보다 먼저 검사한다. 이 경계는 A L234–241의 **기능/특성 본값 기준**을 채택한다. 난이도로 줄인 목표값을 기능 본값처럼 저장하지 않는다. SAN/행운도 본값과 출목을 갖되 별도 규칙 처리하며, 이성 손실량에는 일반 기능의 성취 보상을 붙이지 않는다.

요구 난이도는 `regular`, `hard`, `extreme` 중 하나다. 예: 기능 60, 어려움 요구, 출목 37 → rawLevel=regular, passed=false. 큰 글씨는 **실패**, 작은 글씨는 `37 / 목표 30 이하 · 보통 성공 수준`이다. 영상 59:00–1:00:00의 혼동을 막는다. 자연 01만 대성공이며 행운으로 01을 사지 못한다. [QS p.10; A L234–258; V L119–120]

**보너스/페널티:** 추가 십의 자리 1개당 후보 d100 하나를 더 만든다. 일의 자리는 공유한다. 보너스는 완성된 후보 중 최솟값, 페널티는 최댓값. 서로 상쇄한 순개수 최대 2개. 00+0을 100으로 바꾼 뒤 비교한다. `units=0, tens=[00,10]`이면 보너스는 10, 페널티는 100이다. `min(tens)`를 먼저 고르면 안 된다. [QS p.11; A Bonus/Penalty roll]

**대항:** 양쪽 성취 단계 비교 → 동률이면 기능/특성 본값 비교 → 이것도 같으면 별도 d100 낮은 쪽, 계속 동률이면 반복. 양쪽 모두 실패하면 목표 달성자는 없으며 현 상태가 유지된다. 전투의 반격/회피 동률 예외는 별도 전투 규칙이다. 현재 데모의 미리 정해진 칼날 회피는 **환경 위협 판정**이며 NPC 전투 라운드를 새로 만들지 않는다. 후속 대항 기능용 함수와 경계 테스트는 일반 대항까지만 구현한다. [QS p.10, 전투 pp.13–14]

### 1.4 행운과 강행

행운 소비는 선택 규칙으로 채택한다. 이미 나온 기능 결과를 1점당 1 낮춘다. 다른 주사위를 굴리지 않는다. 원출목·수정출목·소비량을 모두 보존한다. SAN, 행운 판정, 피해/손실량, 대성공·대실패, 강행 결과에는 쓰지 않는다. 아시나의 특성치 직접 판정에는 소비를 열지 않는 것으로 범위를 고정한다(A의 Skill roll 표현에 맞춘 데모 제한). [A L229–230]

실패 결과에서만 `필요한 행운`을 제시한다. 비용=`원출목-이번 목표값`. 성공을 더 높은 등급으로 사는 UI는 이번 데모에서 제공하지 않는다. 성공을 뒤집을 잔량이 없으면 버튼은 비활성화하고 필요한 수만 표시한다. 투자 결과는 이번 요구 수준까지이며 추가 관계 보상은 없다. 감소한 행운은 이후 운 판정의 본값이 된다. 회복·일일 보충은 이번 짧은 데모에 없다.

강행은 **같은 목표에 최대 1회**, 행동을 더 밀어붙일 이유와 방법이 있어야 한다. 먼저 평소 실패와 달리 무엇이 위험해지는지 판정 패널에 표시한다. 플레이어가 확정한 뒤 굴린다. 단순히 “다시”라고 썼다고 무료 주사위를 주지 않는다. 전투/회피, 건강 저항, 정신 저항, SAN, 행운, 피해 굴림은 강행하지 않는다. 대실패 뒤 강행도 이번 데모에서는 닫는다.

실패한 강행은 실제 눈이 96 미만이어도 **예고된 심각한 결과**를 받는다. 출목 등급을 거짓으로 fumble로 바꾸지 않고 `pushedFailure=true`를 따로 기록한다. QS p.10은 예고를 선택 사항으로 설명하지만 **월흔 솔로 UI에서는 항상 예고한다**. 예고는 칼·거리·눈앞의 물건 등 현재 아는 위험에 한정하며 정체·다음 사건을 알려 주지 않는다. 여우가 말하지 않는다.

### 1.5 피해와 이성

HP 피해는 0 아래로 내려가지 않는다. 한 번의 피해가 최대 HP의 절반 이상이면 중상, 건강 판정 실패 시 의식 상실. HP 0은 즉시 의식 상실이며 “0에서 한 번 더 맞아야 쓰러짐” 규칙을 없앤다. 중상이 있는 채 HP 0이면 빈사, 한 번에 최대 HP 이상의 피해는 즉사 규칙을 별도로 검사한다. [QS pp.14–15; A L420–450]

이 데모는 전투 라운드를 도입하지 않는다. 의식 상실/빈사에 도달하면 상태를 기록하고 `e_incapacitated`에서 이번 이야기를 끝낸다. 빈사를 사망으로 표시하지 않는다. 다음 라운드 건강 판정·응급처치·의료 처치는 후속 장면 규칙이다. 엔진의 상태 계산은 구분해 검증한다.

종료 이유는 `unconscious / dying / dead / madness` 중 하나로 저장한다. 한 타격이 최대 HP 이상인 즉사 조건에서는 `dead`와 사망 문구, HP0·중상 조건에서는 `dying`과 빈사 문구를 사용한다. 의식 상실은 쓰러졌다는 사실까지만 쓴다. 모든 이유가 같은 e_incapacitated 비트를 사용해도 원인과 생사 상태를 뭉개지 않는다.

SAN은 공포·충격에만 쓴다. 무시당함·부끄러움·설득 실패를 정신 질환 수치로 바꾸지 않는다. 위험 사건의 `성공 손실/실패 손실`을 d100 SAN 판정으로 결정한다. 예: `0/1`은 성공 시 0, 실패 시 1. SAN 대실패는 해당 사건의 최대 손실이며 “두 배”가 아니다. [QS p.12; A Sanity Rolls]

한 사건에서 5 이상 손실이면 INT 판정을 하고 성공할 때 일시적 광기, 하루 시작 SAN의 1/5 이상 누적 손실이면 장기적 광기, SAN 0이면 지속 플레이 불가 상태다. 이번 콘텐츠의 손실값은 0/1이므로 정상 시작 상태에서 이런 조건에 도달하도록 장면을 억지로 추가하지 않는다. 상태 단위 테스트에서는 경계를 검사하고 해당 상태가 나오면 `e_incapacitated`로 종료한다. 1화에 없는 광기 대사를 생성하지 않는다.

## 2. 아시나의 고정 시트

### 3.3 실패·행운·강행의 처리 계약

`prepare → roll → decision? → resolve → narrate → advance`를 하나의 판정 트랜잭션으로 만든다.

1. prepare에서 행동 ID, 본값, 난이도, 보정, 소지품, 이미 알려진 위험을 고정한다. 확인 후에 난이도를 바꾸지 않는다.
2. roll은 서버에서 한 번만 난수를 소비한다. 클라이언트 애니메이션의 프레임 수는 RNG에 영향을 주지 않는다.
3. 성공이면 기존 hit 결과를 적용한다. 자연 critical은 §3.2 추가 효과를 적용한다.
4. 일반 실패는 결과와 대가 적용을 **보류**하고 `결과 수용 / 행운 N 소비 / 강행 방법`을 제시한다. 가능한 것만 활성화한다.
5. 수용 시 기존 miss의 사건·트랙 효과 + soft 대가 1개. 기존 miss에 들어 있던 `price` 목록 중 soft가 없으면 장면 전체 soft에서 조건에 맞는 것을 고른다.
6. 강행을 고르면 현재 상태에서 hard 후보를 1개 선택해 **ID와 효과를 저장하고 예고**한다. `before` 효과·소지품 소모는 처음 행동에서 한 번뿐이며 강행 때 다시 적용하지 않는다. 강행은 같은 목표·같은 기능·같은 요구 난이도다. 재시도 방법이 새 도구의 이점을 만들면 보너스 1개까지만 추가할 수 있다.
7. 강행 성공은 hit, 실패는 miss + 그 hard 대가. 강행의 자연 critical은 critical 효과, 자연 fumble도 이미 예고한 hard 대가 **하나만** 받는다.
8. 첫 굴림 fumble은 miss + hard 대가 하나. 사전에 강행 위험을 확인한 것이 아니므로 추가 confirmation 없이 확정한다. 자연 대실패가 자동 사망을 뜻하지 않는다.
9. 유효 대가가 없으면 추첨하지 않는다. 일반 실패는 miss만, 대실패는 miss와 추가 HP1(물리 시도) 또는 의심+1(인물이 있는 사회 시도), 혼자 하는 탐색은 탈주-1을 적용한다. 강행은 hard 후보가 하나도 없으면 제공하지 않는다. 미래 예외를 임의 생성하지 않는다.
10. 효과를 전부 확정한 뒤 한 번만 운명/HP/SAN 상태와 다음 비트를 평가한다. `free.rolls`는 최초+강행을 합쳐 목표 시도 1회 증가한다. 현재 free 기본 turns=1을 유지한다.

동일 상황·목표의 실패 후 같은 입력은 새 판정이 아니다. 판정 결과 패널로 돌아오거나 이미 확정된 장면 반응을 이어간다. 해결 완료 후 같은 질문을 다시 강제하지 않는다. 의도·대상·수단이 실제 달라졌을 때만 새 목표로 판정한다. 문자열 금지 목록 추가로 해결하지 않는다.

기존 mixed 문장은 강행 성공 문장으로 통째로 재사용하지 않는다. “성공했지만 잡힌다” 같은 내용을 성공 뒤 몰래 넣지 않기 위해 hit를 사용하고, mixed의 필요한 관찰 가능한 사건은 아래 대가 표에서만 유지한다. 콘텐츠 검증기는 새 규칙 시나리오에서 mixed를 거부한다.

### 3.5 조건 보정·즉흥 입력

기존 mods의 +1/-1을 백분율 10으로 곱하지 않는다. 조건당 보너스/페널티 십의 자리 1개로 치환하고 상쇄 후 2개로 제한한다.

| 조건 | 적용 접근 | 변경 |
|---|---|---|
| 거리_가까움 | run / avoid | run 보너스1, avoid 페널티1 |
| 가방_끈 | run | 페널티1 |
| 눈부심 / 모래바람 | watch | 각각 페널티1 |
| 자리_트임 / 칼_밀착 | dodge | 각각 페널티1 |
| 칼_밀착 | block / bluster | 페널티1 |
| 퇴로_막힘 | flee | 페널티1 |
| 지도_찢김 / 별_가림 | read | 각각 페널티1 |
| 발자국 | read | 보너스1 |
| 바위_온기 / 짐승_소리 | shelter | 보너스1 / 페널티1 |
| 귀찌<=3 | beauty / stare_back / hide_earring | 제거 |

scene twist를 없애면서 그 twist만 생성하던 눈부심·모래바람·구름·발자국·바위·짐승 플래그는 이번 에피소드에서 자동 발생하지 않는다. 조건 매핑은 기존 저장·향후 장면의 지원 규칙이며, 도달하지 않는 조건 때문에 새 장면을 넣지 않는다.

자유 입력 분류 계약: `talk / ask / idle / action / out_of_world`를 유지하고 action 안에서 `goal, target, method, checkRef, difficulty, bonusReasons`를 결정한다. 말재주(짧은 둘러대기), 설득(근거로 납득시키기), 매혹(호감 유도), 위협(겁주기)을 구분한다. 큰 행동은 전용 bold 결과를 유지하고 대사 한 줄로 무효화하지 않는다. 모르는 이름은 플레이어가 다시 적게 한다.

입력에서 규칙을 확정하지 못하면 장면에서 허용한 기능 후보를 판정 카드에 보여 주고 플레이어가 방법을 고르게 한다. LLM이 임의의 새 기능/숫자를 만드는 fallback은 없다. 사용자가 입력한 핸드폰 같은 세계 밖 물건에는 판정·수치 변화가 없다.

### 3.6 귀찌의 단계 공개

귀찌 정보가 이미 내부 데이터에 있다는 이유로 HUD에 전송하지 않는다. 화면용 DTO는 장면 공개 상태에 따라 필드를 빼야 한다.

| 단계 | 트리거 | 수첩 | 시트/알림 | 상태 |
|---|---|---|---|---|
| 1~2화 | 시작~3화 독백 전 | 귀찌의 마법·본모습 없음 | 수명 행·빈칸·자물쇠·툴팁·효과음 모두 없음. 소지품명은 `귀찌` | `earringDays=null`, `earringDisclosure='item'` |
| 3화 | `3화_008.json` 귀찌 독백이 실제 표시된 직후 | 원작 독백 범위의 변장 정보 해금 | 수명 트랙은 아직 없음. GM 해설 없음 | `'disguise'` |
| 4화 | `4화_003.json` 일주일 독백과 `4화_004.json` 탈출 목표가 제시된 직후 | 기존 항목에 시간 제한 추가 | `귀찌 수명 7일`·7칸. `새 수치 · 귀찌 수명` 알림을 한 번만 | `'deadline'`, `earringDays=7`, `deadlineNotified=true` |
| 공개 이후 | 이야기의 날짜가 하루 실제 경과 | 남은 일수 반영 | 7→6처럼 한 칸 감소 | 날짜 eventId마다 1회 |

3화에서 7일을 미리 초기화·소모하지 않는다. 4화 독백이 남은 일주일의 기준점이다. 채팅 턴·주사위 횟수·실제 컴퓨터 시간으로 줄이지 않는다. 날짜가 여러 날 건너뛰면 경과 일수만큼, 하한0. 동일 이벤트 로드 시 재차 초기화/알림/차감하지 않는다. 0은 변장 유지 불가 상태이며 이후 원작 시나리오가 처리한다. **1화 x_unmasked를 되살리는 기본 종료 연결은 없다.**

현재 구현 레인은 공개 단계 타입·직렬화·HUD 필터와 테스트용 이벤트까지 만든다. 아직 없는 3~4화 장면을 새로 구현하는 일은 범위 밖이며 실제 트리거 배치는 해당 화 구현 때 위 원작 위치에 연결한다.

### 3.7 이야기 분기와 공개 정보

의심·집착·호감·탈주 clamp 0~10, b09의 `의심>=6 → r2_bind`, `집착>=4 → e_curious`, 그 외 e_survivor는 유지한다. 의심이 높다는 것은 경계·붙잡음의 내부 이유이며 “첩자”라는 발화를 허용하지 않는다.

`spy_cut`(의심>=10)과 `reckless`(경고 뒤 실패)로 즉시 사망시키던 fate는 제거한다. 의심10은 `r2_bind`로 한 번만 이동하고, 이미 r2_bind라면 다음 결과에서 e_spy로 끝낸다. 공개 결말 e_spy 제목은 `붙잡힌 여행자`, 설명은 상대가 경계하며 가방을 압수하고 붙잡았다는 사실만. 내부 ending ID `spy`는 저장 호환용으로만 허용하고 UI·GM 데이터에는 노출하지 않는다.

`x_collapse`는 반복 입력 처벌로 사용하지 않는다. idle은 1회 후 다음 비트로 진행하며, 쓰러짐은 HP 상태에서만 e_incapacitated로 처리한다. 귀찌 관련 `x_unmasked`도 제거한다. quit 및 road/deal/value/curious/survivor의 비밀 없는 경로는 유지하되 `value`의 귀족 정체 전제는 §3.2대로 바꾼다.

플레이어가 미공개 가문명·본모습을 먼저 입력하면 기존 미공개 이름 정책처럼 그 정보로는 아직 행동할 수 없다고 한 번 안내하고 다시 적게 한다. “귀찌를 빼 본다”처럼 알려진 물건을 만지는 행동은 독백의 비밀 설명을 발동하지 않으며, 1화에서는 귀찌가 빠지지 않는 관찰 가능한 반응까지만 허용한다. 현재 refusal에 있는 “은발을 보였으면…” 문장은 제거한다. 이는 원작 각색의 사건 제한이며 CoC가 플레이어 행동을 원칙적으로 금지한다는 뜻이 아니다.

화면의 긴장 자원은 HP/SAN/Luck다. MP는 표준 시트 필드로 있지만 소모 수단이 없다. 관계·탈주를 HP를 대신하는 또 다른 체력처럼 경고하지 않는다.

## 4. 캐릭터 시트와 만들기

### 4.1 현재 데모의 PC 시트

완성된 고정 시트를 읽는 패널이다. 아시나 생성 단추·주사위·추천값·스탯 교환 UI가 없다. 도입 2번째 줄에서 시트가 열리고 다음으로 넘기면 닫힌다. 이후 `캐릭터` 단추나 `C`로 다시 연다. 입력창에 포커스가 있으면 문자 C를 가로채지 않는다.

1440×900에서 패널 폭1120, 높이760, 화면 중앙. 1280×720에서는 폭1120·높이656으로 내부 세로 스크롤만 생긴다. 1920×1080에서도 폭1120을 유지해 지나치게 벌어지지 않는다. 상단 제목/닫기와 자원 줄은 고정, 본문만 스크롤한다. 전용 모바일 레이아웃과 모바일 검수는 없다.

구글시트의 **초상/신상 → 특성치/파생값 → 기능 → 전투/백스토리** 순서를 유지한다. 3열 본문은 288/336/432px, 열 간격16px, 좌우 안쪽 여백16px로 구성한다. 기본 글자16px, 표 숫자16px tabular, 보조값14px, 행 높이32px 이상이다. 열 사이의 시각적 관계가 정보의 그룹과 일치해야 한다.

기능의 `배정`은 간편 생성 방식 때문에 실제 투자 예산처럼 해석하면 안 된다. 직업 기능은 최종 고정 배정 표시(`50 고정`), 관심 기능은 `+20`, 최종값은 합 열에 표시한다. 일반 생성의 점수 입력 양식은 §7에서만 편집 가능하다.

패널 바탕 `#F7F5FF`, 구획 제목 `#625B9E`, 제목 글자 흰색, 이름 셀 `#E5E0F3`, 값 셀 흰색, 자동 계산 셀 `#ECECEC`, 본문 `#24212C`, 선 `#B9B4C8`. 원본 구글시트의 연보라 구획·회색 계산 칸을 계승한다. 이는 새 UI 지정값이며 영상의 픽셀 색을 측정한 결과가 아니다. 바깥 게임의 기존 사막 테마는 유지한다.

시트와 HUD·선택지·판정 패널은 같은 서버 시트 DTO를 읽는다. CSS에 별도 계산표를 만들거나 클라이언트에 원작 숨은 정보를 내린 뒤 `display:none`으로 가리지 않는다. 접근성 트리·툴팁·수첩 검색·백로그·저장 썸네일도 공개 필터를 공유한다.

### 4.2 판정 전 선택지와 큰 주사위 화면

BG3 연구 B §2·§7의 전달 순서를 적용한다. 예:

`[설득 · 보통 · 성공 40%] 결백을 호소한다`

숫자는 기능 본값만 복사하지 않고 현재 난이도와 순 보너스/페널티를 반영한 **목표 달성 확률**이다. 항법50/어려움이면25%. 보너스1이면43.5%. 자연 대성공 포함, 행운 소비·미래 강행은 제외한다. d10의 모든 조합을 세어 계산하며 독립 d100 두 번 공식으로 근사하지 않는다.

선택 뒤 화면 중앙 800×520의 모달 판정판. 1280에서도 입력창을 밀어내지 않는 오버레이다. 제목은 행동, 그 아래 `기능 본값 · 요구 난이도 · 목표 N 이하`. 조건은 짧은 칩으로 `칼이 닿아 있음 · 페널티 1`처럼 표시한다. 숨은 의심이나 미래 공격을 이유로 쓰지 않는다.

중앙에 112px d10 두 개를 놓고 `십의 자리`·`일의 자리`를 라벨링한다. 추가 십의 자리 주사위는 동일 모양·80px, 기본 십의 자리 옆에 배치한다. `보너스 1`/`페널티 1`을 눈에 보이게 표시한다. 보너스는 초록 테두리, 페널티는 적색 테두리. 버린 후보는 흐리게 표시하되 값을 지우지 않는다.

UI 하단의 단계:

- 굴리기 전: `굴리기`, `돌아가기`. 돌아가기에는 RNG·소모·effects가 없다.
- 굴린 뒤 일반 실패: `행운 N 소비`, `강행`, `결과 수용`. 가능 조건을 만족하는 버튼만 활성화.
- 강행 방법 선택: `새 방법` 입력 또는 장면에 정의한 구체적 수단 → 예고된 hard 대가 한 줄 → `강행 판정`/`돌아가기`. 돌아가도 첫 출목은 유지한다.
- 성공·수용·대실패 확정: `계속`. 효과는 서버에서 한 번 확정되어 있으며 이 버튼이 다시 적용하지 않는다.

행운은 `행운 7 소비 · 47 → 40 · 남은 60 → 53`처럼 표시한다. **재굴림**, 영감, 주사위 아이콘의 회전으로 표현하지 않는다. 250ms 동안 기존 결과 숫자가 내려가고 소비된 자원이 반영된다. BG3의 영감은 선택 기회의 위치만 참고한다.

영상의 구체적 관찰은 `coc_video_study.md`다. 파란 입체 d10·흰 숫자·이동 회전·짧은 결과 배너를 계승하되 BG3 요청에 맞춰 중앙 대형 화면으로 바꾼다.

색만으로 구분하지 않는다. 어려운 난이도를 충족하지 못한 보통 성공 수준도 큰 라벨은 실패다. 영상의 `대단한 성공`을 대성공으로 오역하지 않는다.

구현 렌더러는 `app/web/percentile-dice.ts`의 Canvas2D 투영 방식으로 정한다. 십면체 메시·면 번호·최종 회전 자세 표를 한 번 정의하고, 고정 키프레임으로 회전/이동을 보간한다. 물리엔진·외부 3D 라이브러리를 새로 넣지 않는다. 실제 RNG는 서버에서 이미 결정되므로 모션은 결과를 “뽑는” 장치가 아니다. Canvas의 최종 면과 DOM 숫자가 항상 동일한 이벤트를 읽어야 한다.

Space/클릭은 현재 굴림의 모션만 생략해 곧바로 최종 눈으로 간다. 연타가 다음 판정이나 다음 장면까지 넘어가지 않게 입력을 소비한다. `prefers-reduced-motion`이면 150ms 페이드 후 값·결과만 표시한다. 탭 전환·리사이즈·저장 로드는 출목을 바꾸지 않는다.

효과음은 기존 음소거 설정을 따른다. 착지/결과 효과음이 수치 공개보다 먼저 나면 안 된다. 숨은 판정·관계 수치에 소리를 내지 않는다. 음색은 영상에서 청취 검증하지 않았으므로 “같은 소리”라고 주장하지 않는다.

### 4.4 이야기 안의 변화 알림

확정 결과 뒤 한 줄에 `체력 -2`, `이성 -1`, `행운 -7`을 실제 적용량으로 표시한다. 최대·최소 clamp 때문에 2를 깎으려 했지만1만 줄었다면 `-1`. 원래 변화가0이면 줄을 만들지 않는다. 이성 판정 성공으로 손실0이면 판정 카드에는 `이성 손실 없음`을 남기되 변화 로그는 추가하지 않는다.

관계 알림은 B §3·§7.2의 작은 보조 표시를 채택한다. **최신 사용자 결정 때문에 B §7 표의 `의심 ↑` 제안은 채택하지 않는다.** 의심 변화는 상태에만 남고, 관찰 가능한 경계 행동은 인물 대사·서술로 표현한다.

집착·호감도 아직 의미가 공개되지 않은 동안에는 숫자 토스트를 띄우지 않는다. 원작에서 상대 반응이 명백하게 드러난 이후 `호감 ↑`/`관심 ↑` 한 줄만 2초 표시하며, 내부 집착을 `호감`으로 합치지 않는다. 현재 1화에서는 b09의 표정·대사로 관심이 드러난 뒤 변화에만 알림을 허용한다. 그 전 값을 소급해서 한꺼번에 표시하지 않는다. HP/SAN/Luck 줄이 있으면 같은 줄의 끝에 합쳐 알림 중첩을 막는다.

### 4.5 도입 대사 교체안

현재 `app/web/introduction.ts:3–8`의 여섯 줄을 아래 여섯 줄로 교체한다. 요청에서 지칭한 줄 번호와 현재 파일이 달라 실제 파일 기준을 적었다. 이 문서는 제안 명세이며 아직 기존 코드를 바꾸지 않았다.

1. 난 이 판을 진행하는 사막여우야.
2. 넌 아시나가 돼. 이게 네 캐릭터 시트야.
3. 아래에 할 말이나 행동을 적어. 단추를 골라도 돼.
4. 어려운 행동은 주사위로 정해. 목표 이하가 나오면 성공이야.
5. 01은 대성공. 실패하면 행운이나 강행을 고를 수도 있어.
6. 궁금하면 입력창 오른쪽 내 얼굴을 눌러 물어봐.

2번은 캐릭터 패널, 3번은 입력창, 4~5번은 설명용 정지 판정 카드, 6번은 GM 버튼을 가리킨다. 정지 카드는 본편 RNG·자원을 소비하지 않는다. 모든 등급·부상·숨은 수치를 여섯 줄에 욱여넣지 않고 첫 판정 카드·시트 툴팁에서 읽게 한다. 진행 중 여우의 자발적 규칙 해설을 되살리지 않는다.

### 5.1 수학적으로 확정한 분포

| 80 | 1 | 15 | 24 | 40 | 19 | 1 | 96 | 64 |

어려움 요구의 통과율은 `floor(S/2)%`, 극단적 요구는 `floor(S/5)%`다. **본값을 줄이지 않고 목표만 줄인다.** 항법50/어려움은 총 성공25%, 26~50은 보통 성공 수준이지만 이번 목표 실패다. 보너스1에서25%는43.5%이며 독립 시행 공식43.75%와 다르다.

자연 critical은 보정0에서1%. 보너스1은1.9%, 페널티1은0.1%다. 전체 판정의 critical 비율을 무조건1%로 고정한 테스트는 틀리다. 조건별 분포와 난수 경계는 300개 플레이보다 전수 판정 테스트로 검증한다.

### 5.2 기존 하네스의 기준선

`work/demo-slice/lane45/balance.ts:23–88`은 보통·무작위·무리, 시드1~300, 최대60회 입력을 실행한다. 보통은 default_approach, 무작위는 열린 선택지의 균등 선택, 무리는 지정 행동을 쓴다. 행운은 거절하며 엔진 기본 구성상 활성화되지 않는 경로도 있으므로 새 하네스에서는 명시적으로 활성화한다.

기존 기록 `after47.json`의 파일값: 보통 HP0 1/300·정신력0 17/300, 무작위9/300·3/300, 무리58/300·2/300. 보통 spy_cut22/300, 무작위54/300, 무리62/300·unmasked1/300. **이번에 이전 엔진을 다시 실행한 수치가 아니다.** 2d6 시드와 d100 시드가 같은 결말을 내야 한다는 회귀 목표는 잡지 않는다.

### 5.3 새 정책과 통과 기준

같은 하네스에서 시드1~300을 정책별로 독립 실행한다. 정책 선택 RNG와 판정 RNG를 분리한다. 60입력 상한은 유지하고 상한에 닿으면 성공 종료가 아니라 실패로 기록한다.

| 정책 | 선택/실패 후 결정 | 목표 |
|---|---|---|
| 보통 | 기존 default. 행운·강행 없이 실패 수용 | 300/300 종료, HP0 0~5%, SAN0 0%, 평균 능동 판정3~6회 |
| 무작위 | 열린 접근 균등. 행운 거절. 가능한 강행 여부도50% | 300/300 종료, HP0 0~15%, SAN0 0%, 평균 판정3~8회 |
| 무리 | watch→resist→block→retort→cover→read 우선, 이후 default. 가능한 강행 항상, 행운 거절 | 300/300 종료, HP0 0~25%, SAN0 0%, 대가/피해 평균이 보통보다 낮으면 원인 검토 |

삭제된 hide_earring을 무리 정책에서 retort로 교체하고, 무판정 silent를 강행 정책의 시험 대상으로 쓰지 않는다. 무판정/세계 밖 입력 시나리오는 별도 회귀 테스트에서 검증한다.

모든 정책에 공통:

- 사용자가 중단하지 않은 실행에서 끝나지 않은 비트, 재귀 루프, pending 상태 방치 0건.
- HP/MP/Luck/SAN 음수·상한 초과0건, 중복 부상·중복 효과0건.
- 1화 귀찌 공개·귀찌 소모·unmasked 결말·첩자 발화·의심 토스트0건.
- HP/SAN 붕괴 없는 정상 결말이 보통95% 이상, 무작위85% 이상, 무리75% 이상.
- 단순 선택지만 누른 정책에서 1화 SAN 손실은 합계0~3. 조롱만으로 SAN 손실0.
- 각 정책의 판정별 `본값/요구수준/보정/원등급/통과/행운/강행/피해/최종분기`를 CSV 또는 JSONL로 남긴다. 총 성공률만 보고 결론 내리지 않는다.

300시드는 플레이 흐름의 검사다. 1% 사건은 표본오차가 크므로 critical 3건을 정확한 통과값으로 삼지 않는다. 자연 등급은 전수 테스트, 정책 지표는 위 범위, 결말별 구성은 보고 지표로 나눈다. 보통의 curious 비율을 억지로 높이려고 숨은 주사위를 조작하지 않는다.

위 값은 **설계 목표이며 d100 엔진 실측 결과가 아니다**. 실패하면 먼저 중복 피해·옛 귀찌 효과·의심 누적·강행의 추가 턴 소모가 남았는지 조사한다. 그 오류를 고치지 않은 채 스탯·난수·테스트 허용 범위를 바꿔 맞추지 않는다. 규칙 구현이 맞는데 목표를 벗어나면 접근 난이도·사건 피해의 변경안을 근거와 함께 리드에 보고한다.

### 6.2 타입과 이벤트의 필수 내용

추가 필드를 임의로 늘리지 않도록 다음 계약으로 고정한다.

- `GameState`: `v=2`, `ruleset='coc7-wolheun-v1'`, 원래 seed/rng, 현재 자원, 이야기 트랙, majorWound(boolean), physicalState(conscious/unconscious/dying/dead), madness(none/temporary/indefinite/permanent), incapacitatedReason, dayStartSan/sanLossToday, sanExposureIds, publicKnowledge, earringDisclosure/earringDays/deadlineNotified, 완료된 eventId 목록.
- `RollResult`: rollId, checkKind(skill/characteristic/sanity/luck), reference ID, value, difficulty, target, units, tens[], chosenIndex, rawTotal, rawLevel, effectiveTotal, effectiveLevel, passed, bonusCount, penaltyCount, luckSpent, pushed, parentRollId.
- `PendingCheck`: beat/approach/goal/method, 최초 roll, 적용 완료 beforeEffectId, 허용 decision, 예고 hardPriceId와 효과 snapshot, 직전 입력·다음 비트. 마지막 log를 뒤져 원판정을 추측하지 않음.

- 이벤트 순서: checkPrepared → rolled → decisionRequired(필요 시) → resourcesChanged/conditionChanged → narration → sceneAdvanced. `rawTotal`을 수정해 원주사위 기록을 잃지 않음.

본편 RNG는 순서대로 주사위·명시적 대가 추첨·피해에만 쓴다. 대가 후보가 1개면 추첨하지 않는다. 후보가 여러 개면 균등 선택 후 RNG를 실제로 진행하고, 선택 ID를 저장한다. 예고 뒤에는 다시 추첨하지 않는다. 생성·모션 RNG와 분리한다.

현행 `save.ts:19–24,34–66`은 바깥 SaveFile.v와 GameState.v 모두1이고, 능력5개·트랙과 옛 pendingLuck를 검사한다. 개별 old HP4를 new HP8로 비례 환산하면 SAN 의미·진행 결과·귀찌 스포가 함께 섞인다. **v1의 진행 중 상태를 v2로 억지 변환하지 않는다.**

1. 목록에서 구버전을 `이전 규칙`으로 표시한다. 로드하면 `규칙이 바뀌어 이 장면은 그대로 이어갈 수 없습니다. 기존 저장은 보관하고 1화부터 새로 시작할 수 있습니다.`와 `새 규칙으로 시작 / 돌아가기`를 보여 준다.
2. 새 시작을 고르면 새 slot ID를 만들고 고정 시트·새 공개 상태·새 seed로 시작한다. 옛 파일·원래 slot 이름·view·log를 덮어쓰지 않는다. 새 파일의 meta에 `migratedFromSlot`만 남긴다.
3. 구버전 기록은 별도 읽기 전용으로 볼 수 있게 남긴다. 구규칙 주사위는 “이전 규칙 2d6”로 렌더한다. 그 로그를 새 게임의 기억·수첩·LLM에 합치지 않는다.
4. 옛 pendingLuck·위험 플래그·체력_쓰러짐·정신력_충격·귀찌 수치·수첩 해금·긴장 RNG는 새 플레이에 이식하지 않는다. 이미 끝난 판도 같은 원칙.
5. v2는 pending 포함 정확 복원한다. 판정 중 저장하면 고정된 눈과 현재 결정 창으로 돌아오며 재굴리지 않는다. 애니메이션 재생 위치는 저장하지 않고 최종 눈으로 복구한다.
6. v2 저장 검증은 버전/ruleset/시트preset/비트, 정수·범위, 후보눈과 합계, raw/effective 관계, 행운소비가능성, 허용된 pending 전이, 공개단계와earringDays의 일관성을 검사한다. 불일치는 원본을 보존한 채 로드 오류로 반환한다.

이는 옛 저장의 **무손실 보관 + 새 규칙 시작** 정책이며 중간 진행 보존을 약속하지 않는다. UI 확인 없이 강제로 새 게임으로 바꾸지 않는다.

## 7. 플레이어 캐릭터 만들기(나중)

**현재 데모 구현 단계·완료 조건에 포함하지 않는다.** 아래는 나중에 자기 인물로 별도 이야기를 시작할 때의 결정된 명세다. 아시나 시트와 생성 UI를 공유하되 아시나를 편집 가능한 draft로 만들지 않는다.

### 7.1 흐름

`정체 입력 → 특성 굴림 → 나이 보정 → 파생값 → 직업 → 기능 배분 → 배경 → 확인 → 시작`.

1. 이름·성별·나이·출신·직업 후보를 입력한다. 첫 출시 범위는 인간·15~89세. 신장·체중은 서술 입력이며 SIZ에서 실제 cm/kg를 자동 생성하지 않는다. 설정 시대는 월흔, 현재 지역 목록은 그 시나리오가 허용한 것만 표시한다.
2. 근력→건강→크기→민첩→외모→지능→정신→교육→행운 순으로 한 항목씩 굴린다. 옆에 공식 `3d6×5` 또는 `(2d6+6)×5`가 표시된다. §4.3의 같은 화면·타이밍·조작을 사용하되 **생성 때는 d6 세 개/두 개**, 기능 판정 때만 d10 두 개다. d100으로 능력치를 생성하지 않는다.
3. 개별 눈 → 합 → +6(해당할 때) → ×5 → 본값 순으로 보여 준다. 결과는 시트 본값에 자동 입력되고 반·5분의1과 파생값이 즉시 갱신된다. 영상의 수동 숫자 옮기기에서 생긴 혼동을 줄인다.
4. 각 항목은 draft 안에서1회만. 되돌아가 확인하는 것은 가능하지만 재굴림·서로 교환은 제공하지 않는다. draft를 버리고 전체 생성부터 새로 시작하는 것은 별도 확인 후 가능하다. 판정 RNG와 생성 RNG는 분리한다.
5. 아래 나이 보정을 적용한다. 입력 순서대로 최종값이 바뀌는 장면과 이유를 보여 준다. EDU 향상 굴림은 d100>현재 EDU일 때만 d10을 더하고 상한99.
6. HP/MP/SAN/Luck/DB/체구/MOV·모국어·회피 기본값을 계산한다. 체력·이성은 직접 입력하지 못한다. 중상·광기·성장은 처음0/false.
7. 직업을 고르고 직업 점수·관심 점수를 따로 배분한다. 입력 열은 영상처럼 기본/배정/성장/합/반/5분의1, 배정 셀을 열면 직업·관심 두 입력을 구분한다.
8. 초상·한마디·외관·흉터·성격·신념·중요한 사람/장소/물건을 작성한다. 시나리오 밖 비밀을 창작했다고 실제 세계의 사실로 자동 등록하지 않는다. 기이한 경험·공포증/집착은 시나리오가 허용하는 초기 설정만.
9. 남은 점수가0이고 모든 검증을 통과한 뒤 `이 인물로 시작`. 생성 결과·개별 눈·배분 내역을 저장한다. 시작 후 기본 특성/초기 기능을 다시 편집하지 않는다.

### 7.2 나이 보정

출처 A의 Character Creation/Age/Move Rating 표. 이 규칙은 연령이 확정된 새 인물에만 적용하며 나이가 미공개인 아시나를 거꾸로 추정하지 않는다.

| 나이 | 생성 조정 | EDU 향상 횟수 | MOV 감소 |
|---|---|---:|---:|
| 15–19 | STR 또는 SIZ에서 합계5 차감, EDU-5. 행운 두 번 중 높은 값 | 0 | 0 |
| 20–39 | 없음 | 1 | 0 |
| 40–49 | STR/CON/DEX에서 합계5 배분 차감, APP-5 | 2 | 1 |
| 50–59 | 위 신체 합계10 차감, APP-10 | 3 | 2 |
| 60–69 | 위 신체 합계20 차감, APP-15 | 4 | 3 |
| 70–79 | 위 신체 합계40 차감, APP-20 | 4 | 4 |
| 80–89 | 위 신체 합계80 차감, APP-25 | 4 | 5 |

선택 차감은 각 특성1 이상이 되게 분배한다. 원 굴림 때문에 요구 차감을 만족할 수 없는 draft는 그 나이로 확정할 수 없다고 표시하고 나이 변경 또는 새 draft를 제공한다. 몰래 하한을 덧씌워 높은 특성을 만들지 않는다. MOV는 파생 기본값에서 감소시킨다.

### 7.3 직업과 배분

직업은 배경에 따라 주는 기능 묶음이다. 현재 아시나의 내부 “귀족 여행자”를 플레이어에게 강제로 부여하지 않는다. 후속 최초 출시의 직업표는 아래 세 개로 제한한다. 아래 직업표는 **월흔용 직업 설계**, 점수와 기본 기능 계산은 CoC 방식이다.

| 직업 | 직업점수 | 직업 기능8개 | 재력 범위 |
|---|---|---|---|
| 여행자 | EDU×4 | 관찰력, 항법, 은밀행동, 오르기, 역사, 모국어, 설득, 심리학 | 10–50 |
| 학자 | EDU×4 | 역사, 자료 조사, 모국어, 외국어1개, 심리학, 관찰력, 설득, 자연 | 10–50 |
| 길잡이 | EDU×2+DEX×2 | 항법, 관찰력, 듣기, 생존술(사막), 은밀행동, 오르기, 응급처치, 말재주 | 5–30 |

관심 점수는 최종 INT×2. 직업점수는 그 직업 기능8개와 재력에만, 관심점수는 신화 기능을 제외한 허용 기능에 쓴다. 예산을 합쳐서 직업에 무관한 기능만 올리는 영상의 간편 운영을 그대로 구현하지 않는다.

영상 인물의 EDU60·INT45라면 여행자 기준 **직업240+관심90=330**. 기본값은 예산에서 차감하지 않는다. 예를 들어 회피 기본22에 관심50을 투자하면 합72/반36/5분의1 14. “회피50”이라고 입력한 것이 합50인지 투자50인지 제목으로 구분한다.

초기 **투자 후 기능 상한89**를 데모 후속 생성의 제한으로 채택한다. 영상에서 진행자가90 아래를 요구한 것과 맞춘 선택이며 CoC 전체의 절대 상한이라고 설명하지 않는다. EDU에 연동된 모국어 등 기본값이 이미89보다 크면 그 기본값은 유지하되 추가 투자는0. 크툴루 신화는0·투자 불가. 세계에 없는 현대 기능은 선택 목록에 없다.

위 직업 범위, 예산별 총합, 정수·음수·상한, 전문화 중복, 재력 최소, 미공개 언어/지역 선택을 검증한다. 남은 점수는 **직업/관심 각각**0이어야 시작 가능하다. 배분 결과를 화면에서 임의 보정하지 않는다.

## 8. 위험과 가장 어려운 결정

### 결정 1: 아시나의 원작 인물을 지키면서 숫자를 정하는 방법

권고·채택: 간편 생성의 고정 배열과 기능 배분을 사용한다. 최고 특성은 외모보다 원작에서 반복 수행을 확인한 민첩80, 외모70. 숫자는 원작 사실이 아닌 해석임을 명시한다. 귀족 신분을 화면에서 먼저 설명하지 않고, 고정 시트의 장점은 플레이로 드러나게 한다.

기각: 아시나도 주사위를 굴려 외모/교육 하한을 적용하거나 값을 교환하는 방식. 사용자 최종 결정과 맞지 않으며 낮은 굴림을 막기 위한 보정이 인물의 정체성 대신 시스템을 드러낸다.

위험: 높은 열쇠공은 원작 수행 근거가2화에 있다. 1화 UI에서는 숨기고, 내부 수치 근거와 플레이어 지식을 분리한다. 원작 나이·신장·체중·6~10화 미확인 정보를 만들어 빈칸을 채우지 않는다.

### 결정 2: mixed를 버리고도 실패가 이야기를 멈추지 않게 하는 방법

권고·채택: 목표 달성은 CoC의 이진 결과, 세부 성공 수준은 난이도/대항, 자연 대성공은 작은 추가 이득. 실패 수용/행운/강행을 선택하고 모든 선택은 한 번 해결한 뒤 다음 상황으로 간다. soft/hard를 실패의 부담과 강행 예고로 이동한다.

기각: 보통 성공=기존 mixed, 어려운 성공=hit 같은 일대일 이름 바꾸기. “성공했는데 반드시 대가를 받는” PbtA 규칙이 남고, 영상에서 배운 낮게 굴리기와 실제 효과가 어긋난다.

위험: 기존 miss 효과+대가의 중복 피해, 강행을 새 턴으로 계산한 중복 소모, 무제한 같은 질문. 이를 트랜잭션·eventId·pending 복원·목표별1회 강행으로 해결한다. 밸런스 목표가 아직 실측되지 않았음을 분명히 한다.

### 결정 3: 구글시트처럼 많은 정보를 보여 주면서 원작 공개 순서를 지키는 방법

권고·채택: 필드와 계산은 동일한 표에서 읽되 **공개된 데이터만 서버 DTO에 싣는다**. 의심은 숨은 변수, 귀찌는3화 수첩·4화7일 트랙, 현재 배경은1화 정보만. 변화 알림도 공개된 HP/SAN/Luck와 실제 보인 관계 반응만 낸다.

기각: 모든 필드를 미리 그려 놓고 `???`·자물쇠·열기 힌트로 숨기는 방식. 숨은 기능이 있다는 사실 자체를 알려 주고, 툴팁/접근성/저장 화면에서 정보가 샌다.

위험: 현재 코드의 본모습 CG 전환·귀찌 소개·lore·GM 요약·ending 문구는 HUD만 숨겨도 남는다. §6 파일별 작업과 비공개 회귀를 함께 완료해야 한다. 3~4화 트리거가 아직 구현되지 않았는데 실제 에피소드가 완성됐다고 보고하지 않는다.

### 추가 위험

- **규칙 안내의 간편화:** QS와 공식 위키는 일부 규칙을 줄였다. 특히 MOV8 고정과 일반 생성 MOV7/8/9, 기능 간편 배열과 점수 배분을 섞지 않는다. 현재 채택 규칙은 §1이 단일 기준이다.
- **이성을 기분 게이지로 쓰는 문제:** 대다수 옛 정신력 대가를 제거했다. SAN 손실을 보여 주려고 원작에 없는 공포 사건을 추가하지 않는다.
- **PC 화면 검증:** 문서만 작성한 현재는 실제 시트·애니메이션의 성능과 가독성을 검증하지 않았다. 구현 레인의 완료 조건에 실사용을 포함했다.
- **프레임 한계:** 저해상도 표본에서 DB/체구 수식, 모든 결과 배너 색, 보너스 주사위 모션, 정확한 효과음은 확인하지 못했다. 영상 관찰과 월흔 지정값을 분리했다.
- **옛 저장:** 진행 보존을 시도하지 않는다. 원본을 보관하고 새 규칙 시작을 명시적으로 선택하게 한다.
