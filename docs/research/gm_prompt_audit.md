# GM 프롬프트·검사 감사: 금지 규칙이 실제로 막히는가

2026-11-05 · 기준 브랜치 `cloud/snapshot-1105` · 모델·그림 없이 `--no-llm` 경로와 단위 시험으로 확인했다.

## 무엇을 봤나

- **읽은 코드**
  - `app/src/gm/gm.ts`(LocalGm: 해석, 대화, 연출, 여우 한마디, 배경 설명, `write` 재시도, 대체 줄, `screen`)
  - `app/src/gm/prompt.ts`(시스템·작업 프롬프트)
  - `app/src/gm/validate.ts`(위반 검사)
  - `app/src/gm/rules.ts`(규칙 해석)
  - `app/src/gm/lore.ts`, `app/src/engine/text.ts`
  - `app/content/lore_wolheun.yaml`의 금지어 사전
- **금지 규칙 다섯**
  1. 원작 미래 기억(스포일러, 다음 장면 원작 대사)
  2. 현실 물건·지명 언급
  3. GM 해설(게임 바깥 말, 진행자 말투, 3인칭 서술)
  4. 이름 노출(남자의 이름·칭호, 아시나의 변장·신분)
  5. 같은 말 반복
- **방법**: 하위 에이전트 셋이 규칙을 나눠 맡아 GM 출력 줄 약 500개와 플레이어 입력 약 80개를 만들었다. 각 줄을 `validateOutput`/`checkLines`, `ruleInterpret`, `LocalGm.screen`, 실제 `Engine` + `LocalGm(null)`에 넣어 돌렸다. 가짜 모델 서버로 `LocalGm.write`의 재시도·대체 줄 경로도 돌렸다. 에이전트가 낸 주장은 따로 스크립트를 짜 다시 돌려 확인했다. 확인한 사례는 `app/tests/gm_prompt_audit.test.ts`에 시험으로 남겼다.
- **표기**
  - **막힘**: hard 위반이라 다시 쓰게 하고, 끝내 못 고치면 작가 대체 줄로 바꾼다.
  - **soft**: 한 번만 다시 쓰게 하고 그대로 낸다.
  - **빠짐**: 위반이 하나도 없다.

## 규칙마다 어디서 막나

| 규칙 | 프롬프트 | 검사(`validate.ts`) | 입력 쪽 |
|---|---|---|---|
| 원작 미래 기억 | "다음 장면의 사건을 미리 쓰지 않는다", 숨길 것은 이름만, 원작 대사 예는 옮기지 말 것 | `spoilers`(사전 + 열리지 않은 숨긴 항목 keys), `reserved_line`(뒤 장면 원작 줄을 정규화해 포함 비교) | `screen()`이 스포일러 든 입력을 여우 말로 돌려보냄 |
| 현실 물건 | "이 세계에 없는 말은 인물이 뜻을 모른다" | `modern`, `realworld` 낱말 목록, 영문·한자·가나·이모지 | `ruleInterpret`가 `modern`이면 세계 밖 행동(absurd) |
| GM 해설 | "게임, 주사위, 판정, 인공지능 같은 바깥 이야기를 하지 않는다", 여우는 반말 | `meta` 낱말, `gm_voice`(여우 줄 끝), 내레이션 `register`(아시나는·그녀), `tense` | 없음 |
| 이름 노출 | "정체를 밝히는 답은 하지 않는다", 남자 secret | `spoilers`, `exposure`(변장 풀림 말), 장면별 `echo_only`(웰든·공녀…) | `refuse.unmask`, `identity` |
| 같은 말 반복 | "이번 판에 이미 한 말"(화자별 마지막 6줄) | `repeat`(한 답 안), `repeat_play`(이번 판 같은 화자), `repeat_earlier`, `echo_input`(속마음이 입력 되풀이) | 엔진의 같은 입력 되풀이 감지 |

## 시험 결과

```sh
cd app
bun test                  # 335 pass, 0 fail (새 시험 파일 45개 포함)
bunx tsc --noEmit         # 오류 없음
bun scripts/input_eval.ts --all   # 222개 입력, 고치기 전과 출력이 글자까지 같음
```

- 새 시험 파일 45개 가운데 15개는 고치기 전 코드(`cloud/snapshot-1105`의 `src/gm`)에서 실패하고 고친 뒤 통과한다. 나머지 30개는 이미 막히던 것과 알려진 빈틈을 적은 것, 그리고 회귀를 막는 시험이다.
- `--no-llm`(`LocalGm(null)`)으로 판 17개를 끝까지 돌려 화면 줄 365줄을 고치기 전과 비교했다. 갈래 5개, 되풀이 입력 9가지, b05_why에서 같은 입력 네 번(욕, 칭호 물음, "저기요")이다. 다른 곳은 하나다. '핸드폰을 꺼낸다'를 되풀이한 판에서 b02 속마음 대체 줄이 전에는 늘 "저 사람들, 신기루는…"이었는데, 이제 "사람이야, 사람!…"과 번갈아 나온다. 줄 글자는 바뀌지 않았다.

## 이번에 고친 검사 버그

모두 시험과 함께 고쳤다. 대본·설정 yaml과 화면 글은 고치지 않았다.

| # | 버그 | 사례(고치기 전) | 고친 곳 |
|---|---|---|---|
| 1 | 여우 줄의 존댓말을 못 잡음. `gm_voice`가 '다' 끝만 봤다 | GM "여긴 죽음의 사막 지르다예요." / "그건 아직 몰라요." / "그렇죠." 모두 빠짐 | `validate.ts` `GM_POLITE`(~요·~죠·~십시오 → hard). "땅이니까."(반말)와 필요·중요·강요 같은 낱말은 뺐다. 여우가 따옴표로 인용한 남의 말("살려 주세요.", "왜요?")은 끝 검사에서 빼고 본다. 이건 '다' 끝 검사에도 같이 건다. 줄 전체가 따옴표면 그 안을 본다 |
| 2 | 띄어쓰기를 지우고 맞춰 두 낱말에 걸친 우연이 금지어로 걸림 | "자 해보자!" → 자해(hard), "이런 일 본 적 없어" → 일본, "물 한 국자" → 한국, "작은 발자국" → 은발, "불기 차가운 밤" → 기차 | 바깥 이야기·현대 물건·현실 지명·스포일러·변장 노출은 `forbiddenIn()`으로 본다. 두 글자 낱말은 붙여 쓴 그대로만 보고, 띄어 쓴 낱말과 세 글자 이상 낱말("베 히 다 트", "스마트 폰")은 전처럼 띄어쓰기를 무시한다. 대가로 "폐 하", "국 왕", "은 발"처럼 띄어 쓴 두 글자 낱말은 이제 빠진다. 등급 낱말(욕·선정·잔혹·자해)은 일부러 띄어 써 피하는 일("시 발", "섹 스", "자 살")이 흔해 `ratingIn()`으로 전처럼 띄어쓰기를 무시하고, 확인된 우연 "자, 해 보자/볼까/봐요"만 빼고 본다 |
| 3 | 같은 오탐이 입력 해석에도 있음 | 입력 "자 해볼까"가 `deflect`(등급 밖)로 돌려짐 | `rules.ts`는 `ratingIn`, `LocalGm.screen`은 `forbiddenIn` 사용. 띄어 쓴 "섹 스 하자", "자 살 할래" 같은 입력은 전처럼 돌려진다 |
| 4 | 지난 입력·해석 요약으로 스포일러·노출 검사가 면제됨. `playerText`에 `state.said`(최근 12개)와 `deed`가 들어 있다 | 끼어들기 입력 "베히다트 맞죠?"는 `screen`을 거치지 않고 `said`에 남는다. 그 뒤 12턴 동안 남자 "그래, 내가 베히다트다."가 빠졌다. deed "폐하께 하듯 절했다" → 남자 "폐하라고?"도 빠짐. 지난 말 "전 은발도 아니고" → 내레이션 "은발이 쏟아졌다"도 빠짐 | `validate.ts` `inputDid`. 스포일러·변장 노출은 이번 입력(`opt.input`)에 든 말만 면제한다. 인물이 방금 들은 말을 되받는 것("은발? 무슨 헛소리지.")은 그대로 허락한다 |
| 5 | 한 답 안의 반복을 원문 그대로만 비교함 | "하. 웃기는 여자군." + "하, 웃기는 여자군!" 빠짐. 똑같은 줄 둘도 soft라 끝내 둘 다 화면에 나옴 | 정규화한 글로 비교. `dropRepeats`가 같은 화자의 뒤 줄을 빼고 soft `repeat`을 남긴다 |
| 6 | `polish()`가 상대 인물 줄 앞 "하."를 지우는데, 반복 검사는 지우기 전 글로 봄 | 이미 한 "그 입은 쉬지를 않는군."을 "하. 그 입은…"으로 쓰면 통과하고, "하."가 지워져 같은 줄이 다시 나옴. 한 답의 "하. 웃기는 여자군." + "웃기는 여자군."도 화면에서 같은 두 줄이 됨. 원작 "하. 웃기는 여자군."의 "하." 뺀 줄도 앞당김 검사를 빠짐 | `repeat`·`dropRepeats`·`repeat_play`·`reserved_line`이 맨 앞 "하."(·"하,")를 떼고도 비교. "하."뿐인 줄은 떼지 않고 그대로 비교한다 |
| 7 | 끼어들기의 곧 나올 짧은 줄(2~4글자)이 아무 글에나 든 낱말로 막음 | 곧 나올 줄이 "여자."면 "입을 닫아라, 여자."가 hard로 막힘 | 다섯 글자보다 짧은 원작 줄은 줄 전체가 같을 때만 본다(`reservedFor`가 이미 다섯 글자 미만을 버리는 것과 맞춤) |
| 8 | 대화 대체 줄 고르는 차례가 두 줄짜리 묶음에서 늘 같은 줄. `talks`와 `said.length`가 한 턴에 같이 1씩 늘어 합이 2씩 뛴다. 어느 줄에 갇히는지는 지난 입력 수의 홀짝에 달렸다 | b05_why 돌려 막기 두 줄 중 한 줄만 되풀이. b02 속마음 대체 줄도 한 줄만 | `gm.ts` `pickFallback()`: 이번 판에 아직 하지 않은 줄 가운데서 `talks`로 돌린다 |
| 9 | 대체 줄은 검사를 안 거쳐 이번 판에 한 말이 다시 나옴 | 모델이 세 번 반복 위반 → 대체 줄이 바로 그 반복한 줄 | `talk()`와 `quip()`이 이미 한 말을 먼저 뺀다. 묶음을 다 썼으면 가장 오래전에 한 줄을 고른다. 같은 입력 되풀이로 `talks`가 2씩 뛰거나 끼어들기로 그대로여도 한 줄에 갇히지 않는다 |
| 10 | 즉흥 행동이 끝내 실패하면 해석 요약(deed)이 검사 없이 내레이션 줄로 나옴 | 입력 "휴대폰을 꺼낸다"의 deed "휴대폰을 꺼내 들었다"가 그대로 화면에 나옴 | `narrateFallback`: deed에 금지어·변장 노출 말이 있으면 그 요약을 쓰지 않고 대본 대체 줄로 간다 |
| 11 | 프롬프트와 검사가 어긋나 다시 쓰기 한 번을 날림 | 검사는 나레이션·속마음의 지난 말도 hard로 막는데, 프롬프트 "이미 한 말"에는 인물 대사만 적었다 | `prompt.ts` `spokenRule`: 여우를 뺀 모든 화자의 마지막 6줄 |

## 아직 빠져나가는 표현과 고칠 방향

### 1. 원작 미래 기억 · 이름 노출

| 빠지는 표현 | 왜 | 고칠 방향 |
|---|---|---|
| "**사막 대국의 왕** 앞에서 감히." | 프롬프트의 남자 `secret`이 "사실은 사막 대국의 왕이다"인데, key는 "사막의 왕" | `secret`을 "신분이 매우 높다"처럼 바꾸거나 key에 "대국의 왕" 추가(설정 yaml, 내용 담당 승인 필요) |
| "왕인가", "왕이었", "왕이지", "왕이냐", "왕께서", 임금, 군주, 주군, 술탄, 전하 | key가 "왕이다·왕이시·왕이야·왕이라" 네 꼴뿐 | key 추가. "전하"는 "전하다"(전달)와 겹치니 `전하(?=[,께의여!?.\s]|$)`처럼 경계를 두는 코드 검사가 낫다 |
| "베히·다트", "베-히다트", 전각 점·폭 없는 공백 | 띄어쓰기만 지운다 | 사람 이름 key만 `normalizeKo`로 비교. 짧은 key까지 하면 오탐이 는다 |
| "귀찌를 빼냈다/풀었다/뜯었다", "머리카락이 은빛으로", 은색으로, 백발, 정체가 드러, 원래 모습 | `exposure` 목록이 "귀찌를 뺐", "은빛 머리" 같은 한 꼴뿐 | `exposure`에 꼴을 더하거나, `refuse.unmask.words`를 노출 검사에 자동으로 합친다 |
| 남자 "공녀라. 그럴듯하군", "크롬웰 대공가의 딸"(r2_bind, r4_prove, r5_claim) | 이 장면들의 `echo_only`에 공녀·대공이 없다 | `scenario.identity.words`를 모든 장면의 echo_only로 합친다. 대본 yaml 승인 필요 |
| "북쪽 귀족 아가씨", "크롬웰 귀족의 말씨", "이 땅의 주인" | 바꿔 말한 것이라 낱말 목록으로는 못 막는다 | `checkState`의 예/아니오 판정처럼 "이 글이 남자의 왕 신분이나 아시나의 귀족 신분을 드러내는가?"를 묻는 뜻 검사 |
| "하. 웃기는 여자로군.", "대체 어디가 아름답다는 거지?", "남는 건 살아남는 자와 죽는 자뿐이다." | `reserved_line`은 정규화한 원작 줄 전체가 들어 있어야 한다. 조사 하나만 바뀌어도 빠진다. 원작 대사 예와 가치관에 뒤 장면 줄이 그대로 있다 | 여덟 글자 이상 줄은 `longestCommon / 줄 길이 ≥ 0.8`이면 앞당김으로 본다. 프롬프트 원작 대사 예에서 뒤 장면 줄은 빼고 말투만 남긴다 |
| deed "고개를 숙이고 눈을 감았다" → 뒤 장면 "잠깐 눈을 감았을 뿐인데, 달이…" 면제(soft) | `preemptedBy`가 네 글자만 겹쳐도 "플레이어가 먼저 한 일"로 본다. 겹친 것이 "었을뿐이", "을잃었다" 같은 어미여도 그렇다. 대본 예시로 돌리면 면제 쌍이 11개 나온다 | 겹침 기준을 `max(6, 줄의 40%)`로 올리고, 바로 다음 장면 줄만 면제한다. 면제된 줄은 `repeat_earlier`가 아닌 자기 규칙 이름으로 남긴다 |
| **끼어들기 입력은 `screen()`을 거치지 않는다** | `Engine.interject`가 되돌림 검사를 부르지 않는다. 이번 수정으로 다음 턴부터는 막지만, 그 턴에는 이번 입력이라 면제된다 | 엔진(`engine.ts`) 쪽에서 끼어들기도 `screen`/`bounce`를 거치게 한다. 이번 범위 밖이라 고치지 않았다 |

### 2. 현실 물건

| 빠지는 표현 | 고칠 방향 |
|---|---|
| 총구, 총성, 총소리, "총 따위", "총은/총이/총에" | `총을/총으로`만 있다. 코드 정규식 `(?<![가-힣])총(?=[이은을에으구성소알과도]|\s|$)`(총명·총총·총각 제외) |
| 전화, 폰, 라이터, 배터리, 충전, 지하철, 헬리콥터, 유튜브, 손목시계, 와이파이, 콜라, 냉장고, 에어컨, 손전등, 구급차, 트럭, 드론, 선글라스 | `modern`에 추가(설정 yaml) |
| 도쿄, 뉴욕, 런던, 사하라, 이집트, 아라비아, 하나님, 예수, 교회, 성경, 십자가, 부처, 불교, 알라, 술탄 | `realworld`에 추가. 술탄은 칭호라 스포일러 key 쪽이 맞을 수 있다 |
| 입력 "총 쏜다", "라이터를 켠다", "하나님께 기도한다", "도쿄로 간다" | `ruleInterpret`가 세계 밖 행동으로 못 읽는다. `realworld`는 아예 안 본다. LLM 해석이 없으면 보통 행동으로 판정된다. 입력 분류 평가(`input_eval.md`)와 함께 정한다 |

낱말 목록은 끝이 없다. 연출·대화 출력에 "이 세계에 없을 물건이나 장소를 말하는가?"를 묻는 값싼 예/아니오 검사를 더하는 편이 길게 보아 낫다.

### 3. GM 해설

| 빠지는 표현 | 고칠 방향 |
|---|---|
| 게임, 장면, 턴, 선택지, 확률, 수치, 원작, 웹툰, 작가, 독자, 캐릭터, 엔딩, 시나리오, 레벨, 스탯, 세이브, 진행자, 튜토리얼, 인벤토리, 퀘스트, 호감도, "의심이 2 올랐다" | `meta`에 추가. 게임·턴·장면은 낱말 경계를 두고(패턴, 유턴) 내레이션·인물 줄에만 건다. "규칙"은 남자의 원작 대사("규칙이고 율법이")에 있으니 넣지 않는다 |
| 내레이션 "아시나도/아시나한테/아시나와/공녀는/그 여자는", 속마음 "그녀가" | `register.forbid_words`가 몇 꼴뿐이다. `opt.playerLore`로 `아시나(?!요)` + 조사·공백 정규식을 만들어 내레이션에 건다 |
| 내레이션 "당신은 칼을 피했다" | 2인칭 서술 검사가 없다. 따옴표 밖 문장 앞 "당신/너는/네가"를 내레이션에서 막는다 |
| 여우 배경 설명이 지어낸 사실("크라차의 영주야", "사흘이면 가") | 아는 내용(`note.text`)에 근거했는지 보는 검사가 없다. `answersYes`로 "이 답이 아는 내용에 없는 사실을 말하는가?"를 묻거나, 답을 `note.say` + 짧은 맺음말로 좁힌다 |
| 여우 한마디 "대공가 따님", "은빛 머리가 다 보이겠어" | `QUIP_UNSAID`(미소녀·공녀·은발·웰든)에 대공·크롬웰·은빛이 없다. 노출 검사는 여우 줄을 건너뛴다. 걸려도 피드백이 "판정 결과와 어긋나는 표현"이라 엉뚱하다. 자기 규칙 이름(`quip_unsaid`)을 준다 |

### 4. 같은 말 반복

| 빠지는 표현 | 고칠 방향 |
|---|---|
| 지난 "웃기는 여자군." → "정말 웃기는 여자군." / 지난 줄 + 한 문장 | `repeat_play`는 정규화한 줄이 똑같을 때만 막는다. 같은 화자에 `longestCommon ≥ max(6, 짧은 줄의 80%)`이면 soft `repeat_play_near` |
| 속마음이 남자의 지난 말을 되풀이 | 화자별 비교다. 드물어 그대로 둬도 된다 |
| 연출 대체 줄(`typedFallbackLines`, `neutral`)과 배경 설명 대체 줄이 이번 판에 나온 줄을 다시 냄 | 대화·한마디만 고쳤다. `write`가 대체 줄을 낼 때 `spoken`·`reserved`로 한 번 거르는 도우미를 두면 모두 막힌다 |
| b05_why `talk_fallback`이 한 줄뿐("묻는 말에나 답해라."), b08 대체 줄이 "……"뿐 | 모델이 실패할 때마다 같은 줄이다. 대본에 대체 줄을 더한다(대본 승인 필요) |
| 긴 입력과 여섯 글자 겹친 속마음 줄("…죽을 수는 없어")을 말없이 뺌 | `dropEchoThoughts`가 입력 길이만 본다. 겹침이 속마음 줄 길이의 60% 이상일 때만 뺀다 |
| 나레이션이 자기 지난 줄("칼끝이 멈췄다.")을 다시 쓰면 hard | 이번에 프롬프트에 알려 주게 했다. 짧은 내레이션은 되풀이돼도 자연스러우니 나레이션·속마음은 soft로 낮추는 것도 검토한다 |

### 5. 판정 결과(곁가지)

판정 실패(miss)에 "거짓말이 통했다", "먹혔다"가 빠진다. 반대 낱말이 "성공했·해냈다·완벽하게" 셋뿐이다. "통했·먹혔·제대로 맞"을 더한다.

## 오탐(막지 말아야 할 것을 막음). 이번에 못 고친 것

| 줄 | 걸린 규칙 | 고칠 방향 |
|---|---|---|
| "그 왕 이야기는…", 입력 "왕 이야기 좀 해 줘요"(screen이 "웹툰 봤구나"로 돌려보냄) | spoilers 왕이야 | 세 글자 key라 띄어쓰기를 무시한다. "왕이야"를 `왕이야(?!기)`로 좁힌다 |
| "모래가 버스럭거렸다", 입력 "버스럭 소리를 낸다"(세계 밖 행동) | modern 버스 | `버스(?![럭스])` |

## 승인이 필요한 일

- 위 표의 낱말 추가와 장면 echo_only·대체 줄 추가는 `app/content/*.yaml`(설정·대본)을 바꾸는 일이다. 다른 세션과 겹칠 수 있고 대본 승인이 필요해 이번에 고치지 않았다.
- 이번 수정으로 화면 글자가 바뀐 줄은 없다. 대체 줄을 고르는 차례만 바뀌었다(위 "시험 결과" 참고). 모델이 있을 때는 검사가 더 막거나 덜 막아 다시 쓰기·대체 줄로 가는 빈도가 달라질 수 있다. 이건 모델 없이 재지 못했다.
