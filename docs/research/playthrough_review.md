# 결말 11개 갈래 플레이 검토 (--no-llm, 2026-11-05)

원작 「월흔」도 TRPG 도 모르는 사람이 처음 하는 것처럼, `--no-llm` 경로로 결말 11개에 닿는 대표 갈래를 모두 실제로 돌려 화면 글 전체를 적고 줄마다 평가했다.
**이 문서는 평가만 한다. 화면·게임 글과 코드는 하나도 고치지 않았다.** 글 고침은 7절에 `어디 · 전 → 후` 제안으로만 적었다(사용자 승인 필요).

- 재생 기록(화면 글 전체): [`playthrough/transcripts/`](playthrough/transcripts/) — 갈래 20개 + 화면 고정 글 1개
- 재생기: [`playthrough/run_playthrough.ts`](playthrough/run_playthrough.ts), 갈래 입력: [`playthrough/plays.ts`](playthrough/plays.ts)
- 표의 `03:94` 는 `transcripts/03_spy.md` 94번째 줄이다. yaml 줄은 `app/content/ep01_desert.yaml`, lore 는 `app/content/lore_wolheun.yaml`.

## 0. 한눈에

1. **결말 11개 모두 닿는다. 다만 `x_reckless`(칼 앞에서)는 --no-llm 으로는 닿지 않는다.** 위험(attack) 판단은 LLM 해석만 내리고, LLM 이 늦거나 실패해도 사라진다(gm.ts:126-142, 194). 그래서 입력 한 줄만 "LLM 이 attack 으로 읽었다"고 대신 적어(대역) 확인했다.
2. **엔진의 안전장치 세 개가 실제로 뚫린다**(5절 K1~K3, 모두 실제 seed 로 재현).
   - 판정으로 장면이 넘어가면 '한 번 실패로는 안 끝난다'는 보호가 걸리지 않는다. 첫 경고와 작은 끝이 같은 턴에 온다(18, 16).
   - 결말 장면으로 들어갈 때는 작은 끝 검사가 없다. 의심 10, 귀찌 0 인 채로 보통 결말이 난다(19). 무작위 6000판 가운데 의심 10 이상으로 보통 결말이 난 판이 244판, 귀찌 0 으로 보통 결말이 난 판이 28판이다.
   - '머뭇'이 장면을 넘어 쌓이고 경고는 한 판에 한 번이다. 다른 장면에서 새 경고 없이 쓰러진다(17).
3. **막히면 늘 쓰러진다.** 말만 하거나 현대 물건을 꺼내면, 기본 행동으로 판정이 굴러가는 길에는 닿지 않고 '모래 위에서'로 끝난다(13·14). 문서 `docs/branches.md:74·76` 이 약속한 "받고 진행한다", "다음 판정으로 넘어간다"와 다르다. LLM 이 켜져 있어도 같다.
4. **곁가지 갈래의 마지막 판정은 결말을 바꾸지 않는다.** 결박·해 질 녘·증명·신분 장면이 그렇다(r2_bind·r3_dusk·r4_prove·r5_claim 의 outcomes 에 next 가 없다). 결과는 수치로만 남고, 그 수치가 작은 끝 문턱에 닿을 때만 영향이 있다.
5. **원작 흐름의 두 결말(흥미로운 여자·살아남은 자)은 보이지 않는 집착 4 하나로 갈린다.** 단추만 무작위로 누르면 '흥미로운 여자'는 2.7%, '수상한 이방인'은 27.7% 로 가장 흔하다(3절).
6. **처음 하는 사람이 가장 헷갈릴 화면 장치**는 세 가지다.
   - 행운 창: 무엇이 되는지(합 7, 대가 있는 성공)가 없다.
   - 장면 검사 줄: "긴장 3 · 주사위 6 → 그대로"가 무슨 뜻인지 설명이 없다.
   - 수치: 이유 없이 바뀐다. b04 에 들어가면 의심 +3, 판결 장면에서 귀찌 −1 이 붙는다.
7. **크롬웰 귀족이라고 털어놓아도 위험하지 않다**(08). 여는 글의 "공녀라는 게 들키면 끝이다"와 맞지 않는다.

## 1. 방법

### 돌린 것

- **`docs/research/playthrough/run_playthrough.ts`**: `Engine(scenario, new LocalGm(null, lore), clock, luckPrompt=true)` 로 엔진을 돌린다. 이것은 `./run.sh --no-llm` 이 띄우는 서버(server/main.ts:210)와 같은 구성이다. 엔진이 내는 사건을 `web/main.ts` 가 보여 주는 모양 그대로 적는다.
  - 대사·속마음은 괄호로, 내레이션, 🦊 GM 말상자를 구분한다. 효과음·그림·화면 효과는 줄 끝에 붙인다.
  - 주사위 창은 식·등급·설명 글, 대가 줄은 꼬리표 — 글, 장면 검사는 긴장·눈·결과로 적는다.
  - 알림(토스트), 확인 창, 입력 자리(안내 글, `예:` 안내, 단추와 능력치), 행운 창, 결말 카드, 결과 화면(돌아보기 포함)도 적는다.
  - 기록에 붙은 "(남은 행운 n)"은 기록 도구가 덧붙인 글이다. 행운 창에는 없고 위쪽 행운 칸에만 보인다.
- **`plays.ts`**: 갈래마다 seed, 비트별 입력(직접 친 글·단추·행운 창 답·확인 창 답·🦊 질문)을 적는다. 재생기는 끝에 목표 결말에 닿았는지 확인한다.
- **그림과 LLM 모델은 저장소에 없어서**, 화면 그림은 `〔그림 cg_…〕` 처럼 이름으로만 적었다.

```sh
cd app && bun ../docs/research/playthrough/run_playthrough.ts      # 20갈래 모두 ok (목표 결말 도달)
```

### 검토 과정

1. 갈래 묶음 5개(A 원작 흐름·단추, B 의심·귀찌, C 도주, D 거래·신분·그만두기, E 작은 끝·엉뚱한 입력)를 하위 에이전트 5개가 나눠 읽었다. 원작을 모르는 사람의 눈으로 줄마다 지적했다. 160행이 나왔다(A 30, B 36, C 26, D 34, E 34).
2. **교차 검증**: 다른 하위 에이전트 3개가 지적마다 기록 줄·인용·yaml·코드를 대조했다. 재생기를 다른 seed 로 다시 돌려 '확인/고침/틀림/중복'을 매겼고, 놓친 문제를 '추가'했다.
   - 합계: 확인 118 · 고침 31 · 틀림 1 · 중복 10 · 추가 8 (A·E 64행, B 36행, C·D 60행)
3. **직접 재검토(1차)**: 검증 에이전트의 '추가' 8건 가운데 엔진 동작 5건을 재생기 갈래(16~20)로 다시 재현했다.
   - 재현한 것: K1·K2·K3, 2번째 맨손 공격, 도주 중 은발.
   - 상태를 직접 고친 재현(난수 바꾸기)은 쓰지 않았다. 무작위 단추 탐색으로 그 일이 실제로 나는 seed 를 찾아 넣었다.
4. **직접 재검토(2차)**: 기록 도구 자체의 빈틈 두 가지를 고쳤다. 줄 수는 그대로라 인용한 줄 번호는 유지된다.
   - 내레이션 줄의 효과음·그림을 적지 않았다. 그래서 "칼을 뽑는 장면이 화면에 전혀 없다"는 지적이 과장됐다.
   - 결과 화면 돌아보기의 주사위 줄을 줄여 적었다. 그래서 "행운을 쓴 숫자가 어긋난다"는 지적이 잘못 나왔다.
   - 두 지적은 고친 기록을 기준으로 다시 판정했다.
5. **최종 교차 확인**: 이 문서에 넣은 줄 번호는 모두 고친 기록에서 다시 맞췄다. '--no-llm 한정' 표시는 gm.ts·engine.ts 로 범위를 다시 확인했다(아래 '범위' 칸).

### '범위' 칸의 뜻

- **공통**: LLM 이 켜져도 같다(작가 고정 줄·엔진 규칙).
- **--no-llm**: GM 이 글을 쓰지 못해 대체 줄을 쓸 때만 생긴다. LLM 이 쓰기에 실패할 때도 같다.
- **단추**: 접근 단추를 누를 때 생긴다. LLM 이 켜져 있어도 같다.
- **LLM 켜짐**: LLM 해석이 있어야 생긴다. 대역으로 재현했다.

## 9. 확인하지 못한 것

- **LLM 이 켜진 실제 화면.** 모델이 저장소에 없다. GM 이 판정 결과를 풀어 쓴 글, 엉뚱한 입력에 대한 인물 반응, 🦊 답의 LLM 판은 보지 못했다. '--no-llm' 표시가 붙은 지적은 LLM 이 켜지면 줄어들 수 있다. 다만 LLM 쓰기가 실패하면 같은 대체 줄이 나온다.
- **x_reckless 를 LLM 이 실제로 attack 으로 읽는지.** 12·20 은 대역이다. 어떤 입력을 얼마나 자주 attack 으로 읽는지는 모른다.
- **그림·화면 연출.** assets 가 없어 CG·입식·배경·주사위 애니메이션·컷인은 이름으로만 확인했다. 화면 크기에 따른 줄바꿈, 글자 찍는 속도, 실제 플레이 시간(분)은 재지 않았다.
- **브라우저로 직접 클릭.** `./run.sh --no-llm` 서버를 띄우지 않고 같은 엔진·GM 구성을 직접 돌렸다. 서버의 저장·불러오기, 이야기 지도, 끼어들기(대사가 흐르는 중 입력)는 이번 갈래에 넣지 않았다.
- **2~10화 원고와의 대조.** 원작 설정이 맞는지는 lore 사전 범위에서만 봤다.
