# 숨긴 이름의 어휘 경계 수리

2026-11-09. 공유 GM 검수의 원인·수정·집중 증거다. 실제 모델 생성이나 별도 비문 수리 완료 보고가 아니다.

## 원인

원시 `work/continuation/qa/real-1794206518713/canonical_first.jsonl`의 행동4 narrate 시도1~3을 직접 읽었다. 세 후보의 “목을 짓누르던”은 각각 `lore/spoilers: 누르` hard 반려였다. 누르라는 인물을 지시한 문장이 아니다.

`forbiddenIn`은 일반 금지 묶음에 사용하는 부분문자열 includes 검사다. 고유명사도 여기에 태워 단어 내부의 누르를 이름으로 처리했다. 추가로 출력 검수의 입력 면제도 mentions를 사용해, 플레이어가 “짓누르던”이라고 쓴 것만으로 GM의 실제 “누르가 다가왔다” 유출까지 면제하는 반례가 있었다.

## 수정

수정 파일:

- `app/src/gm/validate.ts`
- `app/src/gm/gm.ts`
- `app/tests/name_boundary64.test.ts`

정본 인물의 id/alias/names, 장소와 그 정본 표기 별칭으로 고유명사 여부를 판단한다. 이 이름에만 Unicode 문자 경계와 이름 뒤 조사·호칭·서술격 결합을 확인하는 properNameIn을 적용한다. 특정 인물이나 “짓누르던” 같은 단어를 예외 목록에 추가하지 않았다. 다른 이름을 정본에 추가해도 같은 문법 경계를 사용한다.

입력 screen, 출력 spoilers 검수, 플레이어 입력의 이름 되받기 면제, 즉흥 deed의 보호어 검수가 같은 비교를 사용한다. 일반 활용형은 이름 면제를 열지 않으며 실제 이름을 먼저 말한 입력의 기존 되받기 정책은 유지한다.

스포일러에는 이름 이외에 사건·동사구도 섞여 있다. 첫 접근에서 모든 spoilers에 명사 경계를 적용하자 기존 “감옥에 처넣어라” 등 비이름 보호가 빠지는 회귀가 발견됐다. 이름과 비이름을 정본 메타데이터로 구분하는 쪽으로 바꿨으며 해당 단언은 완화하지 않았다. 현대 물건·현실 지명·등급·변장 노출과 비이름 스포일러의 기존 비교는 그대로다.
