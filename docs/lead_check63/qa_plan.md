# 63차 실제 브라우저 스토리 QA 실행 계획

현재 상태: 실행기 준비 단계. 62차 코어 반영 전 서버에서는 최종 QA를 실행하지 않는다. 18191/18192 서버 준비와 코어 배포 완료는 별개다. 서버 시작·종료·사용자 포트 18080/18081 조작 기능은 실행기에 없다.

## 실행

저장소 루트에서 구문 준비와 타입 검사:

```bash
tsc --project work/demo-slice/lane63/tsconfig.json --pretty false
bun work/demo-slice/lane63/prepare.ts
node --check work/demo-slice/lane63/runner.mjs
```

리드가 새 코어 반영 완료를 알린 뒤 전체 실행:

```bash
bun work/demo-slice/lane63/prepare.ts --run --parent-ready --round round63-01
```

한 경로 재검증과 후보 시드 변경:

```bash
bun work/demo-slice/lane63/prepare.ts --run --parent-ready --route avoid-mixed --seed 2 --round round63-avoid-02
```

`--logs`에는 부모가 지정한 `work/` 아래 격리 서버의 실제 `WOLHEUN_LOGS` 폴더를 붙인다. 이 옵션이 있으면 해당 브라우저 세션의 원본 로그를 함께 복사하고 호출별 지연·attempts·violations·fallback·최종 생성 줄을 기록한다. 없으면 결과 화면이 실제 요청한 `/api/result` 응답의 호출 수·재생성 수·대체 수·총 지연·평균 지연·대체율만 기록한다. 사용자 로그 폴더를 이 옵션에 넣을 수 없다.

실행은 에고 전용 작업 공간 하나, 1440×900 탭 하나에서 진행한다. 입력은 `fill`과 `click`, 진행은 화면 단추로만 한다. 시드는 앱이 이미 지원하는 주소 매개변수를 쓴다. API를 직접 호출해 플레이하거나 저장 상태·주사위·수치·장면을 주입하지 않는다. CDP는 창 크기, 이 탭 미디어 음소거, 실제 요청 관찰에만 사용한다. 화면의 일시 표시를 놓치지 않도록 읽기 전용 DOM 관찰 버퍼를 둔다. 게임 상태에는 쓰지 않는다.

## 경로와 근거

최소 11판은 결말 경로 8개 + 첫 플레이어 1개 + 특수 입력 1개 + 사용자 판 1개다. 피함 mixed 추가 1판, 문법 품질 8판을 포함해 현재 기본 목록은 20판이다. 최소 개수를 채웠다는 이유로 미실행 입력이나 결말 불일치를 통과시키지 않는다.

기존 자유 입력 중 서술형 행동은 괄호로 감싸고, 말과 행동이 섞인 문장은 행동 부분만 감쌌다. 접근법 단추는 실제 화면의 `data-id`로 누른다. 행운은 쓰지 않는다. 큰 행동 해석 확인은 의도대로 한다는 단추를 누르고, quit 판 외 그만두기 확인은 계속한다. 예정에 없는 선택지는 자동으로 첫 항목을 고르지 않고 중단한다.

시드는 코어·판정 소비 순서가 바뀌면 결과가 달라진다. 특히 survivor와 avoid hit/mixed는 현재 후보이며 실제 26B 검증을 하지 않았다. 목표 tier·경로·결말이 다르면 실패로 남기고 `--seed`로 재검증한다. 목표를 관찰값으로 덮어쓰지 않는다. 특수 입력 판이 여섯 입력 전에 끝나도 성공으로 처리하지 않는다.

줄별 원작 출처는 YAML `cut`의 PSD 범위를 기록한다. 대본과 정확히 일치한 줄에는 현재 대본의 화자·문장·요구 CG도 함께 둔다. 즉흥 줄은 원작 문장과 같다고 주장하지 않는다. 정확한 c번호가 없는 줄은 `대본에 원작 컷 미기록`으로 남기며 임의로 c번호를 붙이지 않는다. 화면에 공개되지 않은 내부 플래그·비밀 정보는 수치처럼 추정해서 적지 않는다.

CG 식별자는 실제 보이는 레이어의 이미지 주소를 실제 매니페스트 응답과 대조한다. CG 전환 레이어도 함께 기록한다. b04의 연속 사진 3장·무음 영상과 최종 원작 대조는 부모 담당이다. 실행기는 줄별 CG·대사 짝과 빈 줄을 찾는 별도 근거만 제공한다.

## 직접 읽을 기준

모든 transcript를 처음 하는 사람 관점에서 읽고 qa_issues와 language_review를 작성한다. 활용·조사·시제·주어/서술어 호응·띄어쓰기·번역투·독백/말의 문체를 줄마다 보고, 원작 인물의 기존 말투와 나란히 대조한다. 자동 낱말 치환이나 rejected 문장만 통과시키는 수정은 하지 않는다. 화면 원문은 보존하고 리드의 프롬프트·스키마·생성 검증 수정 뒤 새 회차 실제 26B 결과와 비교한다. 모델 거절 초안이 로그에 없으면 교정 전 초안을 봤다고 쓰지 않는다.

이야기 검수는 하지 않은 행동 전제, 물건·후드·부상·시간 모순, 필요 없는 입력·판정, 같은 물음 반복, 큰 행동을 무관한 한 줄로 넘김, 인물 말투 이탈, GM 훈수·스포, 비밀 조기 공개, 대체 줄·침묵, 그림과 대사의 시점 불일치를 포함한다. 자동 후보가 0이어도 사람이 검수하지 않았으면 통과가 아니다.

괄호만·말만·혼합·전각·빈 괄호·불일치 괄호·무괄호 행동의 62차 경계 검증은 부모 코어 회귀 결과와 함께 대조한다. 이 실행기의 판별 기록만으로 수정 요청이 내부 턴·소지품을 소비하지 않았다고 단정하지 않는다. 추가 표현은 routes.ts의 입력 배열로 확장하고 같은 화면 기록기를 사용한다.

## 후속 화·분기 맵 연결

연결 계약을 받은 뒤 `--scenario`를 여러 번 지정해 각 화의 원작 컷 메타데이터를 등록한다. `--connections` JSON은 `[{ "id": "...", "route": "natural", "from": "실제 출발 beat", "to": "실제 도착 beat" }]` 형식이다. 화면 장면 방문 순서로 계약을 확인한다. 계약·소스 파일이 오기 전에는 연결 통과를 표시하지 않는다.

이 기능은 연결 지점의 관찰 검증이다. 감옥·2화의 새 자유 입력, 기존 저장 불러오기·중간 저장 재개, 분기 맵의 실제 두 갈래 표시·과거 시점 복원 조작은 각 담당 레인의 최종 화면 계약을 받은 뒤 별도 경로로 추가해야 한다. 현재 사막 입력 계획으로 미구현 후속 화를 완료라고 표시하지 않는다. 사막 탈주 성공자를 후속 감옥으로 강제 연결하면 ACCEPTANCE 위반이다.

## 준비 단계 검증 한계

현재 실행한 검사는 구문·타입 검사뿐이다. 실제 에고 CDP 이벤트 형식, DOM 대기 조건, 실제 26B의 경로 해석, 후보 시드, 특수 입력 완주 가능성, 원작 문장 자연스러움은 리드 준비 신호 뒤 실제 플레이로 확인한다. 자동 후보·미완주·목표 불일치는 실패로 남고, 사람의 문법·스토리 검수는 늘 미완료로 시작한다. 서버를 띄우거나 최종 스토리 QA를 실행하지 않았다. 커밋·코드레빗 요청도 하지 않는다.
