# 실제 질문의 대상·관계 진단

2026-11-09. 모델 호출 없이 보존된 원시 요청·응답과 현재 소스를 읽었다. 질문 수리 소스는 아직 바꾸지 않았으며 아래는 진단과 수정 제안이다. 대실패 구현과 별도 결함이다.

공통 근거 폴더는 `work/continuation/map/run/frame-gemma/`다. `logs/gm-trace.jsonl` 8행, `logs/model-requests.jsonl` 26행을 직접 읽었다. 모델 요청은 chatJson 10회와 예열 3회이고 요청·응답 쌍이 있다. 질문 JSON의 trace는 HTTP 요청·응답이며 실제 모델 trace와 구분했다.

## 실제 실패

| 질문 | 해석·생성 원문 | 결과 |
|---|---|---|
| 지금 우리가 있는 나라는 어디야? / 공개 전 | interpret는 현재 위치 질문이라고 이유를 쓰면서 about=kracha. explain은 “사막 건너 남대륙에 있는 도시, 크라차야.”, violations=[] | 현재 국가 관계를 목적지 도시로 대체했다. |
| 같은 질문 / 공개 후 | about=fesian, 페시안 국가 설명, violations=[] | 공개된 정본과 맞는 내용 통과. 이 한 건이 공개 전 실패를 해결하지는 않는다. |
| 방금 저 둘이 크롬웰의 정보를 캐내자고 한 대화를 아시나도 들은 거야? | interpret 이유는 아시나가 대화를 들었는지에 대한 상황 확인이나 about=strangers. explain 3회 모두 아시나도 들었다고 생성 | 3회 모두 off_topic으로 반려한 뒤 최종 script “일주일 만에 본 사람들이야.”로 대체. 후보와 대체 모두 질문에 맞는 정상 답변으로 세지 않는다. |

공개 전 저장은 권위 state가 ep02_unlock/페시안_앎=true지만 확인된 private frame은 ep02_prison_country/페시안_앎 없음이다. 이것은 정상 시점 분리다. 실제 요청의 system에도 공개 직전의 표시 줄이 들어 있었다. 미래 state를 참조하도록 바꾸거나 hidden 조건을 풀 이유가 없다.

정본 `lore_wolheun.yaml:22`의 kracha는 “사막 건너 남대륙의 도시. 아시나가 가려던 곳”이며 현재 국가의 근거가 아니다. `:70`의 strangers는 사막에서 일주일 만에 본 세 사람이며 궁정 수행원 대화의 청취 여부를 설명하지 않는다.

## 원인

1. `gm.ts:273–277`은 선택한 about가 공개된 note id인지 검사하지만, 그 note가 원래 질문의 대상·관계에 답할 수 있는지 검사하지 않는다. 해석 이유가 현재 위치/청취 여부를 정확히 적어도 반환 구조에는 고른 note id만 남고 그 충돌을 막는 경계가 없다.
2. `buildExplainUser`는 고른 note를 “이 질문의 대상”으로 확정하고 그 대상에 대해서만 답하라고 한다. 실제 모델 요청 id=3은 크라차를, id=7은 사막의 세 사람을 이렇게 받았다. 현재 위치·표시 줄을 별도 설명하는 부분도 about=scene일 때만 추가된다. 이미 잘못 고른 note를 문장 생성 단계가 되돌리기 어렵다.
3. `gm.ts:521–553`의 mustMention은 사람 note의 이름·keys를 기준으로 하고 `validate.ts:346`은 이 낱말 포함 여부를 검사한다. 공개 전 도시 답은 장소이므로 이 조건도 없다. 관객 후보의 반려 이유는 “사막의 세 사람에 대해 답하세요”였다. 즉 실제 질문의 청취 관계가 아니라 잘못 고른 note와의 일치를 검증했다.
4. `gm.ts:583`의 현재 주장 근거 검수는 conversation의 talk에 적용되며 explain의 질문 관계 검수가 아니다. 기존 근거 검수 통과 여부를 이 두 질문의 정합성 증거로 대신할 수 없다.
5. `explainFallback`은 선택된 note의 say/text를 그대로 낸다. 질문이 그 note로 답 가능한지 확인하지 않으므로 모델 후보를 모두 반려한 뒤에도 최종 화면이 무관한 설명으로 바뀐다.
6. 관객 선언은 YAML에 보존돼 있지만 `buildSystem:134`는 “관객 시점이면”이라는 조건문만 보내고 현재 beat.perspective의 실제 값은 명시하지 않는다. 실제 관객 해석 요청은 “지금 아시나 앞에 사람이 있다”라는 일반 facing 문구도 받았다. 화면에 보이는 화자와 아시나 곁에 있는 인물을 구분할 권위 문맥이 부족하다. 표시 줄만 전달했다고 아시나의 청취 사실이 전달된 것은 아니다.

## 제안하는 교정 경계

질문이 요구한 주체·관계·답의 종류와, 공개된 note 또는 확인된 표시 문맥이 그 관계를 실제로 뒷받침하는지를 함께 판단해야 한다. 현재 위치와 목적지, 국가와 도시, 화면에서 본 대화와 주인공이 들은 대화를 구분한다. note가 공개돼 있다는 사실만으로 질문의 답으로 채택하지 않는다.

확인된 장면 시점의 실제 perspective와 표시 줄은 화면 설명의 근거로 제공하되 아시나 기억으로 승격하지 않는다. 관객 장면의 청취 여부는 그 선언·현장 인물·이미 확인된 사실로만 답하고 증거가 없으면 들었다고 단정하지 않는다. 현재 국가를 답할 공개 근거가 없으면 none/모른다는 답을 허용한다.

이 판단은 해석→생성→최종 fallback에 동일하게 적용해야 한다. 잘못된 note로 대상이 고정된 상태에서 장소 설명만 다시 쓰거나, 재시도 횟수를 늘리거나, 국가·관객 낱말 규칙을 추가하는 수정은 원인을 해결하지 않는다. source 명칭과 지식 잠금은 유지한다.

집중 수용 대조는 현재 국가 공개 전/후, 목적지 도시 질문, 같은 지명이 다른 관계에 있는 질문, 관객 대화의 뜻과 아시나의 청취 여부, 증거 없는 질문, 생성 후보가 모두 반려된 fallback이다. 같은 원시 3건만 외워 맞히지 말고 문서 밖 표현도 포함해야 한다. 실제 모델 창은 리드 배정 뒤에만 사용한다.

리드 승인 뒤 소스와 집중 회귀를 적용했다. 현재 구현·분차 증거·실모델 잔여의 정본 인계는 `question_relation64_implementation.md`다. 위 진단의 과거 실제 모델 실패를 새 소스의 성공 증거로 바꾸지 않는다.
