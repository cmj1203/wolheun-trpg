범위: `gm.ts`, `prompt.ts`, `gm.test.ts`, `work/demo-slice/lane63/grammar/`. API 검사만 수행했다. 브라우저 QA는 리드 담당이다. 사용자 서버 18080·18081에 접근하거나 재시작하지 않았다. 커밋·코드레빗 실행 없음.

## 진단과 수정

반려 원문은 `app/logs/159e37ce-e913-4397-a5aa-40bb6f133412.jsonl:27`의 `그렇게 우는다고 목숨이 붙어있나, 이방인.`이다. 기존 `write`는 형식·설정 검사, `reaction`일 때만 말투·입력 반응 검사, 상태 검사 순으로 진행했다. 일반 대화와 짧은 반응 모두에서 용언 활용을 검사하는 단계가 없었다.

26B에 단순 예·아니오 판정을 맡기는 방식은 이 오류를 놓쳤다. 모든 용언의 활용 근거를 먼저 쓰게 하면 일부 표본에서는 잡았지만, 실제 LocalGm 재현에서는 잘못된 활용을 적절하다고 판정했다. 보조 용언의 정상 띄어쓰기를 오류로 보는 경우도 있었다. 이 방식은 채택하지 않았다. 실패를 포함한 원문은 `calibration*.json`, `boolean-evidence.json`, `v1-evidence.json`에 남겼다.

채택한 방식은 생성문 전체에 최소 교열을 요청하고 원문과 대조하는 것이다. 문법·활용·조사·호응·뜻만 교열하며 말투·의미·어휘·문장 파편·허용 띄어쓰기는 보존하도록 한다. 반환 줄 수와 원문 대응을 검증하고, 차이가 있으면 `format/grammar` hard 위반과 교열 차이를 기존 재생성 피드백으로 넘긴다. 교열문을 화면에 대신 출력하거나 단어 목록으로 치환하지 않는다. 문법 검수 실패나 잘못된 응답도 미검수 생성문을 통과시키지 않는다.

기존 반응 검사 뒤, 상태 검사 앞의 공통 생성 경계에 적용하므로 일반 대화·짧은 반응·연출·설명을 함께 보호한다. 기존 입력 경계, spoken/acted, 화자·표정, 반응 검사, 상태 검사를 보존했다. 생성 시도 수는 생성 횟수 그대로이며 검수 호출을 생성 재시도로 세지 않는다. 위반·원문은 기존 trace에 기록한다. 다음 시도 예산 추정에는 생성과 모든 검수에 걸린 시간을 포함한다.

새 회귀는 일반·짧은 반응 모두의 문법 반려와 재생성, 교열 피드백 전달, 표정 보존, 의도적인 단편 유지, 검수 서버 오류·응답 형식 오류의 차단을 확인한다. 문법 fixture와 요청 기록은 별도 채널로 분리해 기존 생성·상태·반응 판정 큐를 소비하지 않는다. 구현 전 일반 대화 회귀는 오류 문장이 1회 만에 통과해 `attempts: 2` 기대와 달리 `attempts: 1`로 실패했다.

## 소스 소유권 반환

검증 완료 후 `gm.ts`·`prompt.ts`·`gm.test.ts` 소유권을 즉시 반환했다. 이후 이 작업에서는 소스 파일을 수정하지 않는다. 최종 API 묶음은 소스를 이미 메모리에 읽은 프로세스로 실행했다. 새 improv goal/state 계약 변경이 병행되더라도 이 보고서의 API 증거는 문법 작업이 반환한 버전을 대상으로 한다.

반환 시점 변경 목록은 `work/demo-slice/lane63/grammar/owned-diff.json`에 있다. 원래부터 큰 파일을 허용 범위 밖으로 분할하지 않았으며, 생성 경계의 검수와 기존 재생성 루프에만 작은 변경을 넣었다. 외부 교열 응답은 `unknown`으로 받아 경계에서 줄 수·원문 대응·문자열을 확인한다. 테스트용 production export나 검사 우회 스위치는 추가하지 않았다.

## 실제 26B API 증거

모델 `gemma-4-26b-a4b`, 주소 `http://127.0.0.1:18192`. `probe.ts`가 실제 `LocalGm.talk`를 호출했다. b06_swing 문맥을 사용했고, 짧은 반응은 엔진과 같이 화자를 남자로 제한했다. 생성·반응 검사·문법 교열·상태 검사는 모두 실제 모델을 사용했다. 해석·주사위·화면 전환을 포함한 Engine 전체 플레이 검사는 아니다.

새 입력 8건은 모두 최초 생성 후 통과했다. 문법 재생성 **0/8**, 대체 **0/8(0%)**, 평균 **8,320ms**, 범위 **4,792~14,670ms**다. 이 묶음의 문법 교열 호출은 평균 **2,981ms**, 범위 **1,056~5,039ms**였다. 이 수치는 관측 표본의 지연이며 원래 반려 기록의 3,682ms와 동일 입력·동일 부하 비교가 아니다.
