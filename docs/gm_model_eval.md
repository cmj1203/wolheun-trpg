# 로컬 GM 모델 비교

고른 모델: **Gemma 4 26B-A4B it MoE (UD-IQ4_XS)**. `app/config/models.json` 의 기본값이다.

## 방법

- 입력: `app/eval/cases.yaml` 의 20개(무효 입력 1개 포함, 답을 쓰는 입력 19개). 비트, 판정 결과, 시드를 모델끼리 같게 고정했다.
- 실행: `bun eval/run_eval.ts <모델키>`. 원시 결과는 `app/eval/results/<모델키>.jsonl`, 요약은 `.summary.json`.
- 말투·비트·자연스러움: 후보 이름을 가리고 케이스마다 순서를 섞은 시트(`app/eval/results/blind_scores.json` 에 풀린 결과)를 채점자 한 명(Claude 하위 작업)이 1~5점으로 매긴 평균이다. 대체된 답은 빠진다.
- 응답 시간은 입력 하나의 해석 + 서술을 합친 시간이다. 장비: MacBook Pro M5 Pro, 메모리 48GB, llama-server, GPU 사용.

## 선정 이유

1. 말투가 1순위 기준이고 26B-A4B 가 가장 높다(4.50). 비트 준수도 가장 높다(4.28).
2. 첫 시도 통과가 89%로 12B(58%)보다 훨씬 높아 다시 생성이 적다. 그래서 전체 시간 중앙값은 비슷해도 p90 이 13.7초로 12B(19.5초)보다 안정적이다.
3. Kanana 와 Qwen 은 더 빠르지만 말투와 비트 점수 차이가 크다. Kanana 는 입력을 받지 않고 길을 다시 묻는 답(c08)이 있고, Qwen 은 문체 위반을 남긴 답이 74%다.

대가와 한계:

- 메모리를 14.7GB 쓴다. 이 맥(48GB)에서는 여유가 있지만 12B(8.5GB)의 두 배에 가깝다.
- 자연스러움은 12B 가 조금 높다(3.95 대 3.78). 해석은 c10 하나를 틀렸다(지도를 꺼내는 입력을 '애원'으로 읽음). 판정은 그대로 진행된다.
- 채점자가 한 명이고 표본이 19개라 26B 와 12B 의 작은 점수 차이는 근소하다. 결정을 가른 것은 첫 시도 통과와 p90 이다.
- 활성 파라미터가 4B 여도 생성 속도는 빠르지 않았다(초당 18.9토큰, 12B 27.4토큰).

체감 시간은 앱에서 줄였다. 주사위를 서술보다 먼저 띄우고, 서술을 기다리는 동안 대사창에 점 연출을 보여 주고, 다시 쓸 시간이 15초 상한을 넘으면 바로 작가 대사로 넘어간다(`budgetMs`). 위 표는 이 상한을 넣기 전에 잰 값이다. 26B-A4B 에서 3번 시도해 35.3초가 걸린 c08 은 이제 첫 시도 뒤 바로 대체된다.

## 해석 규칙 수정 뒤 다시 돌린 결과(26B-A4B)

c10('가방에서 낡은 지도를 꺼내 보여 주며 …')을 '애원'으로 읽던 문제를 고쳤다. 가진 소지품을 쓰는 행동의 키워드가 2개 이상 맞으면 LLM 보다 규칙 해석을 따르고(`ITEM_RULE_MIN_SCORE`), 해석 프롬프트에 소지품 행동을 고르는 지침을 넣고, 가방 행동 예시와 키워드('꺼낸', '펼쳐')를 더했다. 결과는 `app/eval/results/after_interpret_fix/`.

| 항목 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 해석 정확도 | 95% (19/20) | 100% (20/20) |
| 추가로 바뀐 해석 | - | c20 '무효' → '받아치기'(둘 다 정답 범위). 나머지 18개는 같다 |
| 첫 시도 통과 | 89% | 95% |
| 작가 대사 대체 | 5% | 5% (c08) |
| 평균 시도 | 1.16 | 1.05 |

응답 시간(중앙값 13.0초 → 5.9초)과 생성 속도(초당 18.9 → 44토큰)도 달라졌지만 이번 수정 때문이 아니다. 처음 쟴 때는 다른 무거운 작업과 같이 돌았다. 위 모델 비교표의 시간은 같은 조건에서 쟴 값이 아니어서, 모델 간 속도 비교는 대략적으로만 본다.
