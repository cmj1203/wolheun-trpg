# 59d 실제 26B 연속 입력 — 표정 대조

59c와 같은 판(시드 59, 정상 도입 → 달려가 길 묻기 → b05)에서 같은 8개 입력에 문서에 없는 표현 4개(9~12)를 더해 순서대로 넣었다. 시험 복사본은 59c와 같이 b05 3턴·b06 20턴으로 늘리고 의심 10 결말 전환만 유예했다. 실제 콘텐츠는 바꾸지 않았다. 기대 표정은 실행 전에 스크립트에 적었고 실행 뒤 바꾸지 않았다. 시험은 별도 26B(18192)로 돌렸고 사용자 서버(18080·18081)는 건드리지 않았다.

59c 대비 30% 넘게 늘어난 입력은 2건(4번 1.33배, 7번 1.40배)이다.
- 4번: 해석 호출 하나와 대사 호출 하나로 59c와 구성이 같다. 이번에 바꾸지 않은 해석 호출이 같은 프롬프트 토큰 2924개로 6.3초 걸렸다(59c 4.4초). 대사 호출은 1.6초로 59c와 같다. 사용자 서버가 같은 시간에 떠 있었다.
- 7번: 결과 연출 1회차(6.0초)에 reaction_repeat(soft) 위반 두 가지가 있었다. 남자 대사 끝맺음 '-군'이 직전 두 줄에 이어 세 번 연속이었고, 호칭 '여자'도 직전 대사와 같았다. 다시 쓴 2회차(4.0초)는 호칭을 '이방인'으로 바꿨지만 '-군' 끝맺음을 벗어나지 못했고, 최종 화면에는 1회차 줄("죽고 싶어 안달이 났군, 여자.")이 나갔다. 늘어난 시간은 이 다시 쓰기 한 번이며, 앞 줄에서 남자가 쓴 어미·호칭이 59c와 달라서 생긴 일이다(기록: `model_sequential.json` 7번 traces).
- 3·4차에서 6~8번이 느렸던 것은 시험 서버의 프롬프트 캐시가 빗나가 해석 호출이 토큰 6,500개를 처음부터 처리했기 때문이다(1·2·5차는 3,500개). 프롬프트 길이는 59c와 같다(run4_model_requests.jsonl).
