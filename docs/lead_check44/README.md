# 44차 READY

2026-11-06. 변화 기록, 사용한 물건의 대가 우선 선택, 소지품 상태 설명을 구현했다. 커밋하지 않았다.

## 구현

- 공통 `applyEffects`에서 실제 변화량으로 `change` 이벤트와 저장 로그를 만든다. 수치 상·하한에 막혀 변화가 없으면 쓰지 않는다.
- 결과 서술 뒤의 효과 적용 순서대로 이야기 창에 작은 줄을 남긴다. 판정, 대가, 장면 입장·검사, 정체 노출 등 같은 효과 적용 경로를 쓰는 사건에 적용된다. 징조 자체에 효과가 없으면 줄도 없다.
- 수치 이름은 `TRACK_INFO.label`을 쓴다. 따라서 `귀찌 수명 -1`, `탈주 준비도 +1`로 표시한다. 색은 기존 오른쪽 깜빡임과 공유한 `trackTone`을 쓴다. 오른쪽 깜빡임도 유지한다.
- 이야기 창의 줄, 기록 창의 글·색, 저장 화면의 줄을 보존한다. 다음 판정을 시작하면 이야기 창의 이전 변화 줄은 비우며 기록에는 계속 남는다.
- 아직 닫힌 `trackGate`는 효과 적용 시점에 판정한다. 이후 남자를 만났다고 이전에 숨겼던 변화 줄을 소급해서 적지 않는다. 기존 내부 `tracks` 로그는 유지하고, 플레이어에게 보이는 `change` 기록만 거른다.
- `approach.item` 또는 입력에 나온 소지품 이름으로 사용 물건을 찾는다. 해당 장면 표에서 7~9는 같은 물건의 soft, 실패는 hard 대가를 결과별 목록보다 먼저 고른다. 조건·한 번 제한을 지키며, 대응 대가가 없으면 기존 후보 선택으로 돌아간다.
- 물건과 대가의 연결은 `lose`와 해당 소지품의 상태 플래그로 판단한다. 귀찌는 기존 수치 소모를 따른다. 핀의 대가를 새로 만들지 않았다.
- 잃은 물건은 `state.items`에서 빠지고 관련 행동 버튼은 잠긴다. 같은 물건을 쓰는 직접 입력도 판정 전에 막는다. 지도 찢김·가방 상태는 수첩과 HUD 소지품 설명에 붙는다.
- `showLine`의 빈 줄 처리, `.dialog.silent`, `parseLine`, 43차 담당 파일·대사·이름 금지 로직은 바꾸지 않았다.

## 숨긴 수치 변화 수

기준: 수첩 공개 비트를 처음 통과하기 전까지 도달 가능한 비트 그래프에서, 0이 아닌 변화가 선언된 위치를 센다. 기본 즉흥 결과를 각 비트에 적용한 뒤 집계했다. 한 효과가 두 수치를 바꾸면 수치별로 각각 세고, 같은 수치는 같은 효과에서 한 번 센다. 실제 실행 횟수나 한 판의 누적량이 아니다.

|---|---|---:|---|
| 의심 | `수첩:man` | 10 | `b02_people`: 큰 즉흥 mixed·miss, idle, 대가 2곳, 접근 결과 5곳 |
| 집착 | `수첩:man` | 2 | `b02_people.improv_bold` hit·mixed |

## 연구 근거

- PbtA GM 수의 자원 소모는 무기·장비 등을 소비하거나 잠시 못 쓰게 하는 결과를 허용한다. 사용한 물건과 같은 물건의 기존 대가를 우선 연결했다. 근거: `docs/research/sources/dw_gm.txt:154-155`, 기존 정리 `docs/research/solo_trpg_study.md`.
- Ironsworn의 대가 선택은 현재 상황에 맞는 부정적 결과를 먼저 정할 수 있고, 대가 표 24~32는 가치 있는 물건의 손실·파괴다. 따라서 물건 대가가 장면 표에 있을 때만 우선하며 새 사건을 임의로 추가하지 않았다. 근거: `docs/research/sources/ironsworn_moves.txt:350-369`, 기존 정리 `docs/research/prices_design_19B.md`.

7~9에 soft, 실패에 hard를 배정하는 세부 규칙은 이번 리드 지시와 프로젝트의 기존 대가 계약을 따른다. 두 게임의 판정표를 그대로 복제한 것은 아니다.

## 입력 · 결과 · 대가 · 표시된 줄

LLM을 끈 실제 `LocalGm`으로 시드를 찾았다. 시험 저장에서 해당 장면을 직접 준비하고, 브라우저에서 불러오기·입력·주사위 진행을 조작했다. 모든 사례의 행운은 0으로 고정했다. 상태·결과를 화면에 주입하지 않았다.

| 입력 | 장면 · 시드 | 결과 | 대가 | 표시된 줄 |
|---|---|---|---|---|
| 핀으로 밧줄을 쑤셔 본다 | `b05_why` · 2 | 성공 12 = 6+5+1 | 없음 | 집착 +1 |
| 지도를 펼쳐 저 남자 눈앞에 들이민다 | `b02_people` · 1 | 대가 있는 성공 7 = 2+4+1 | `map_wind` | 귀찌 수명 -1 / 낡은 지도 찢김 / 의심 +3 |
| 가방을 방패처럼 휘두른다 | `b05_why` · 5 | 실패 4 = 1+2+1 | `bag_taken` | 의심 +2 / 의심 +1 · 마법 가방 잃음 |
| 지도를 펼쳐 별이 뜰 방향을 짚는다 | `r3_dusk` · 5 | 실패 5 = 1+2+2 | `map_lost` | 귀찌 수명 -1 / 낡은 지도 잃음 |
| 핀으로 밧줄을 쑤셔 본다 | `b05_why` · 1 | 대가 있는 성공 7 = 2+4+1 | `man_doubt` | 의심 +1 · 집착 +1 / 의심 +1 |

`/`는 사건별로 다른 줄이다. 지도 mixed의 `의심 +3`은 다음 장면에서 남자 수첩이 공개된 뒤 일어난 장면 검사 변화다. `b02_people` 판정 중 숨긴 수치를 표시한 것이 아니다. 지도 실패 화면은 결말 덮개가 뜨기 전 이야기 줄에서 촬영했다.
