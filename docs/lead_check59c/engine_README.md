**‘그 남자의 마음’이 안 보인 원인은 시험 저장본이었다.** b05에서 바로 시작해 b03_ask를 건너뛰었고 `수첩:man`이 없었다. `ep01_desert.yaml:15`~`:18`의 공개 조건, `engine.ts:150`의 `closedTrackGates`, `web/main.ts:1008`의 `applyGate`가 의도대로 의심·집착·호감과 제목을 숨겼다. 화면 배치 버그는 아니었다. 이번에는 정상 도입 → ‘달려가서 길을 묻는다’ → b03_ask → b05 순서로 진입했다. `screen_checks.json`과 사진에서 마음 세 칸이 실제로 보인다(의심 10·집착 2·호감 0).

같은 8개 자유 입력의 최종 결과는 **침묵 0·호칭 반복 0·대체 출력 0·58b 시간 기준 30% 초과 0**이다. 상황별 기대 표정은 실행 전에 정했으며 **6/8 일치**했다. 7번은 실제 모델의 결과 서술·대가·성격 반응과 menacing으로 끝났다. **sneer는 여전히 7/8이고 6·8번은 기대한 intrigued와 불일치**한다. 모든 표정 문제가 해결됐다고 보고하지 않는다.

- 엔진 대가: `cloak_cut` · `칼끝이 외투 자락을 베어 갔다.`

## 표정 쏠림 진단과 실제 요청

`model_requests.jsonl`은 검증 스크립트가 **실제 HTTP POST 본문을 전송 직전 기록하고 그대로 native fetch에 전달한 원문**이다. 모델 입력을 나중에 재구성한 문서가 아니다. system·user·seed·temperature·JSON schema를 포함한다.

`request_audit.json`으로 확인한 실제 요청은 41건, 그중 대사 생성 요청은 11건이다. **11/11에 인물 표정 규칙과 상황별 표정 규칙이 모두 들어 있었다.** 파일이 로드되지 않거나 요청에서 빠진 문제는 아니었다.

스키마의 남자 face enum 순서는 `neutral, smile, surprised, wary, sneer, dumbfounded, menacing, intrigued`다. face는 필수이며 **default는 없다**. 출력 형식 예시는 `face:"neutral"`이고, 화면도 자유 입력 때 neutral로 초기화한다. sneer가 첫 enum이거나 기본값·형식 예시로 강제되는 장치는 확인되지 않았다. enum 순서를 바꾼 A/B 시험은 하지 않았으므로 순서의 통계적 영향까지 부정하지 않는다.

확인한 문맥상 요인은 다음과 같다.

- 8개 중 첫 5개는 울음·겁·기력 저하 같은 몸 반응이다. 사용자가 제시한 규칙상 sneer/neutral이 기대되므로 이 5개가 sneer인 것은 오류로 세지 않았다.
- 인물 성격·말투에는 짧은 비웃음이 반복되고, 기존 큰 행동 요청문은 손목·무기의 실제 저지에도 ‘놀람’을 먼저 지시했다. 중간 실행의 7번이 dumbfounded로 나온 요청 원문도 `_run3partial`에 보존했다.
- 물리적 위협과 관찰의 문맥을 구별하도록 요청문을 바로잡은 뒤 7번은 menacing으로 바뀌었다. 반면 6·8번의 담대한 대화에 기대한 intrigued는 나오지 않았다. 두 불일치는 그대로 남겼다.

`model_table.md`에는 요구한 **결과 서술**, **상황 → 기대 표정 → 실제 표정** 열을 추가했다. 기대는 `lead_check59c_model.ts`에 모델 실행 전에 정했으며 결과를 보고 허용 범위를 바꾸지 않았다. 일치 6/8, menacing 1회(7번), intrigued 0회다. 나오지 않은 intrigued 사진은 만들지 않았다.

## 시험 구성과 비교 범위

같은 8개 입력·시드 59를 사용했다. HUD를 정상 공개하려고 정상 도입을 거친 결과, 이전의 직접 b05 시작과 달리 도입의 상태·주사위 소모가 반영된다. 이번 7번은 대가 있는 성공이며 앞 실행의 단순 성공과 판정이 다르다.

원래 각 1턴인 위협 장면의 시험 복사본만 b05 3턴·b06 20턴으로 늘렸다. 정상 도입 상태에서 첫 실행은 7번에 의심 10의 spy_cut 결말에 도달했다. 그 7턴 기록·요청·로그·CPU는 `_run3partial`로 별도 보존했다. 이후 **8개 반응을 같은 판에서 비교하는 시험 복사본에만 spy_cut 결말 전환을 유예**했다. 의심 수치·대가·판정은 유지했고, 실제 시나리오 파일·사용자 서버의 결말 규칙은 바꾸지 않았다. 따라서 기본 대본 그대로의 8턴 완주나 전체 결말 QA를 주장하지 않는다.

앞 run2 결과 19개는 각각 `_run2` 이름으로, 앞선 run1도 그대로 보존했다. 예: `model_table_run2.md`, `model_sequential_run2.json`, `reaction_07_run2.png`.
