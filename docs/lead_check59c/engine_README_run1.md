## 실제 모델 연속 입력

26B는 18192, 앱은 18191에서 실행했다. `app/scripts/lead_check59c_model.ts`가 실제 `LlmClient`·`LocalGm`·`Engine.act`를 통과시켰고, 같은 session·상태·발화 기록을 8개 입력에 걸쳐 유지했다. 감정 입력 5개는 58b 원문과 다른 새 표현이며 뒤에 평범한 말·행동 3개를 넣었다.

원래 b05·b06은 각각 감정 입력 한 번 뒤 다음 장면으로 넘어간다. 요청한 8개 연속 반응을 비교하려고 **시험 시나리오 복사본의 턴 상한만 b05 3턴·b06 20턴으로 연장**했다. 기록·수치·발화를 초기화하지 않았다. 실제 YAML은 수정하지 않았다. 이 결과는 기본 대본 그대로의 정상 완주 검증이 아니다.

필수 열인 입력·모델 원문·위반·다시 쓰기 횟수·최종 줄·고른 표정·걸린 시간은 `model_table.md`에 있다. 전체 사건·생성 원문·위반·전후 상태는 `model_sequential.json`, 집계는 `model_audit.json`이다.

| 침묵 0 | 7번 남자 모델 원문 `…….` 1개 | 미충족 |

7번의 실제 결과는 양손으로 남자의 손목을 잡아 칼날을 몸에서 비껴내는 서술, 남자의 `…….`과 intrigued, 남자가 움직임을 멈추고 주시하는 서술이다. 구조 반복으로 침묵 대체된 사례가 아니라 모델 자체의 침묵이다. 행동 결과는 서술됐지만 침묵 0으로 세지 않았다.

58b에는 전체 턴 벽시계 필드가 없어 각 행 GM 기록의 interpret·talk 시간 합을 기준으로 삼았다. 새 입력의 전체 엔진 처리 시간과 같은 순번을 비교했다. 평범 입력 3개도 58b 감정 입력 순번과 비교한 참고치이며, 같은 입력·같은 부하의 성능 실험이 아니다. 이 수정 때문에 빨라졌다고 주장하지 않는다. 턴별 CPU 전후 값은 `model_table.md`·`model_audit.json`, 실행 중 2초 간격 CPU 표본은 `model_cpu.log`에 있다.
