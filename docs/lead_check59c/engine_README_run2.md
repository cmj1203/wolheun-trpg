# 59c 재검증

직접 대화·큰 행동의 말 없는 인물 반응을 hard 위반으로 고쳤다. 같은 8개 입력의 최종 출력은 **침묵 0·직전 두 줄 호칭 반복 0·58b 시간 기준 30% 초과 0**이다. 전체 시험 **704 통과·0 실패**, tsc 진단 0, 코퍼스 **222/268**이다. 7번은 hard 위반이 남아 허용된 기존 대체 경로를 1회 사용했다.

앞 실행의 증거 19개는 각각 `_run1`을 붙여 보존했다. 예: `engine_README_run1.md`, `model_sequential_run1.json`, `model_table_run1.md`, `face_intrigued_run1.png`, `tests_run1.log`. 당시 결과를 덮어쓰거나 성공으로 바꾸지 않았다.

점·말줄임표 목록이나 반응 낱말표를 만들지 않았다. `[\p{L}\p{N}]`으로 말 내용이 있는지를 검사한다. `……왜지?`처럼 실제 말이 섞이면 통과한다. 반응을 요구하지 않는 원작 침묵·나레이션은 이 검사로 막지 않는다. hard 위반의 기존 예산·대체 경로는 변경하지 않았다. 59c의 soft `reaction_repeat`, 세 번 연속 끝맺음, 직전 두 줄 호칭 비교와 59b 말줄임표 정규화도 유지했다.

## 표정 경로 진단

run1 7번 해석은 `kind=action`, `bold=true`, `deed=남자의 손목을 잡아 옆으로 밀어냈다.`였다. 큰 행동 정보가 사라진 것은 아니었다. `gm.narrate`는 이미 이 경우 반응 화자와 최소 줄 수를 검증기로 전달했다.

`lore_wolheun.yaml:173`~`:178`의 표정 규칙은 `prompt.ts:54`를 통해 시스템에 실리고 있었다. 다만 큰 행동 요청문은 '굳기·칼을 거두기·더 위험해지기'를 일반 성격에서 고르게 하면서, 바로 일어난 신체 저지와 단순 관찰의 우선순위를 연결하지 않았다. 7번의 손목이 잡혀 칼이 밀리는 순간을 관심만으로 넘긴 intrigued는 그 순간의 '놀람·실제 저지' 규칙과 맞지 않았다.

큰 행동 요청문에서 기존 인물별 규칙을 그 실제 결과에 적용하도록 고쳤다. 특정 face ID를 강제로 넣거나 후보를 menacing으로 제한하지 않았다. run1은 **sneer 7/8, intrigued 1/8**이었다. 이번 최종 화면도 **sneer 7/8**이며, 7번만 **dumbfounded**다. 표정 다양성이 전반적으로 개선됐다고 주장하지 않는다.

## 같은 8개 입력 재검증

`model_table.md`에 입력·모델 원문·위반·다시 쓰기 횟수·최종 줄·고른 표정·걸린 시간이 있다. 전체 사건·전후 상태·생성 원문은 `model_sequential.json`, 집계는 `model_audit.json`이다.

앞 실행과 같은 입력·시드 59·같은 판 상태를 썼다. 원래 각 1턴인 위협 장면을 연속 비교하기 위해 **시험 시나리오 복사본만 b05 3턴·b06 20턴**으로 늘렸다. 실제 YAML은 수정하지 않았다. 입력마다 상태·발화를 초기화하지 않았다. 기본 대본 완주 검증으로 주장하지 않는다.

| 조건 | 이번 관측 |
|---|---|
| 최종 침묵 | 0 |
| 직전 두 줄 같은 호칭 | 0 |
| 58b 같은 순번 시간 대비 30% 초과 | 0 |

7번 첫 생성은 `…….`·intrigued여서 새 hard `reaction_response`로 거절됐다. 두 번째는 `……뭐지?`·dumbfounded로 실제 말 내용이 복구됐지만 기존 `tier_mismatch`가 남았고, 15초 재시도 예산 때문에 세 번째 생성을 하지 못했다.

최종 화면은 기존 대체 경로의 `남자의 손목을 잡아 옆으로 밀어냈다.` → `……미친 여자군.`·dumbfounded다. 판정은 근력 성공이고 정신력 +1·집착 +2·호감 +1 변화도 적용됐다. 점만 있는 줄이 아니며, 실제 말 내용과 행동 결과가 남았다. 사용자가 허용한 hard 위반의 최후 대체 경로를 그대로 사용했다.

남은 기존 검사 문제: 7번 초안은 아시나가 남자의 손목을 밀어 **남자의 칼날**이 허공을 가른다고 썼지만 `tier_mismatch`가 '허공을 가르'를 성공과 반대라고 거절했다. 이번 변경에서 판정 검사 조건은 바꾸지 않았다. 두 번째 초안의 말 내용이 복구된 뒤에도 이 지적으로 대체에 도달했음을 숨기지 않았다.

## 시간과 CPU

이번 전체 턴은 **7.022~17.277초**다. 58b 같은 순번 기준은 **0.088~0.535배**로 30% 초과가 없다. 58b에는 전체 벽시계 필드가 없어 interpret·talk의 기록 ms 합을 사용했다. 서로 다른 입력의 같은 순번 비교이며 평범 입력 3개도 감정 입력 기준과 비교한 참고치다.

같은 입력을 쓴 **run1과 비교하면 7번은 11,807 → 17,277ms, +46.3%**다. 새 hard 검사 뒤 두 번째 생성까지 수행한 턴이다. 당시 모델 PID 28892의 CPU는 입력 전 **14.5%(SN)**, 뒤 **11.1%(SN)**였다. CPU가 증가 원인이라고 단정하지 않는다. 나머지 턴의 전후 CPU와 시간은 표·감사 JSON에 있고, 실행 중 2초 표본은 `model_cpu.log`다. '30% 이내'의 기준을 run1으로 바꿔 읽으면 이 7번은 미충족임을 명시한다. 원래 59c 지시의 기준은 58b다.
