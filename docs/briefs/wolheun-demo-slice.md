# 레인 브리프: wolheun-demo-slice

목표: /Users/choeminju/월흔_trpg/docs/spec.md 의 피칭 데모 앱 골격을 만들고, 1화 사막 조우 한 장면을 처음부터 끝까지 플레이하는 수직 슬라이스를 이 MacBook Pro에서 인터넷 없이 돌린다. 핵심은 혼합형 GM이다. 시나리오 비트는 파일로 쓰고, 자유 입력은 로컬 LLM GM이 원작 말투로 받고, 판정은 코드가 굴린다.

입력:
- 명세: docs/spec.md(사용자 결정과 리드 기본값 전부).
- 원작 자료: 에셋 레인 wolheun-ep01-assets 가 /Users/choeminju/월흔_trpg/assets/ep01/ 에 컷, cuts.json, ep01_script.md 를 만드는 중이다. 준비되기 전에는 공개 줄거리(https://namu.wiki/w/월흔)로 비트를 잡고, 나오면 원문 대사와 컷으로 바꾼다.
- 입식: 입식 레인 wolheun-sprites 가 /Users/choeminju/월흔_trpg/assets/sprites/ 에 넣는다. 그 전에는 자리 표시용 실루엣을 쓴다.
- 장비: MacBook Pro M5 Pro, 통합 메모리 48GB. llama.cpp(llama-server, llama-cli)가 Homebrew로 설치돼 있고 ollama와 mlx는 없다.

산출물(/Users/choeminju/월흔_trpg/ 아래):
1. app/ : 비주얼 노벨형 화면. 배경, 입식 자리, 대사창, 자유 입력창, 선택지, 주사위 연출, 진행 수치(의심, 집착과 호감, 귀걸이 남은 시간, 탈주 준비도)를 보여 준다. LLM 서버와 앱을 함께 띄우는 실행 스크립트 하나를 둔다.
2. 엔진: 시나리오 비트 파일 형식, 판정 규칙(2d6 + 능력치, 10+/7~9/6-, 실패해도 진행), 저장과 불러오기, 플레이 기록(선택, 판정, 시간).
3. 로컬 GM: 비트를 벗어나지 않게 묶는 프롬프트 구조, 원작 설정 사전(인물 말투, 호칭, 지명, 금지 사항), 출력 검증(설정 위반이나 등급 위반이면 막고 다시 생성).
4. docs/gm_model_eval.md : 상업적 이용이 가능한 로컬 모델 3개 이상을 같은 입력 20개로 비교한다. 기준은 말투 재현, 비트 준수, 한국어 자연스러움, 첫 토큰 지연, 전체 응답 시간, 메모리다. 고른 모델과 이유를 적는다.
5. 슬라이스 콘텐츠: 사막 조우 장면 비트, 판정 지점 2개 이상, 분기 결과 2개 이상, 결과 화면.
6. 테스트: 판정 엔진 단위 테스트(시드 고정 주사위), GM 출력 검증 테스트, 정해진 입력으로 슬라이스를 끝까지 자동 플레이하는 e2e 스크립트.
7. 주요 화면 스크린샷과 실행 방법 README.

멈춤 조건: 외부 네트워크 호출이 없음을 확인한 상태에서 실행 스크립트 하나로 앱이 뜨고, 자동 플레이 스크립트가 고른 로컬 모델로 슬라이스를 끝까지 통과하며, 테스트가 모두 통과한다. 테스트 출력, 스크린샷, 모델 비교표 경로를 증거로 READY를 보낸다.

제약:
- 게임 실행 중 외부 네트워크를 호출하지 않는다. 원작 텍스트를 외부 AI API로 보내는 코드를 넣지 않는다.
- 상업적 이용이 허용된 라이선스의 모델만 쓴다. 애매하면 리드에게 report로 묻는다.
- 메모리 48GB를 입식 레인과 나눠 쓴다. 개발 중에는 작은 모델로 돌리고, 큰 모델 비교는 시작 전에 memory_pressure로 여유를 확인한다. 30분 넘게 메모리를 크게 점유하는 작업은 시작 전에 report로 알린다.
- 디스크에 동시에 두는 모델은 합계 30GB 이하로 하고, 비교가 끝난 모델은 지운다.
- 데모 범위(어느 화까지)는 리드가 정한다. 슬라이스 밖 콘텐츠는 만들지 않는다.
- 원본 PSD와 ~/Downloads는 읽기만 한다.
- 15세 이용가.
- git 원격과 PR은 없다. 로컬 git 커밋은 해도 된다. 증거는 파일 경로와 명령 결과로 낸다.
