# 59차 엔진 표정 연결

58b는 먼저 마쳤으며 별도 결과는 `../lead_check58b/README.md`다. 59차는 지시 3번(+4번)의 엔진·표정 연결만 처리했다. 기존 설치 그림을 사용했고 assets를 수정하지 않았다.

인물별 표정·실제 26B 입력 12개·각 1440 화면·새 표정 14개 시트·전체 시험과 코퍼스 검증을 완료했다. 큰 행동 3개 모두 해당 행동을 받는 연출과 결과 변화가 있고, 세계 밖 2개는 판정·수치·비트 변화가 없다. 최종 12개는 전부 실제 모델 출력이며 대체 줄 사용은 0개다.

## 연결과 검증

- `ep01_desert.yaml` cast: 아시나·속마음 각각 neutral·smile·surprised·wary·flustered·scared·indignant·smug·tired, 남자 neutral·smile·surprised·wary·sneer·dumbfounded·menacing·intrigued. cold는 neutral 의미이며 출력 ID가 아니다.
- 일반·후드 새 10개와 남자 새 4개의 실제 sprite 키를 등록했다. 기존 렌더러 `setFace`가 그 키로 설치 파일을 읽는다. 로더는 선언된 모든 표정에 일반·대체 입식이 있는지 검사한다.
- `types.ts`의 전 인물 공통 FACES를 제거했다. 출력 스키마는 화자마다 별도 enum을 가진다. 검증 오류에는 화자와 허용 목록을 넣어 다시 고르게 하며, 다른 인물의 표정을 neutral로 덮지 않는다. `withNotes`에서도 lore 고정 반응의 표정을 해당 cast와 대조한다.
- lore와 프롬프트에 상황별 의미 규칙을 연결했다. 세계 밖 말은 어이없음·냉소, 큰 시도와 실제 저지는 놀람·위협, 칭찬·미인계는 냉소·흥미로 구별한다. 아시나의 공포·당황·항의·능청·피로도 별도 선택한다.
- 고정 대사 **23곳**의 `어디 · 전 → 후`는 `engine_fixed_changes.md`다. `억울해…`의 smile 상속을 indignant로 바꿨고, 원작 냉소·당혹·미인계 문맥을 각각 연결했다.
- 여우는 시작 안내·질문 모드에서 보이고 이야기 인물 줄에서는 숨겨진다. 실제 표시 기록은 `engine_fox_modes.json`, 12개 인물 줄의 여우·GM 배지 숨김은 `engine_screen_checks.json`이다.

## 검증 중 찾은 원인과 수정

1. 뽀뽀는 해석 모델이 action·bold로 읽었지만 기존 beauty 접근법이 먼저 반환돼 큰 행동 정보가 버려졌다. 큰 신체 행동은 같은 목적의 말 접근법보다 먼저 실제 시도 경로로 보존했다. 말로 하는 미인계는 그대로 접근법이다. 회귀 시험 수정 전 실패: `engine_bold_before.log`.
2. 엔진이 정한 가방 압수 대가를 소지품 검증이 무단 상실로 거절했다. 보존할 소지품을 계산할 때 outcome뿐 아니라 선택된 price.effects.lose도 반영했다. 대가 없는 임의 상실은 계속 막는다. 수정 전 실패: `engine_price_before.log`. 최종 뽀뽀는 두 번째 연출 생성에서 시도·손목 저지·압수·인물 반응을 모두 통과했다.
3. 미인계 CG를 모델 모든 줄에 일괄 붙여 남자의 선택 표정을 가렸다. CG는 사건 서술과 그 그림의 인물에게 이어지고, 다른 인물의 표정 반응 줄에서는 걷히도록 엔진의 부착 원인을 고쳤다. 수정 전 실패: `engine_cg_before.log`, 수정 후 실제 남자 얼굴: `engine_input_12.png`.
4. 초기 화면 재현기는 결말 상태를 가진 저장본의 남은 이벤트를 버려 3·11번이 이미 결과 화면으로 넘어갔다. 실제 대사 대기 시점의 남은 이벤트를 보존해 다시 찍었다. 12번의 CG 가림도 모음 그림을 열어 찾아 고쳤다. 실패 기록과 before 파일은 보존했으며 최종 파일에는 반응 얼굴이 보인다.

최종 대체 출력은 0개다. 일부 초안은 길이·판정 결과 불일치·큰 행동의 줄 수 부족으로 다시 썼으며 원문과 위반을 JSON에 남겼다.
