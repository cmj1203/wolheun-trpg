# 아시나 r3 후보 PC 1440 표시 관문

2026-11-09. 대상은 아직 설치하지 않은 r3 후보 두 장의 PC 화면 표시뿐이다. 원작·화소 대조는 반복하지 않았다(r3 귀찌 재검수 `docs/lead_check61/asina_hair_r3_review.md` 참조).

## 판정

| 대표 | 판정 | 요약 |
|---|---|---|
| 일반 `asina_surprised_candidate_r3.png` | **PASS(렌더 전용 대체)** | 실제 앱 입식 칸에서 원본과 같은 크기·위치. 머리 정리, 얼굴 구도, 투명도, 머리 가장자리 모두 문제 없음 |
| 후드 `asina_hood_surprised_candidate_r3.png` | **PASS(렌더 전용 대체)** | 같은 결과 |
| 자연 스토리 진행에서의 표시 | **UNVERIFIED** | 후보를 설치하지 않았으므로 스토리를 끝까지 돌려 보지 않았다 |

이 판정은 **후보를 실제 앱 입식 DOM에 임시로 끼워 넣은 렌더 전용 확인**이다. 설치된 운영 에셋이 아니고 자연 스토리 QA도 아니다.

## 방법

- **격리 앱.** `app/` 디렉터리에서 `WOLHEUN_PORT=18351 WOLHEUN_NO_LLM=1`과 저장·로그·지도·피드백 경로를 `work/continuation/asina-hair-recovery/pc-qa/` 아래로 지정해 `bun src/server/main.ts`를 직접 띄웠다. 시작 규약은 `app/src/server/main.ts`의 `optionsFromEnv`, `sharedWithUser`(사용자판 18081과 파일·LLM을 공유하면 시작을 거부)를 읽고 따랐다. 모델은 시작하지 않았고 18080·18081·18192·18196과 다른 레인의 시험 서버(18193·18194·18221·18231·18241)는 건드리지 않았다. 끝난 뒤 내가 띄운 18351 서버만 종료했다.
- **브라우저.** Ego Browser의 내 전용 공간 `asina r3 pc1440 qa`(번호 17)에서만 작업했고, 끝나서 `finish({ keep: [] })`로 닫았다. 사용자·다른 에이전트 공간은 사용하지 않았다. 매 실행마다 `Emulation.setDeviceMetricsOverride`로 창을 1440×900(배율 1, 비모바일)으로 맞췄고 스크린샷 8장이 모두 1440×900이다.
- **장면.** 실제 앱을 "처음부터"로 시작해 공백 키로 `1화 사람?!` 장면까지 진행했다. 여기서 아시나는 가운데 칸(`#slot-center`)에 후드 차림으로 나오고, 화면에 `대사창`·위쪽 표시줄·오른쪽 수치판이 모두 보인다. 이 장면에서 앱 자신이 `asina_hood_surprised.png`를 쓰는 것을 확인했다(후드 원본은 자연 상태 그대로다).
- **렌더 전용 대체.** 입식 `<img>`의 `src`만 바꿨다. 후드 원본은 앱이 제공하는 `/media/ep01/gen/hood/asina_hood_surprised.png`, 일반 원본은 `/media/ep01/gen/asina/asina_surprised.png`, 후보는 r3 PNG를 데이터 URL로 디코드해 넣었다(CSP가 `img-src data:`를 허용). 앱의 실제 CSS 크기·자르기는 그대로다. 아래 어두운 배경 확인에서는 `#bg`의 배경 그림만 앱의 실제 자산 `desert_night.png`로 임시 교체했고 확인 뒤 원래대로 돌렸다.
- **같은 조건.** 여덟 번의 촬영에서 입식 `<img>`의 화면 사각형이 모두 같다: x 368.99, y 83.39, 너비 702, 높이 1053(1024×1536 원본의 0.6855배, 무대 높이의 130%). 장면·자세(`speaking` 클래스)·대사창·표시줄·수치판이 같고, 입식 밖 좌우 띠를 비교하면 원본과 후보 화면이 같다(왼쪽 띠 일치, 오른쪽 띠는 수치판의 작은 갱신 정도의 차이).

## 한계와 UNVERIFIED

- **자연 스토리 QA 아님.** 후보를 설치하지 않았고 장면 스크립트가 후보를 부르지 않는다. 표정 전환 페이드(`morphSprite`)·장면 전환·저장 후 불러오기 경로는 거치지 않았다.
- **일반(후드 없는) 아시나**는 이 장면에서 앱이 쓰지 않으므로, 같은 가운데 칸에서 `src`만 바꿔 보았다. 왼쪽·오른쪽 칸을 따로 렌더하지는 않았지만, 세 칸은 크기·아래쪽 위치가 같고 `left`/`right` 오프셋만 다르다(`app/web/style.css`의 `.sprites .slot`).
- **어두운 배경은 자연 장면이 아니다.** 앱의 실제 밤 배경 자산을 임시로 깔아 본 것이다. 해질녘·암전·CG 장면은 보지 않았다.
- `dim`(말하지 않는 인물) 상태의 밝기 저하, CG가 입식을 가리는 상태(`cg-on`)는 확인하지 않았다.
- 모바일은 범위 밖이다.
