# 아시나 머리 v16 복구

2026-11-09. 남은 16종의 후보·변경 마스크·생성 근거를 완성했다. **설치 승인 상태가 아니다. 독립 Claude 미술 검수는 계정 풀 차단으로 대기 중이다.**

## 실제 생성 상태

- v16 첫 생성 16건과 재시도 3건, 총 19건 모두 기존 네이티브 생성 PNG가 존재한다. 생성 원본과 저장 복사본의 SHA-256이 모두 일치한다. 입력 그림의 현재 해시도 기록과 모두 일치한다.
- 17건의 기록은 exit 0이다. `asina_hood_tired`, `asina_hood_wary`의 기존 run JSON은 exit_code가 null이다. 로그에는 복사 명령 성공과 최종 저장 경로가 있으나 종료 코드를 소급해 0으로 쓰지 않았다.
- 기존 기록의 PID 19개를 `ps -p ... -o pid,ppid,pgid,stat,etime,comm`으로 확인한 결과 살아 있는 PID가 없었다(exit 1, 행 없음). 재시작·중단·추가 생성은 하지 않았다.
- 첫 시도 16건과 재시도 3건, 기존 후보·로그·스크립트는 그대로 남겼다. 재시도 선택은 기존 `hair_selection.json`의 indignant 2종과 wary 일반 1종을 따랐다.
- 대표 2종 r3의 기존 Claude 원작/ROI 승인과 PC1440 렌더 전용 PASS는 그대로다. 재생성하거나 재검수하지 않았다.

## 원인과 새 후보

기존 `v16_compose.ts`는 머리 마스크 외에 얼굴 타원의 가중치도 합쳤고, 원본·생성본 알파가 둘 다 250 이상일 때만 원본 알파를 유지했다. 따라서 최종 선택 직전 후보 16종에서 얼굴 보호 사각형 안 8,682~8,734화소, 알파 4,448~21,555화소가 변경됐다. 기존 합성을 그대로 최종 선택하면 얼굴·표정·원본 알파 보존 조건에 어긋난다.

새 `v16c`는 **원본 그림에서 시작해 기존 합성 결과의 머리 ROI 색만 적용**한다. 원본과 기존 네이티브 편집본 양쪽에서 갈색 머리로 분류되고, 기존 변경 마스크 안인 화소만 사용한다. 얼굴 보호 상자 `[451,363,558,465]`와 양쪽 귀찌 중심 반경 9px는 제외한다. 경계 가중치는 ROI 안쪽으로만 줄인다. 알파는 모든 화소에서 원본 그대로다. 다른 표정의 눈·얼굴을 가져오거나 얼굴 패치를 이식하지 않는다.

원본 18종의 해시는 전부 기록과 같으며 운영 assets·app·ep02는 쓰지 않았다. 추가 설치·커밋·푸시·모델 호출·브라우저 작업도 없었다.

## 자체 검수와 남은 검수

GPT 복구 담당자가 `qa/self/recovery_v16c_comparison.png`의 16종 원본/후보 쌍을 직접 보았다. 4×4칸이며 각 칸 왼쪽은 원본, 오른쪽은 v16c다. 원본 상반신/머리 영역을 50% 크기로 그린 오프라인 비교판이다. 실제 앱 화면이나 PC1440 QA가 아니다.

- 비교판에서 얼굴 표정·자세·복장의 눈에 띄는 이동이나 교체는 보이지 않았다. 정확한 보존 근거는 위 화소 검사다.
- 원본 실루엣과 얼굴 주변 앞머리를 그대로 보존했으므로 기존의 가는 물결 가닥과 일부 색 가장자리는 남는다. 내부 갈색 영역의 정리에 한정되어 대표 r3와 같은 정리 강도라고 승인하지 않았다.
- 색 분류 마스크는 의미상의 머리 영역을 완전히 증명하지 않는다. 후드/머리·의상 경계 포함 여부와 고배율 연결감은 독립 Claude 검수가 확인해야 한다.
- 남은 16종의 원작/ROI 독립 미술 QA, 고배율 가장자리 검수, 실제 PC1440 앱 표시·전환·스토리 QA는 미검증이다. 이번 요청의 브라우저 금지 범위를 지켰다.
- 독립 승인자는 **Claude만**이다. 계정 차단을 GPT 승인으로 대체하지 않았다. 기존 대표 2종의 PASS는 이 16종에 전파하지 않았다.

최종 상태는 파일별 `PRODUCTION_CANDIDATE_UNINSTALLED_PENDING_CLAUDE`다. 자체 검수 결과와 독립 검수 대기는 `qa_manifest.json`에 별도 기록했다.

## ep02 결합 계약

기준 디렉터리: `work/continuation/asina-hair-recovery/`.

1. `v16/manifest.json`의 `original`과 `original_sha256`이 승인된 가방 전용 마스크의 기준 원본과 정확히 같은지 먼저 확인한다.
2. `changed_mask`는 RGB PNG이며 255인 화소만 원본과 RGBA가 다르다. `allowed_mask`는 합성 가중치의 지지 영역이며 정확한 차이 마스크와 다르다.
3. 머리 `changed_mask`와 승인된 가방 전용 마스크를 교차한다. 겹침이 0일 때만 각 승인 영역의 화소를 같은 원본에 결합한다. 겹침이 있으면 좌표를 보고 별도 판단한다.
4. 원본 전체 몸을 후보로 교체하거나 ep02 별칭을 자동으로 바꾸지 않는다. 이 복구에서는 실제 교차 검사나 결합을 하지 않았다.

## 산출물

모두 위 기준 디렉터리 아래다.

- 후보 16장: `v16/candidates/<이름>_candidate_v16c.png`
- 정확한 차이 마스크 16장: `v16/candidates/<이름>_changed_mask_v16c.png`
- 허용 가중치 마스크 16장: `v16/candidates/<이름>_allowed_mask_v16c.png`
- 선택: `v16/final_selection.json`
- 원본/후보/마스크 해시와 생성 연결: `v16/manifest.json`
- 네이티브 원본·Codex 세션·명령·입력 해시·PID/PGID·로그 해시 19건: `v16/generation_accounting.json`
- 파일별 화소·알파·마스크 재계산: `v16/verification_v16c.json`
- 자체 검수/독립 검수 구분: `v16/qa_manifest.json`
- 자체 검수 비교판: `v16/qa/self/recovery_v16c_comparison.png`
- 생성/검증 코드: `v16_recovery.ts`, `v16_verify_recovery.ts`

복구 스크립트와 검증 스크립트는 기존 `app/node_modules/@types`를 지정한 `tsc --strict --noEmit`에서 각각 exit 0이다. 독립 실행 파일의 편집기 LSP는 Bun/Node 주변 타입을 자동 탐색하지 못했으며 설치로 해결하지 않았다. 복구 실행과 저장 PNG 검증 실행도 각각 exit 0이다. 코드레빗 대기열은 허용 경로 밖에 파일을 쓰므로 실행하지 않았다.
