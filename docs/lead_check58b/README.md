# 58b 감정 반응과 변화 숫자

58차의 같은 입력 10개를 같은 비트(b05·b06)에서 기존 18097의 `gemma-4-26b-a4b`로 검증했다. 59차 cast·표정·이미지 연결은 아직 적용하지 않은 상태다. 모델 반응은 **10/10** 통과했으며, 9번째 입력의 해석 시간 초과 뒤 생긴 무판정 분류 오류는 아래와 같이 별도로 고쳤다.

## 원인과 수정

말투 판정 실패가 `checkState`의 상태 사실 목록에 합쳐져 `beat/state_check`로 보고됐다. 말투를 별도 `lore/reaction_style` 검사로 옮겼고 설명 독백·상황 해설·40자 초과만 거절한다. 입력에 대한 구체적인 반응이 없는 대사는 별도 `beat/reaction_response`로 다시 쓴다. 상태 검사는 후드 등 실제 상태만 다룬다.

검사 분리만 한 첫 실행에서는 무관한 감탄이 남았다. 행동 반응 검사를 붙인 다음 실행도 장면 목표와 원작 예시의 짧은 감탄에 끌려 같은 줄을 반복했다. 감정 반응은 전용 시스템·요청 문맥으로 분리해 입력에 실제로 보인 모습만 짧게 받도록 했다. 낱말별 대응표나 이 10개를 위한 고정 대사는 추가하지 않았다.

변경 위치별 전후 표: `changes.md`. 첫 실행은 `model_round1.json`, 두 번째 중단 실행은 `model_round2_partial.json`이다. 최종 원문·검사·대체 여부·시간은 `model_emotions.json`에 보존했다. 첫 9개 실행 뒤 감시 명령이 600초 제한에 종료돼, 완료된 행은 보존하고 `--resume`으로 마지막 입력만 이어 갔다. 시간 초과 당시 모델 PID 16678은 `SN`, CPU 0.1%, `/health`는 `ok`였다. CPU가 지연 원인이라고 단정하지 않는다.

## 같은 감정 입력의 실제 반응

각 행은 새 판이다. ‘최종 줄’은 장면 전환 뒤 나오는 고정 대사를 제외한 실제 모델 반응이다. 입력과 무관한 `왜 죽이면 안 된다는 거지?`나 감탄·침묵만 있는 답은 성공으로 세지 않는다.

| 입력 | 모델 원문 | 위반 | 최종 줄 | 행동 반응 여부 |
|---|---|---|---|---|
| 눈가가 따끔해져 말문이 막힌다 | 눈물이라. 이방인, 겨우 그 정도로 죽음을 피할 수 있을 것 같나? | 없음 | 원문과 같음 | 통과: 눈가에 차오르는 감정을 짚어 비웃음 |
| 설움이 북받쳐 목소리가 잠긴다 | 목소리까지 잠기는군. 이방인, 그게 네 한계인가? | 없음 | 원문과 같음 | 통과: 잠긴 목소리에 반응 |
| 등골이 서늘해져 온몸이 굳는다 | 몸이 굳은 걸 보니, 죽음이 눈앞이라도 온 건가? | 없음 | 원문과 같음 | 통과: 굳은 몸에 반응 |
| 분해서 입술만 파르르 떨린다 | 입술을 떨 만큼 분한가? | 없음 | 원문과 같음 | 통과: 떨리는 입술과 분함에 반응 |
| 헛웃음이 새어 나오고 눈물이 맺힌다 | 눈물이라. 그게 이방인의 마지막 반응인가? | 없음 | 원문과 같음 | 통과: 실제 눈물에 반응 |
| 맥이 풀려 어깨가 축 처진다 | 맥이 풀린 건가, 이방인. 벌써 끝인가? | 없음 | 원문과 같음 | 통과: 기운 빠진 모습에 반응 |
| 이가 덜덜 떨려 말이 안 나온다 | 이빨 부딪히는 소리가 여기까지 들리는군. 겁에 질린 건가? | 없음 | 원문과 같음 | 통과: 이가 떨리는 소리에 반응 |
| 어이가 없어 멍하니 눈만 깜빡인다 | 눈만 깜빡이는군. 이방인, 겁을 먹은 건가? | 없음 | 원문과 같음 | 통과: 눈 깜빡임은 받음. 겁이라는 해석은 남자의 추측이며 입력의 감정과 같다는 뜻은 아님 |
| 입 안이 바싹 마르고 숨이 막힌다 | 숨이 막히나, 이방인? | 없음 | 원문과 같음 | 통과: 막힌 숨에 반응 |
| 가슴이 먹먹해 아무 말도 못 한다 | 1회: 가슴이 막히기라도 했나? 말도 못 할 만큼. / 2회: 가슴이 막히기라도 했나? 하, 우습군. | 1회 `lore/reaction_style`, 2회 없음 | 가슴이 막히기라도 했나? 하, 우습군. | 통과: 먹먹함과 말문 막힘에 반응 |

처음 9개 반응 줄은 첫 생성, 10번째는 두 번째 생성이 통과했다. 대체 침묵은 없었다. 10번째 첫 문장은 실제 입력을 받는 짧은 문장이지만 의미 판정기가 말투 위반으로 거절했다. 이 오거절도 원문과 함께 숨기지 않고 표에 남겼다.

## 해석 중단 뒤의 규칙 경로

9번째 입력의 최초 해석 호출은 **90,008ms**에 시간 초과했다. 그 오류를 확인한 시점 모델 PID 16678의 `ps` 값은 **SN·CPU 0.1%**, 경과 **3일 3:17:16**이고 `/health`는 `ok`였다. 요청이 끊긴 정확한 순간의 CPU 표본은 수집하지 못했다. 뒤의 별도 관측은 CPU **6.1%**, 경과 **3일 3:19:02**, 단일 슬롯이 처리 중이었다. CPU가 원인이라고 단정할 자료는 없다.

모델 없는 `LocalGm(null)`도 이 입력을 `improv`로 분류함을 새 엔진 경계 시험으로 먼저 재현했다(`body_before.log`: 예상 idle·실제 improv). 기존 무시도 규칙은 그대로 머무는 표현·부정 동작만 보고 현재형 서술어를 동작으로 읽었다. `text.ts:isNoAttempt`에서 목적어를 대상으로 하는 시도와, 절마다 주어에 생기는 피동·상태 변화를 문장 구조로 구분했다. 감정 낱말 목록을 늘리지 않았다.

같은 입력 및 문서에 없던 `기운이 빠지고 손끝이 저린다`, `정신이 아득해지고 다리가 풀린다`는 규칙 경로에서 idle·주사위 없음이다. `숨이 막혀도 남자의 팔을 밀어낸다` 등 목적어·별도 행동·의도 있는 몸짓 3개는 idle이 아니다. 회귀 시험은 수정 전 실패·수정 후 통과했다. 시간 초과 원본은 `model_before_body_fix.json`에 남겼다.

수정 후 같은 9번만 기존 90초 제한으로 재확인했다. 해석 **66,664ms**, 반응 **25,317ms**, 총 **91,986ms**, 오류·대체·주사위 없음이었다. 모델 CPU는 입력 전 **0.1%(SN)**, 입력 후 **3.4%(RN)**였고, 최종 대사는 `숨이 막히나, 이방인?`이다. 최종 `model_emotions.json`의 **10개 전부 rolled=false**, 실제 행동 반응 **10/10**, 대체 침묵 **0개**다.
